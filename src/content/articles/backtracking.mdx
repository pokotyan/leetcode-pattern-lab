## 「全部のパターンを試す」を、行き当たりばったりでやらない

こんな問題を考えます。

> `nums = [1, 2, 3]` から作れる、すべての部分集合（空集合も含む）を求めてください。

答えは `[], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3]` の8通りです。要素数が3個なら8通り、4個なら16通り……というように、**要素数 N に対して 2<sup>N</sup> 通り**あります。これを漏れなく、かつ重複なく列挙するには、行き当たりばったりの for ループでは対応できません。

## 「選ぶ」か「選ばないか」を、全要素について決める

ここで発想を切り替えます。部分集合を作るというのは、結局のところ**「配列の各要素について、それを含めるか含めないかを1つずつ決めていく」**ことと同じです。`1` を選ぶか選ばないか、`2` を選ぶか選ばないか、`3` を選ぶか選ばないか……この決定をすべて再帰で表現します。

```python
def subsets(nums):
    res = []
    path = []
    def backtrack(i):
        if i == len(nums):
            res.append(path[:])   # 決まったので記録（コピーを取る）
            return
        path.append(nums[i])       # nums[i] を「選ぶ」
        backtrack(i + 1)
        path.pop()                  # 選んだのを取り消す
        backtrack(i + 1)             # nums[i] を「選ばない」
    backtrack(0)
    return res
```

`path` が「今、組み立てている途中の部分集合」です。ある要素について「選ぶ」場合を再帰で最後まで試したあと、`path.pop()` で選んだことを**取り消して**から、「選ばない」場合も試します。この**「試す → 取り消す（戻す） → 次を試す」**という流れが、バックトラック（後戻り法）という名前の由来です。

<SubsetsBacktrack client:visible />

`i` が配列の末尾に到達するたびに、その時点の `path` が1つの答えとして記録されます。**「選ぶ」を先に全部深く掘り下げてから、「選ばない」も試す**という順番で、木を上から下まで総当たりしている様子を見てください。

<Callout type="warn" title="res.append(path[:]) の [:] を忘れると、あとで答えが全部同じになります">
  `path` は再帰の間ずっと使い回している、**1つだけの共有リスト**です。`res.append(path)` と書いてしまうと、リストの参照（住所）だけがコピーされます。あとで `path` の中身が `append` や `pop` で変化すると、**`res` に入れたはずの過去の答えまで、一緒に書き換わってしまいます。**
  `path[:]`（またはPythonの `list(path)`、`copy.deepcopy` など）で**中身を複製してから**記録する必要があります。これはバックトラック問題で最も踏みやすい落とし穴の1つです。
</Callout>

## 骨格はどの問題でも同じです

`Permutations`（順列）や `Combination Sum`（合計が target になる組み合わせ）も、見た目は違いますが骨格は共通しています。

```python
def backtrack(path, その他の状態):
    if 終了条件:
        res.append(path[:])
        return
    for 候補 in 選べるものたち:
        path.append(候補)          # 選ぶ
        backtrack(path, 更新した状態)
        path.pop()                  # 取り消す
```

「何を候補として for ループで回すか」「終了条件は何か」「同じ要素を2回選んでよいか」といった部分だけが問題ごとに変わり、**「選ぶ → 再帰 → 取り消す」という3ステップの骨格は変わりません。** この骨格が体に染み込めば、初見のバックトラック問題でも手が止まらなくなります。

<Callout type="tip" title="Permutations との違い">
  `Subsets` では「今見ている要素を選ぶか選ばないか」という**2択**を、要素の数だけ繰り返しました。
  `Permutations`（順列）では代わりに、「まだ使っていない要素の中から、次にどれを置くか」という**選択肢が複数ある for ループ**になります。骨格の「選ぶ → 再帰 → 取り消す」は同じですが、候補の作り方が「2択」から「残りの中からどれか1つ」に変わる、という違いです。
</Callout>

## 重複を避ける：ソートしてから隣とだけ比較する

`Subsets II` のように、入力に重複した値が含まれる場合、同じ部分集合を2回数えてしまうことがあります。ここで使うテクニックは、Two Pointers の記事の `3Sum` で見た重複スキップと、まったく同じ発想です。

**先に配列をソートしておき、「同じ階層で、直前と同じ値を選ぼうとしたらスキップする」**というルールを加えます。ソートしてあるおかげで、同じ値は必ず隣り合っているので、この1行のチェックだけで重複を防げます。

## なぜ計算量が O(N · 2<sup>N</sup>) なのか

`Subsets` を例に考えます。各要素について「選ぶ／選ばない」の2択があるので、パターンの総数は 2<sup>N</sup> 通りです。1つのパターンが確定するたびに、`path[:]` でリストをコピーするのに O(N) かかります。合計すると O(N · 2<sup>N</sup>) です。**「答えの個数がそもそも指数的に多い」問題では、答えを列挙するコスト自体が計算量の大部分を占める**ということを覚えておいてください。

## この型の計算量

| 問題 | 時間 | 空間 |
| --- | --- | --- |
| Subsets（部分集合） | O(N · 2<sup>N</sup>) | O(N)（再帰の深さ） |
| Permutations（順列） | O(N · N!) | O(N) |
| Combination Sum（重複ありの組み合わせ） | 入力による（枝刈りで大きく変わる） | O(target)（再帰の深さ） |

## 「これはバックトラックだ」と気づくためのサイン

- 「すべての〜を求めよ」「すべての組み合わせ／順列／部分集合」
- N の制約が小さい（10〜20程度）→ 指数的な計算量を許容している合図
- 「選ぶ・選ばない」「使う・使わない」という2択、または「次に何を置くか」という選択の繰り返し
- 途中で明らかに条件を満たせないとわかったら、**それ以上その枝を掘らずに打ち切れる**（枝刈り）

<Callout type="warn" title="枝刈りを忘れずに">
  `N-Queens` のように、途中で「もうこの置き方は絶対に成立しない」とわかる問題では、無駄にすべての枝を最後まで掘り下げず、**その時点で戻ってしまう（枝刈りする）**ことで、実行時間が大きく変わります。「全部試す」ことと「無駄なく試す」ことは両立できます。
</Callout>
