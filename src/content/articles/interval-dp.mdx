## この記事を読む前に押さえておく型

- **二次元 DP**：状態を2つ持つ DP の書き方（表を用意して、埋める順番を決めて、遷移式を立てる）がそのまま土台になります。この記事で変わるのは**埋める順番**だけです。`dp[i][j]` が何を表すかを自分で決める、という手つきに慣れていることが前提です

## まず、困っている状況を体験してみます

> 文字列 `s = "bbbab"` の中から、いくつか文字を取り除いて（順番は変えずに）回文を作ります。作れる最長の回文の長さを求めてください。

答えは `"bbbb"` の4です。ここまでの DP と同じように、`dp[i]` を「`i` 文字目までの答え」として立ててみましょう。

……ここで手が止まります。「`i` 文字目までの最長回文部分列」が分かっていても、`i + 1` 文字目を足したときにどうなるかが決まりません。回文は**両端から同時に決まる**ものなので、「左から `i` 文字目まで」という区切り方と相性が悪いのです。

同じ問題は、もっと露骨な形でも現れます。

> 風船が `nums = [3, 1, 5, 8]` と並んでいます。風船 `i` を割ると `nums[i-1] × nums[i] × nums[i+1]` コインがもらえます（端の外側は 1 とみなします）。割った風船は列から消え、両隣が新しく隣り合います。全部割ったときの最大コインを求めてください。

こちらはさらに厄介です。風船を1つ割るたびに**隣接関係そのものが変わる**ので、「`i` 番目まで処理した」という状態が意味を持ちません。

## 発想を変える：状態を「区間」にする

そこで、状態の持ち方を変えます。「`i` 番目まで」ではなく、**「区間 `[i, j]` の中だけを見たときの答え」**を `dp[i][j]` とします。

回文の問題なら、`dp[i][j]` は「`s` の `i` 文字目から `j` 文字目までの中での、最長回文部分列の長さ」です。この決め方なら、遷移式が自然に書けます。

- `s[i] == s[j]` なら、両端をそのまま回文の両端として使えます。内側 `dp[i+1][j-1]` に 2 を足すだけです
- 違うなら、左端を諦める（`dp[i+1][j]`）か、右端を諦める（`dp[i][j-1]`）かの大きいほうです

```python
def longest_palindrome_subseq(s):
    n = len(s)
    dp = [[0] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):     # i は右から左へ
        dp[i][i] = 1                   # 1文字はそれ自体が回文
        for j in range(i + 1, n):
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1] + 2
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])
    return dp[0][n - 1]
```

## 埋める順番が、この型の本体です

ここが区間 DP で一番つまずくところです。遷移式を見ると、`dp[i][j]` を計算するのに必要なのは次の3つです。

- `dp[i+1][j-1]`（1つ内側）
- `dp[i+1][j]`（1つ下の行）
- `dp[i][j-1]`（1つ左の列）

どれも、`dp[i][j]` より**区間が短い**マスです。つまり、**幅の狭い区間から順に埋めていけば、必要な値は必ず先に埋まっています。**

これを実現する書き方は2通りあります。

**書き方1：`i` を大きいほうから回す**（上のコード）。`i` が減っていくので、`dp[i+1][...]` の行はすでに埋まっています。`j` は `i` より大きいほうへ進むので、`dp[i][j-1]` も埋まっています。

**書き方2：区間の幅を明示的に回す**。

```python
for length in range(2, n + 1):        # 区間の幅
    for i in range(n - length + 1):
        j = i + length - 1
        ...
```

こちらのほうが「狭い区間から」という意図がコードに直接現れます。どちらでも構いませんが、**自分がどちらの順序で埋めているのかを説明できること**が大事です。

<Callout type="warn" title="表の左下（j &lt; i）は使いません">
  `dp[i][j]` は区間 `[i, j]` の答えなので、`j < i` は「空の区間」であって意味を持ちません。シミュレーターの表で左下が灰色になっているのはこのためです。

  ここを 0 のまま放置して構わないのですが、`for j in range(n)` のように全体を回してしまうと、意味の無いマスにも遷移式を適用してしまい、`dp[i+1][j-1]` などが変な値を拾います。**`j` は必ず `i` 以上から回す**と決めてください。

  また、対角線（`dp[i][i]`、1文字だけの区間）の初期値も忘れやすい部分です。回文なら 1、コストの最小化なら 0、というように問題ごとに違います。
</Callout>

## 「最後に処理する1つ」を決める：Burst Balloons

風船の問題に戻ります。区間で状態を持つところまでは同じですが、もう一段の工夫が要ります。

まず素直に「**最初に割る風船**を `k` に決める」と考えてみます。すると `k` を割った瞬間に列が縮み、`k` の左側と右側が**新しく隣り合って**しまいます。左右が独立していないので、「左の答え + 右の答え」という形に分解できません。

ここで発想を裏返します。「**この区間で最後に割る風船**を `k` に決める」としたらどうでしょうか。

`k` が最後に割られるということは、その時点で `k` の左右にある風船は**すべて割り終えている**ということです。つまり `k` を割るときに隣にいるのは、区間のさらに外側にある風船、すなわち**区間の両端**です。両端は区間の外なので、この区間の処理のあいだ動きません。

そして、`k` より左側の風船たちと、右側の風船たちは、**お互いに影響しません**（間に `k` が立ちはだかっているので、隣り合うことがありません）。左右をきれいに分解できます。

そこで `dp[i][j]` を「**開区間** `(i, j)` の中の風船をすべて割ったときの最大コイン」と定義します。両端の `i` と `j` は割らずに残す、という約束です。

```python
def max_coins(nums):
    vals = [1] + nums + [1]           # 両端に 1 を足して境界を消す
    n = len(vals)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n):        # 区間の幅を、狭いほうから広げていく
        for i in range(n - length):
            j = i + length            # 開区間 (i, j)。両端は割らずに残す
            for k in range(i + 1, j): # k を「この区間で最後に割る風船」に決める
                gain = vals[i] * vals[k] * vals[j]
                dp[i][j] = max(dp[i][j], dp[i][k] + gain + dp[k][j])
    return dp[0][n - 1]
```

遷移式の3つの項を確認してください。

- `dp[i][k]`：`k` より左側の風船を全部割ったときのコイン。両端 `i` と `k` は残っている
- `vals[i] * vals[k] * vals[j]`：最後に `k` を割るときのコイン。このとき隣にいるのは、必ず `i` と `j`
- `dp[k][j]`：`k` より右側の風船を全部割ったときのコイン

両端に 1 を足しているのは、「端の外側は 1 とみなす」という問題文のルールを、**場合分けではなく配列の形で表現する**ためです。番兵を置くことで、`i - 1` や `i + 1` が範囲外になる心配が消えます。

<Callout type="tip" title="「最後の1つを決める」は区間 DP の定番の切り口です">
  操作の順番によって状況が変わる問題では、「最初」ではなく「**最後**」を決めると分解できることがよくあります。

  - Burst Balloons：最後に割る風船を決めると、左右が独立する
  - Minimum Score Triangulation of Polygon：多角形のある辺について、その辺と三角形を作る頂点 `k` を決めると、多角形が2つに割れる
  - Strange Printer：区間の左端の文字を、どこまで一気に印字するかを決める

  素直な向き（最初から）で分解できないときは、**逆の向き（最後から）を試す**。これは覚えておく価値のある手筋です。
</Callout>

## この型の計算量

| 問題 | 状態の数 | 1状態あたりの遷移 | 合計 |
| --- | --- | --- | --- |
| Longest Palindromic Subsequence | O(N²) | O(1) | O(N²) |
| Burst Balloons | O(N²) | O(N)（`k` を全部試す） | **O(N³)** |
| Minimum Score Triangulation | O(N²) | O(N) | O(N³) |

区間 DP は、状態が O(N²) あるうえに、遷移で区間の分け方を全部試すと O(N) かかるため、**O(N³) になることが多い**型です。N が 500 なら 1.25 億回でぎりぎり、N が 100 なら余裕、というのが目安になります。

逆に言えば、**制約で N が 100〜500 程度に抑えられていたら、O(N³) を許す意図がある**と読めます。これは区間 DP を疑う強い手がかりです。

## 「これは区間 DP だ」と気づくためのサイン

- 答えが**両端から**決まる（回文、対称性）
- 要素を1つ処理すると、**残りの並びや隣接関係が変わる**
- 「区間をまとめる」「区間を2つに割る」操作が出てくる
- 多角形、括弧列、連続する箱や石など、**まとまりとして扱う対象**がある
- 制約の N が 100〜500 と小さい（O(N³) 前提の出題）

<Callout type="warn" title="連続した部分配列の問題すべてが区間 DP ではありません">
  「区間」という言葉が出てきても、区間 DP が要るとは限りません。

  - 区間の**和**が欲しいだけ → 累積和
  - 連続する部分配列の中で条件を満たす最長／最短 → Sliding Window
  - 区間の更新と取得が交互に来る → BIT / セグメント木
  - 区間を**どう分割するか**を決める必要があり、分割の仕方で答えが変わる → 区間 DP

  見分けるポイントは、**「区間の内側をどう処理するか」に選択の余地があるかどうか**です。選択の余地があり、その最適な選び方を探しているなら、区間 DP の出番です。
</Callout>
