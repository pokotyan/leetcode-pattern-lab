## 配列と何が違うのか

配列は「連続したメモリの上に、値が順番に並んでいる」データ構造でした。これには、途中に要素を挿入するときに後ろを全部ずらさなければいけない、というデメリットがあります。

連結リストは、それぞれの値（ノード）が**バラバラの場所に置かれていて、次のノードへの矢印だけでつながっている**という構造です。矢印を1本付け替えるだけで挿入や削除ができる代わりに、`nums[5]` のように**いきなり5番目へジャンプすることはできません**。先頭から矢印をたどっていくしかありません。

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

これが1つのノードの正体です。「値」と「次のノードへの矢印」の2つだけを持っています。

## 矢印を1本ずつ付け替える：リストの反転

一番最初に慣れておきたいのが、リストを反転する操作です。

> 連結リスト `1 → 2 → 3 → 4 → 5` が与えられます。これを逆順の `5 → 4 → 3 → 2 → 1` にしてください。

配列なら `nums[::-1]` で一瞬ですが、連結リストではそうはいきません。**各ノードの矢印を、1つずつ逆向きに付け替えていく**必要があります。

ここでの一番のハマりどころは、「矢印を付け替えたら、次にどのノードに進めばいいかわからなくなる」ことです。`cur.next = prev` と書いた瞬間、`cur` の本来の「次」の情報は上書きされて消えてしまいます。

そこで、**矢印を付け替える前に、次に進むべき場所を別の変数に退避しておきます。** `next_node = cur.next` を先にやっておけば、あとで矢印を書き換えても迷子になりません。

```python
def reverse_list(head):
    prev = None
    cur = head
    while cur:
        next_node = cur.next   # 次のノードを先に退避しておく
        cur.next = prev        # 今のノードの矢印を、前のノードへ向け直す
        prev = cur              # prev を1つ進める
        cur = next_node          # cur も1つ進める（退避しておいた next へ）
    return prev                  # 最後に prev が新しい先頭
```

<ReverseLinkedList client:visible />

1手ずつ進めて、矢印がどちらを向いているかを確認してみてください。`prev` は「もう反転し終わった部分の先頭」を指していて、リストの反転は「毎回1本だけ矢印を裏返して、その境界を少しずつ右へずらしていく」作業だとわかります。

<Callout type="warn" title="退避の順番を間違えると、リストが千切れます">
  もし `cur.next = prev` を `next_node = cur.next` より先に実行してしまうと、その時点で `cur` の本来の「次」の情報が失われます。そうなると、`cur = next_node` で進もうとしても、どこへ進めばいいかわからなくなり、リストの途中で処理が止まってしまいます。**「壊す前に、必要な情報を退避する」**という順番は、連結リストの問題全般で繰り返し出てくる注意点です。
</Callout>

## 先頭が変わる操作は、ダミーノードで楽をする

リストの先頭にあるノードを削除したり、先頭に新しいノードを挿入したりする処理では、「もし対象が先頭だったら」という特別扱いが必要になりがちです。これを避ける定番のテクニックが、**ダミーノード**です。

本物の先頭の前に、値を気にしない仮のノードを1つ置いておきます。こうすると、「先頭を操作する」という特別なケースが、「ダミーノードの次を操作する」という普通のケースに変わり、場合分けが消えます。

```python
dummy = ListNode(0, head)
# ... dummy.next を操作していく ...
return dummy.next   # 最後に本当の先頭を取り出す
```

`Merge Two Sorted Lists` や `Remove Nth Node From End of List` のように、「先頭が変わるかもしれない」問題では、まずダミーノードを置けないか考えてみてください。

## 速さの違う2人：Slow / Fast Pointers

ここからが連結リストの記事の本題です。**同じ道具で、まったく違う2つの問題が解ける**という面白いパターンを見ていきます。

想像してみてください。円形のトラックを、2人が同じ方向に走っています。1人は普通の速さ、もう1人はその2倍の速さです。もしトラックが本当に輪っかになっているなら、速いほうはいつか必ず遅いほうに追いつきます。もしトラックが輪っかではなく、まっすぐなゴールがあるなら、速いほうは遅いほうに追いつく前にゴールに着いてしまいます。

これが、連結リストでサイクル（輪っか）があるかどうかを判定する仕組みです。

> 連結リストが与えられます。リストの中に輪っかがあるかどうかを判定してください。

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next        # 1歩ずつ進む
        fast = fast.next.next   # 2歩ずつ進む
        if slow is fast:
            return True         # 追いついた = 輪っかがある
    return False                 # fast が None に着いた = 輪っかは無い
```

<LinkedListCycle client:visible />

「輪っかなし」と「末尾が1番目に戻る」を両方試してみてください。輪っかが無いときは `fast` が先にリストの終端（`None`）へ着いてループが終わります。輪っかがあるときは、`fast` が輪っかの中をぐるぐる回っているうちに、必ず `slow` に追いつきます。

<Callout type="tip" title="なぜ必ず追いつけると言えるのか">
  輪っかの中に入ると、`fast` は `slow` よりも1歩ずつ多く進みます。輪っかの長さを `L` とすると、2人の距離は毎回1ずつ縮まっていくので、最大でも `L` 回のループ内で必ず追いつきます。**無限に輪っかの中を追いかけっこし続けることはない**というのが、この判定が正しく終わる理由です。
</Callout>

同じ「速さの違う2人」という道具は、リストの**中央**を求める問題にも使えます。`fast` が2歩ずつ進んで先にリストの端に着いたとき、`slow` はちょうど半分の位置にいます。`fast` が最後まで進む間に、`slow` はその半分しか進んでいないからです。`Reorder List` のような問題は、この「中央を求める」処理と、さきほどの「反転」処理、そして2つのリストを交互に繋ぐ処理を組み合わせて作られています。1つずつの道具に分解できれば、難しい問題も部品の組み合わせとして見えてきます。

## この型の計算量

| 用途 | 時間 | 空間 |
| --- | --- | --- |
| 反転 | O(N) | O(1) |
| ダミーノードを使った挿入・削除 | O(N) | O(1) |
| Slow / Fast Pointers（中央・サイクル検出） | O(N) | O(1) |

配列と違って、連結リストの操作はほとんどが O(1) の追加メモリで済みます。矢印を付け替えるだけなので、新しい配列を作る必要がないからです。

## 「これは連結リストの型だ」と気づくためのサイン

- 「**先頭が変わるかもしれない**」削除・挿入 → ダミーノードを検討する
- 「**壊す前に情報を退避する**」必要がありそうな、矢印の付け替え → 反転のパターン
- 「**輪っかがあるか**」「**中央**を求めよ」「**後ろから k 番目**」→ Slow / Fast Pointers
- LRU Cache のように「**削除も追加も O(1) で**」という要求 → 双方向リスト + ハッシュテーブル（別記事で詳しく扱います）
