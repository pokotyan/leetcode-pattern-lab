## スタックは「皿を積む」だけのシンプルなデータ構造です

スタックは、洗い終わった皿を1枚ずつ積み重ねていくところを思い浮かべてください。**新しい皿は一番上にしか置けません**し、皿を取るときも**一番上からしか取れません**。これを LIFO（Last-In-First-Out：最後に入れたものが最初に出る）と呼びます。

配列との違いは、「途中の要素にはアクセスしない」と割り切っている点です。この制約があるおかげで、「直前に何を置いたか」「対応する相手が見つかるか」といった問題が、驚くほどすっきり書けます。

## 対応関係を持つ問題：括弧のチェック

一番わかりやすい例から始めます。

> 文字列 `s` が、開き括弧と閉じ括弧の対応が正しく取れているかどうかを判定してください。`s = "()[]{}"`、`"(]"`、`"([)]"` のように、3種類の括弧が混ざります。

人間なら、文字列を左から読みながら、**開き括弧が出てきたら「あとで閉じるべき候補」として頭の片隅に置いておき**、閉じ括弧が出てきたら「一番最近、頭に置いた開き括弧」と対応しているかを確認するはずです。

この「一番最近置いたものを確認する」という動きが、まさにスタックです。開き括弧が来たら積む、閉じ括弧が来たら一番上を降ろして種類が合うか確認する。これだけです。

```python
PAIR = {")": "(", "]": "[", "}": "{"}

def is_valid(s: str) -> bool:
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)              # 開き括弧は積む
        else:
            if not stack or stack[-1] != PAIR[ch]:
                return False               # 相手がいない or 種類が違う
            stack.pop()                    # 対応が取れたので降ろす
    return len(stack) == 0                 # 積み残しが無ければ成功
```

<ValidParentheses client:visible />

入力を `([)]` に変えてみてください。`)` が出てきた時点でスタックのトップは `[` になっていて、`(` とは種類が違います。ここで即座に `False` が確定します。見た目は「括弧の対応が取れているように見えなくもない」文字列ですが、**入れ子の順序が正しくない**ため無効、というのがこの問題のひっかけどころです。

<Callout type="warn" title="判定条件は2つ、両方とも必要です">
  「閉じ括弧が来たときにスタックが空、または種類が違う」場合に `False` を返すのはもちろんですが、**文字列を最後まで読み終えたあとにスタックが空になっているか**も必ず確認してください。
  たとえば `s = "((("` は、閉じ括弧が一度も出てこないので `while` ループの中では一度も `False` になりませんが、最後にスタックに `(` が3つ積み残った状態です。これを見逃すと、開きっぱなしの括弧を正しいと判定してしまいます。
</Callout>

## 直前の要素と比較して、潰していく：Asteroid Collision

対応関係だけでなく、**「直前に置いたものと今のものを比べて、どちらかを消す・変える」**という処理も、スタックにするととても素直に書けます。

> `asteroids` という配列があります。正の数は右へ、負の数は左へ進む隕石の大きさを表します。右へ進む隕石のすぐ後ろに左へ進む隕石が続くと衝突し、**小さいほうが消え、同じ大きさなら両方消えます。** すべての衝突が終わったあとの隕石の配列を求めてください。

配列を左から順番に見ていきながら、**「今の隕石」と「スタックの一番上（＝直前に生き残った隕石）」を比較する**という流れになります。ポイントは、右向き `→` の直後に左向き `←` が来たときだけ衝突が起きる、という条件です。同じ方向どうし、あるいは左向きのあとに右向きが来ても、すれ違うだけで衝突しません。

`asteroids = [10, 2, -5]` を例に手で追ってみます。

1. `10`（右向き）を見る。スタックは空なので、そのまま積む。`stack = [10]`
2. `2`（右向き）を見る。スタックのトップは `10`（同じ右向き）なので衝突しない。そのまま積む。`stack = [10, 2]`
3. `-5`（左向き）を見る。スタックのトップは `2`（右向き）なので、正面衝突が起きます。`2 < 5` なので、小さい `2` が消えます。`stack = [10]`
4. まだ `-5` は生きているので、**もう一度**スタックのトップと比較します。トップは `10`。`10 > 5` なので、今度は `-5` のほうが消えます。`stack = [10]` のまま

「1つ消したら終わり」ではなく、**消えた後も自分がまだ生きているなら、次の相手ともう一度比較する**というところが、この問題を難しくしているポイントです。だからこそ `while` ループになっています。

```python
def asteroid_collision(asteroids):
    stack = []
    for a in asteroids:
        alive = True
        while alive and stack and a < 0 < stack[-1]:
            top = stack[-1]
            if top < -a:
                stack.pop()          # 上のほうが小さい。消して続行
            elif top == -a:
                stack.pop()          # 同じ大きさ。両方消える
                alive = False
            else:
                alive = False        # 上のほうが大きい。a が消える
        if alive:
            stack.append(a)
    return stack
```

<AsteroidCollision client:visible />

`10, 2, -5` の例で実際にステップを進めてみてください。`2` が消えたあとも `while` ループが続き、もう一度 `10` と比較しにいく様子が見えます。

<Callout type="tip" title="alive フラグが無いと、何が起きるか">
  `alive` という変数は、「今見ている隕石 `a` が、まだ生き残っているかどうか」を管理しています。これが無いと、`a` がすでに消えたあとなのに `if alive: stack.append(a)` の判定ができず、消えたはずの隕石をもう一度積んでしまいます。
  「ループの中で自分自身が消えることがある」という、少し変わった構造の問題なので、こういう状態フラグが必要になります。
</Callout>

## この型の計算量

| 用途 | 時間 | 空間 |
| --- | --- | --- |
| 括弧の対応チェック | O(N) | O(N) |
| 隕石の衝突（Asteroid Collision） | O(N) | O(N) |

「1つの要素に対して `push` と `pop` はそれぞれ高々1回ずつ」という考え方をすると、`while` ループが入っていても全体では O(N) になることが多いです（Asteroid Collision の各要素も、最終的には高々1回しか push されません）。

<Callout type="tip" title="補助情報を、値と一緒に積む">
  `Min Stack`（スタックの最小値を O(1) で取得できるようにする問題）では、単に値だけを積むのではなく、**「その時点でのスタック全体の最小値」も一緒に積んでおく**という工夫をします。こうすると `pop` したときも、その1つ下の最小値が自然に復元されます。「値だけでなく、その時点で欲しい情報もセットで積む」というのは、スタックを使う問題でよく出てくる発想です。
</Callout>

- 「**対応関係**」「開く・閉じる」「ペアになる」
- 「**直前の**要素と比較して」「隣り合う要素を消す・変える」

- 逆ポーランド記法のように、**演算子が来たら直近の値を使う**という構造
