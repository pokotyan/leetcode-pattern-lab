## この記事を読む前に押さえておく型

- **累積和**：区間の端点を「ここで +1、ここで −1」というイベントに置き換えて足し上げると、その時刻に重なっている個数が出ます。これは差分配列とまったく同じ計算で、この記事の後半で使います
- **ヒープ**：「いま使っている部屋のうち、一番早く空くのはどれか」を毎回取り出す必要があります。この「常に最小を取り出す」操作をヒープで O(log N) にできることを知らないと、必要な部屋数を求める型が組み立てられません

## まず、困っている状況を体験してみます

> 会議の予定が `[[0, 30], [5, 10], [15, 20]]` のように与えられます。すべての会議を開くには、会議室が最低何室必要でしょうか。

必要な部屋数は、**同じ瞬間に並行して走っている会議の最大数**です。まず思いつくのは、会議を全部のペアで見比べて重なりを数える方法でしょう。

```python
for i in range(n):
    for j in range(n):
        if 重なっている(i, j):
            ...      # O(N^2)
```

ところが、これでは「どの瞬間に何件重なっていたか」までは分かりません。ペアで重なっていても、3件が同時に重なっているのか、時間をずらして2件ずつ重なっているのかを区別できないからです。しかもペアの数は N² なので、N = 10,000 で1億回に達します。

ここで一度、問題の見え方を変えてみます。会議を「長さのある区間」として扱うから難しいのであって、**会議を「始まった」「終わった」という2つの出来事に分解してしまえば、あとは時刻順に並べるだけの一次元の問題になります。**

## 発想を変える：端点だけをイベントとして時刻順に並べる

区間の問題で本当に意味があるのは、**端点だけ**です。区間の内側では何も起きません。状況が変わるのは、区間が始まる瞬間と終わる瞬間だけです。

そこで、数直線の上を左から右へ1本の縦線（掃過線）が動いていくところを想像してください。その線が区間の左端に触れたら「1つ増えた」、右端に触れたら「1つ減った」と記録していきます。これが Line Sweep（掃過）と呼ばれる型です。

この型は、次の3つの形でよく出てきます。どれも「まず端点で並べ替える」という最初の一歩が共通しています。

| 形 | 並べ替えの基準 | その後にやること | 代表問題 |
| --- | --- | --- | --- |
| まとめる | 開始の早い順 | 直前に確定した区間と比べて、重なれば伸ばす | Merge Intervals |
| 同時に何個あるか | 開始の早い順（＋ヒープ） | 終了時刻をヒープに入れ、空いた部屋を再利用する | Meeting Rooms II |
| 重なり回数を数える | 端点をイベント化して時刻順 | +1 / −1 を足し上げて最大値を取る | My Calendar II |

## まとめる：ソートすると、比べる相手が1つだけになる

まずは一番素直な形からです。

> 区間 `[[1,3], [2,6], [8,10], [15,18]]` のうち、重なっているものをつなげて、重ならない区間の集まりにしてください。

ここで大事なのは、**開始時刻の早い順に並べ替えてしまう**ことです。並べ替えると、次の性質が手に入ります。

いま見ている区間の開始時刻は、これまでに見たどの区間の開始時刻よりも後（または同時）です。ということは、この区間が重なる可能性があるのは、**直前に確定した区間だけ**です。それより前の確定済み区間は、終端がさらに手前にあるので届きません。

比べる相手が毎回1つに絞られるので、二重ループが消えます。

```python
def merge(intervals):
    intervals.sort()                          # 開始時刻の早い順に並べる
    merged = []
    for start, end in intervals:
        if merged and start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)   # 重なるので伸ばす
        else:
            merged.append([start, end])               # 離れているので新しい区間
    return merged
```

<MergeIntervals client:visible />

「内側に入る」という入力を選んでみてください。`[1, 10]` の内側に `[2, 3]` が完全に入っているとき、終端は `max(10, 3) = 10` のまま変わりません。`merged[-1][1] = end` と書いてしまうと、ここで区間が**縮んで**しまい、そのあとの判定が全部狂います。`max` が要るのはこのためです。

<Callout type="warn" title="「端が接している」を重なりと見なすかどうか">
  `[1, 4]` と `[4, 5]` をつなげて `[1, 5]` にすべきかどうかは、問題によって違います。

  - Merge Intervals は「接していればつなげる」が正解なので、判定は `start <= merged[-1][1]` です
  - 一方 Meeting Rooms II では、10時に終わる会議と10時に始まる会議は同じ部屋を使えるので、接している場合は**重なっていない**と扱います

  つまり、不等号に等号を含めるかどうかが問題ごとに反転します。ここを間違えても小さい入力ではたいてい正しい答えが出てしまうので、**必ず「端が接する入力」を自分で1つ作って確かめてください。**
</Callout>

## 同時に何個あるか：終了時刻をヒープに入れる

会議室の問題に戻ります。開始時刻の早い順に会議を見ていくところまでは同じです。違うのは、**いま使っている部屋を覚えておく必要がある**点です。

部屋について本当に知りたいのは「いつ空くか」だけなので、使用中の部屋は**終了時刻の集まり**として持っておけば十分です。新しい会議が始まるとき、確認することはただ1つ。

> いま使っている部屋のうち、**一番早く空く部屋**は、この会議が始まるまでに空くか？

空くならその部屋を使い回せます。空かないなら、他のどの部屋はもっと遅くまで塞がっているので、新しい部屋を1つ増やすしかありません。「一番早く空く部屋」を毎回取り出すのは、最小値を取り出す操作そのものなので、ヒープの出番です。

```python
import heapq

def min_meeting_rooms(intervals):
    intervals.sort()                  # 開始時刻の早い順
    heap = []                         # 使用中の部屋の「終了時刻」
    for start, end in intervals:
        if heap and heap[0] <= start:
            heapq.heappop(heap)       # 一番早く空く部屋が、この会議の前に空いた
        heapq.heappush(heap, end)     # この会議で部屋を1つ使う
    return len(heap)
```

<MeetingRoomsII client:visible />

`[[0,30], [5,10], [15,20]]` を1手ずつ追ってみます。

1. `[0, 30)` を見る。ヒープは空なので部屋を1つ使う。ヒープは `[30]`
2. `[5, 10)` を見る。一番早く空くのは 30 だが、会議は 5 に始まる。**間に合わないので2部屋目**。ヒープは `[10, 30]`
3. `[15, 20)` を見る。一番早く空くのは 10 で、15 までに空いている。**その部屋を使い回せる**ので取り出してから入れ直す。ヒープは `[20, 30]`

最後にヒープに残った2が答えです。ここで疑問に思うかもしれません。「取り出してすぐ入れ直すなら、ヒープの大きさは変わらないのでは？」その通りで、**部屋を使い回せた回では大きさが変わらず、使い回せなかった回だけ1つ増えます。** だからこそ、最後の大きさが「同時に必要だった部屋数の最大値」になります。

<Callout type="tip" title="ヒープを使わない、もう1つの書き方">
  同じ問題は、端点をイベントに分解しても解けます。開始で `+1`、終了で `−1` を並べて時刻順に足し上げ、その最大値を取るだけです。

  ```python
  def min_meeting_rooms_events(intervals):
      events = []
      for start, end in intervals:
          events.append((start, 1))     # 開始で +1
          events.append((end, -1))      # 終了で -1
      events.sort()
      cur = best = 0
      for _, delta in events:
          cur += delta
          best = max(best, cur)
      return best
  ```

  `events.sort()` はタプルの比較なので、時刻が同じときは第2要素の小さいほう、つまり `−1`（終了）が先に処理されます。10時に終わる会議と10時に始まる会議が同じ部屋を使えるのは、この順番のおかげです。**もしこの問題が「接していても別の部屋が要る」だったら、終了を `+1` 側より後に回す必要があります。** 並べ替えの基準そのものが、問題文の解釈を表しているわけです。

  足し上げて最大値を取るこの計算は、差分配列とまったく同じものです。時刻の範囲が狭ければ差分配列、広ければイベントの並べ替え、と使い分けます。
</Callout>

## この型の計算量

| やり方 | 時間 | 空間 | 内訳 |
| --- | --- | --- | --- |
| 全ペアを見比べる | O(N²) | O(1) | 重なりの個数までは正しく数えられない |
| 開始順ソート + 直前と比較 | O(N log N) | O(N) | ソートが支配的。走査は O(N) |
| 開始順ソート + ヒープ | O(N log N) | O(N) | ソート + N 回のヒープ操作 |
| 端点のイベント化 | O(N log N) | O(N) | 端点は 2N 個。そのソートが支配的 |
| 差分配列（時刻の範囲が狭いとき） | O(N + T) | O(T) | T は時刻の種類数。ソートが要らないぶん速い |

どの形でも、効いているのは「ソートで O(N log N) を払って、走査を1回にする」という取引です。区間の問題で O(N²) が見えたら、まず並べ替えを疑ってください。

## 「これは区間の掃過だ」と気づくためのサイン

- 入力が `[[start, end], ...]` の形で与えられる
- 「重なっている」「同時に」「かぶらないように」「最大でいくつ並行するか」という言い方が出てくる
- 「予約」「会議」「日程」「線分」「ビルの高さ」といった、時間や位置の広がりを持つもの
- 素直に書くと全ペアの比較になり、制約が 10<sup>4</sup> を超えている
- 答えが「区間の集まり」か「同時に存在する個数」のどちらかである

<Callout type="warn" title="何でソートするかは、問題ごとに変わります">
  区間の問題は「とりあえず開始時刻でソート」で片付くものばかりではありません。

  - **Merge Intervals**：開始の昇順。重なる相手を直前の1つに絞るため
  - **Non-overlapping Intervals**（重なりを最小の削除で解消する）：**終了**の昇順。早く終わるものを優先して残すほうが、後ろに余地が残るため
  - **Remove Covered Intervals**：開始の昇順、同じ開始なら終了の**降順**。長いほうを先に見ることで、後から来たものを「覆われている」と判定できるため

  「なぜその基準で並べるのか」を言葉にできないまま書き始めると、ほとんどの場合どこかで破綻します。まず並べ替えの基準を決め、その基準のおかげで**何が1つに絞れるのか**を確認してから、ループを書いてください。
</Callout>
