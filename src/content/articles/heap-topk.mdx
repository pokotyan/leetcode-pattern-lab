## ヒープは「一番上だけ、すぐ取り出せる箱」です

ヒープ（優先度付きキュー）は、中身を完全にソートしているわけではありませんが、**「一番小さい（または一番大きい）値だけは、いつでもすぐ取り出せる」**という特別な性質を持つデータ構造です。追加（push）も取り出し（pop）も O(log N) で済みます。

Python では `heapq` という標準ライブラリで使えますが、これは**最小ヒープ**（常に一番小さい値が先頭に来る）だけを提供しています。最大値がすぐ欲しい場合は、値にマイナスをかけて入れる、というちょっとしたテクニックを使います。

```python
import heapq

heap = []
heapq.heappush(heap, 5)
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)
print(heap[0])   # 1（一番小さい値がすぐわかる）
print(heapq.heappop(heap))  # 1 を取り出す
```

## 全部ソートするのは、実はやりすぎです

こんな問題を考えます。

> 配列の中から、`k` 番目に大きい値を求めてください。

一番素直なのは、配列全体をソートして `nums[-k]` を見ることです。これは O(N log N) かかります。でも、よく考えてみてください。**「全部を正しい順番に並べる」必要は、本当にあるでしょうか？** 欲しいのは `k` 番目の値だけです。

ここで使うのが、**「サイズが k を超えたら、一番小さいものを追い出す」ヒープ**です。配列を1つずつ見ながら、このサイズ制限付きのヒープに追加していきます。すべて見終わったとき、ヒープに残っている `k` 個が「上位 `k` 個」で、その中の一番小さいもの（ヒープの先頭）が、ちょうど `k` 番目に大きい値になります。

```python
import heapq

def find_kth_largest(nums, k):
    heap = []
    for num in nums:
        heapq.heappush(heap, num)
        if len(heap) > k:
            heapq.heappop(heap)     # 一番小さいものを追い出す
    return heap[0]                  # heap のトップが k 番目に大きい
```

`k=2` の例で追ってみてください。`3, 2, 1` まで見た時点でヒープは `[1, 2, 3]` の3個になり、サイズ制限の2を超えるので一番小さい `1` が追い出されます。**「今まで見た中の上位 k 個」だけを、常にヒープが覚えている**という状態が保たれ続けます。

<Callout type="tip" title="なぜ最小ヒープなのに「大きい方」が求まるのか">
  「上位k個を保ちたい」のに、なぜ最小ヒープ（一番小さい値がすぐわかるヒープ）を使うのか、不思議に思うかもしれません。
  理由は、**「追い出すべき候補（一番小さいもの）を、すぐに見つけたいから」**です。サイズ制限を超えたら真っ先に切り捨てたいのは「今の上位k個の中で、一番弱い（小さい）もの」なので、それをすぐ取り出せる最小ヒープが最適な道具になります。
</Callout>

## この考え方（size-k のヒープ）が使える場面

「全体をソートせず、上位 k 個だけを保つ」という考え方は、形を変えて色々な問題に出てきます。

- `Top K Frequent Elements`：出現回数をハッシュテーブルで数えたあと、その回数をキーにして size-k のヒープで絞り込みます
- `K Closest Points to Origin`：原点からの距離を計算しながら、size-k のヒープで「近い順の上位k個」を保ちます

どちらも「まず何らかの値を計算する」→「その値を使って size-k のヒープで絞り込む」という2段構えになっている点が共通しています。

<Callout type="warn" title="k が小さいときにこそ効果が出る">
  この方法の計算量は O(N log k) です。ソートする方法（O(N log N)）と比べて、`k` が `N` よりずっと小さいときに真価を発揮します。`k` が `N` に近い場合は、素直にソートしたほうがシンプルで、速度もほとんど変わりません。「常にヒープが正義」というわけではなく、**k の大きさを見て判断する**ことも大切です。
</Callout>

## 発展：2つのヒープで中央値を追いかける

`Find Median from Data Stream` は、データが次々と流れてくる中で、その時点までの中央値を常に答え続ける問題です。ここでは、**小さい方の半分を最大ヒープ、大きい方の半分を最小ヒープ**という、2つのヒープに分けて持つ、という発展的な考え方を使います。

2つのヒープのサイズの差が1以下になるように保っておけば、中央値は「どちらかのヒープの先頭」、あるいは「両方のヒープの先頭の平均」としてすぐに求まります。size-k のヒープと同じく、「全部を並べ替えない」という発想の延長線上にあるテクニックです。

## この型の計算量

| 用途 | 時間 | 空間 |
| --- | --- | --- |
| ヒープへの push / pop | O(log N) | — |
| size-k のヒープで Top-K を求める | O(N log k) | O(k) |
| 全体をソートして求める | O(N log N) | O(N)（実装による） |

## 「これはヒープを使う型だ」と気づくためのサイン

- 「**上位 k 個**」「**k 番目に大きい（小さい）**」を求めたい
- データが**次々と流れてくる**中で、最小・最大・中央値を随時答えたい
- 複数の候補の中から、**常に一番良いものだけを取り出したい**（ダイクストラ法もこの一例です）
- k が N よりずっと小さいと、問題文や制約から読み取れる
