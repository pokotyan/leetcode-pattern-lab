## まず、困っている状況を体験してみます

次のような問題があったとします。

> 配列 `[2, 7, 11, 15]` の中から、足すと 9 になる2つの数字を探してください。

答えは `2` と `7` です。簡単ですよね。あなたはきっと、頭の中で総当たりのように「2と7？ 9だ、見つかった」と探したはずです。これが一番素直なやり方で、コードにすると次のようになります。

```python
for i in range(n):
    for j in range(i + 1, n):
        ...  # O(N^2)
```

`i` 番目の要素を1つ選んで、それより後ろにある `j` 番目の要素と全部ペアにして確かめる。これで確実に答えは見つかります。

問題は、**配列が大きくなったときにどれだけの回数チェックすることになるか**です。配列の長さが N のとき、このペアの数はだいたい N²/2 個になります。N が 4 くらいなら6ペアなので余裕ですが、これが N = 100,000（10万）だったらどうなるでしょうか。

計算してみると、ペアの数はおよそ 50 億個になります。コンピュータが1秒間にこなせる処理がだいたい1億回だとすると、**50秒くらいかかる計算**です。LeetCode の実行時間制限は普通1〜2秒なので、これは確実にタイムアウトします。

つまり、「全部のペアを確かめる」というやり方そのものを、そもそもやめる必要があります。

## 発想を変える：確かめる前に捨てる

ここで欲しいのは、「このペアはもう確かめなくていい」と**確かめる前に判断できる仕組み**です。それができれば、全部のペアを見なくても答えにたどり着けます。

Two Pointers は、配列の中に2つの位置（ポインタ）を置いて、それを動かしながら答えを探していくテクニックです。ポイントは、**片方を動かしたとき、もう片方をどちらに動かすべきかが自動的に決まる**という状況を作ることです。そうすれば、2つのポインタは合計で高々 N 回しか動かないので、全体の処理は O(N) になります。

Two Pointers には大きく分けて2つの形があります。まずは表で全体像をつかんでおいて、あとで1つずつ実際に手を動かしながら理解していきましょう。

| 形 | ポインタの初期位置 | 動き方 | よく出る問題 |
| --- | --- | --- | --- |
| 逆方向 | 両端（先頭と末尾） | お互いに向かって内側へ寄っていく | 回文判定、和が target になるペア探し、面積の最大化 |
| 同方向 | 両方とも先頭 | 速いほうが先を偵察し、遅いほうが「ここまでは確定」という位置を指す | 要素の詰め直し、重複除去、部分列の判定 |

## 逆方向：両端から寄せていく

一番わかりやすい例から始めます。文字列が回文（前から読んでも後ろから読んでも同じ）かどうかを判定する問題です。

`"racecar"` という文字列を例に、人間ならどう確かめるか考えてみてください。おそらく、一番左の文字 `r` と一番右の文字 `r` を見比べて「同じだ」と確認し、次は内側の `a` と `a` を見比べて……というふうに、**両端から内側に向かって1文字ずつチェックしていく**はずです。途中で1回でも文字が違えば、その時点で「回文じゃない」と確定して、それ以上見る必要はありません。

これをそのままコードにします。

```python
def is_palindrome(s: str) -> bool:
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True
```

`left` が左端、`right` が右端を指すポインタです。`left < right` のあいだ、つまり2つのポインタがすれ違う前まで比較を続けます。

<ValidPalindrome client:visible />

実際にステップを1手ずつ進めてみてください。入力欄を `interviewcat` に変えると、1文字目の `i` と最後の文字目の `t` を比べた瞬間に不一致が見つかり、即座に `False` を返すのがわかります。残りの文字を一切見ていません。これが Two Pointers の効きどころです。

<Callout type="tip" title="なぜメモリを使わずに済むのか">
  `s[::-1]` で文字列を反転させて元の文字列と比較する、という書き方でも回文判定はできます。ただしこれだと、反転済みの文字列を新しく作るぶん O(N) のメモリを使います。
  Two Pointers なら `left` と `right` という2つの数字を持つだけなので、メモリは O(1) で済みます。この違いは、フォローアップの質問で必ずと言っていいほど聞かれます。
</Callout>

## なぜ「逆方向」でうまくいくのか、数字で確かめてみます

回文判定は「両端から寄せる」以外にやりようがないので、ここでは別の問題で「なぜその方向にポインタを動かすのが正解なのか」をじっくり見ていきます。

> 昇順にソート済みの配列から、足すと target になる2つの数字を探してください。

たとえば `numbers = [1, 3, 4, 5, 7, 11]`、`target = 9` としましょう。実際に手を動かして探してみます。

1. `left = 0`（値は1）、`right = 5`（値は11）からスタート。合計は `1 + 11 = 12`。目標の9より**大きすぎます**。
2. ここで疑問に思うかもしれません。「`left` を動かしたらどうなるの？」試しに `left` を1つ進めると `3 + 11 = 14` となり、もっと大きくなってしまいます。配列はソート済みなので、`left` を右に進めると値は必ず大きくなるか同じです。つまり、和が大きすぎるときに `left` を動かすのは**絶対に悪手**です。動かすべきは `right` のほうだと確定します。
3. `right` を1つ左へ動かして `right = 4`（値は7）。合計は `1 + 7 = 8`。今度は目標より**小さすぎます**。
4. 同じ理屈で、今度は `right` を動かしても和はさらに小さくなるだけなので意味がありません。動かすべきは `left` です。
5. `left` を1つ進めて `left = 1`（値は3）。合計は `3 + 7 = 10`。大きすぎるので `right` を動かします。
6. `right = 3`（値は5）。合計は `3 + 5 = 8`。小さすぎるので `left` を動かします。
7. `left = 2`（値は4）。合計は `4 + 5 = 9`。**目標と一致しました。** 答えは `(4, 5)`、1-indexed で `[3, 4]` です。

この手順を眺めると、**大きすぎるときは `right` を、小さすぎるときは `left` を動かす**というルールが、毎回迷いなく決まっていることに気づきます。これをコードにするとこうなります。

```python
def two_sum(numbers, target):
    left, right = 0, len(numbers) - 1
    while left < right:
        s = numbers[left] + numbers[right]
        if s == target:
            return [left + 1, right + 1]
        if s < target:
            left += 1     # 和を大きくしたい
        else:
            right -= 1    # 和を小さくしたい
    return []
```

先ほどの手作業の手順が、そのままステップとして再生されるのを確認してみてください。

<Callout type="warn" title="動かさなかった組み合わせは、本当に無視していいのか">
  さきほどの例で `left = 0`、`right = 5` の和が大きすぎたので `right` を動かしましたが、これは「`left = 0`（値1）と、`right = 5` より左にあるどの数字を組み合わせても target にならない」ということまで保証しているわけではありません。あくまで「`right = 5` は大きすぎたので除外する」というだけです。
  ただし、配列の中で `left = 0` と組み合わせて条件を満たしうる `right` の候補は、`right` を1つずつ左に動かすことで**もれなく試している**ので、心配はいりません。`left` を動かす番になるのは、その `left` について試せる `right` をすべて試し終えたとき（もしくは試す前から明らかに無理だとわかったとき）だけです。
</Callout>

## ソートして持ち込む：3Sum

`3Sum` は、Medium の中でもかなり出題頻度が高い問題です。和が 0 になる**3つの数字の組み合わせ**を、重複なくすべて求めます。

3つ選ぶので、素直に3重ループで書くと O(N³) になってしまいます。ここで発想を1段階変えます。**「1つを固定してしまえば、残りは2つを選ぶ問題になる」**という考え方です。2つを選ぶ問題は、もう見た通り Two Pointers で O(N) で解けます。

手順はこうなります。

1. まず配列を**ソート**します（これで Two Pointers が使える前提が整います）
2. 一番左の数字 `i` を1つ固定します
3. 残りの範囲 `[i+1, n-1]` から、和が `-nums[i]` になるペアを、逆方向 Two Pointers で探します
4. 同じ組み合わせを2回数えてしまわないよう、重複はスキップします

`nums = [-1, 0, 1, 2, -1, -4]` を例に見てみます。ソートすると `[-4, -1, -1, 0, 1, 2]` です。

- `i = 0`（値 -4）を固定。残り `[-1, -1, 0, 1, 2]` から和が 4 になるペアを探しますが、最大でも `1 + 2 = 3` なので見つかりません。
- `i = 1`（値 -1）を固定。残り `[-1, 0, 1, 2]` から和が 1 になるペアを探すと、`left=-1, right=2` で `-1 + 2 = 1` が見つかります。組み合わせは `[-1, -1, 2]`。
- `i = 2` は値がまた `-1` です。**これは直前の `i = 1` と同じ値なので、飛ばします。** 飛ばさないと `[-1, -1, 2]` をもう一度見つけてしまい、同じ答えを2回数えることになります。
- `i = 3`（値 0）を固定。残り `[1, 2]` から和が 0 になるペアを探しますが、`1 + 2 = 3` なので見つかりません。

最終的な答えは `[[-1, -1, 2]]` の1つだけです（実際にはもう1つ `[-1, 0, 1]` が別の位置から見つかります。手元で追ってみてください）。

```python
def three_sum(nums):
    nums.sort()
    res = []
    for i in range(len(nums)):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                       # i の重複をスキップ
        left, right = i + 1, len(nums) - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if s < 0:
                left += 1
            elif s > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1              # left の重複をスキップ
    return res
```

<ThreeSum client:visible />

入力を `-2, 0, 0, 2, 2` に変えてみてください。重複スキップが2箇所とも働く様子が見えます。もしスキップを外してしまうと、`[-2, 0, 2]` という同じ組み合わせが何度も答えに追加されてしまいます。

<Callout type="warn" title="重複スキップは2箇所。忘れやすいのは right 側">
  重複のスキップは次の2つが必要です。

  - **`i` の重複**：`i > 0 and nums[i] == nums[i-1]` なら `continue`。`i > 0` を書き忘れると、配列の先頭要素まで飛ばしてしまうので注意してください
  - **`left` の重複**：答えを1つ見つけて採用した**直後だけ**スキップします。まだ何も見つけていない場面でスキップしても意味がありません

  逆に `right` 側は、スキップを書かなくても問題ありません。`left` を進めた時点で、同じ組み合わせはもう一度は採用されないからです。「両方スキップしなきゃ」と思い込んでコードを複雑にしてしまう人が多いので、ここは覚えておいてください。
</Callout>

## 同方向：書き込む位置と読み取る位置を分ける

ここまでは両端から寄せていく形でしたが、もう1つの形として、**両方とも先頭からスタートして、片方が先を偵察する**というパターンがあります。

たとえば「配列内の 0 を全部末尾に寄せる。ただし0以外の要素の順番は変えない」という問題を考えてみます。

やり方はこうです。`left` を「次に0以外の値を書き込む場所」、`right` を「配列を読み進めていく場所」として使います。`right` で1つずつ配列を見ていき、0でない値を見つけたら、それを `left` の位置に持ってきて `left` を1つ進める。これだけです。

```python
def move_zeroes(nums):
    left = 0                       # 次に非ゼロを置く位置
    for right in range(len(nums)): # 読み取り位置
        if nums[right] != 0:
            nums[left], nums[right] = nums[right], nums[left]
            left += 1
```

`left` は「ここまでは0以外の値で詰め終わった」という境界線を指していて、`right` がその境界線を確認しながら配列全体を1回だけ走査します。`Remove Element`、`Remove Duplicates from Sorted Array`、`Is Subsequence` はどれもこの形で解けます。

<Callout type="tip" title="もう1つの同方向：速度に差をつける">
  同方向にはもうひとつ、`left` と `right` に**移動する速さの差**をつける形（Slow / Fast Pointers）があります。これは連結リストの中央検出やサイクル検出で活躍するので、連結リストの記事でじっくり扱います。ここでは「そういう形もある」とだけ覚えておいてください。
</Callout>

## この型の計算量

| 形 | 時間 | 空間 | なぜそうなるか |
| --- | --- | --- | --- |
| 逆方向（ソート済み前提） | O(N) | O(1) | 2つのポインタが合計で高々 N 回しか動かない |
| 逆方向（自前でソートする） | O(N log N) | O(1)〜O(N) | ソートのコストが支配的。空間は言語やソート実装による |
| 3Sum | O(N²) | O(1) | 外側のループが N 回 × 内側の Two Pointers が N 回。出力用の配列は除く |
| 同方向 | O(N) | O(1) | 配列を1回だけなめる（in-place） |

## 「これは Two Pointers だ」と気づくためのサイン

問題文に次のような要素があったら、Two Pointers を疑ってみてください。

- 「**ソート済み**の配列が与えられる」→ かなりの確率で、ソート済みであることを利用する解法があります
- 「**2つの要素**の組み合わせ」「ペア」「3つ組」というキーワード
- 「**in-place** で」「追加の配列を使わずに」→ 同方向の詰め直しパターン
- 「**両端**」「回文」「面積」「容器」
- ソートしても答えの意味が壊れない（元の順序が答えに関係しない）→ ソートして持ち込める

<Callout type="warn" title="ソートしていいかどうかは、必ず確認する">
  `3Sum` は「値の組み合わせ」だけを求めるので、ソートしても答えは壊れません。
  一方で無印の `Two Sum` は**元の index** を答えとして返す必要があるので、うっかりソートしてしまうと index の情報が失われて壊れます。
  ソートして使いたい場合は「値と元の index をペアで持つ」か、そもそも Two Pointers ではなくハッシュテーブルの解法に切り替えるか、どちらかを選びます。
</Callout>
