## DFS / BFS だけでは足りない場面

グラフの記事で、「閉路があるかどうか」を DFS で判定する方法を見ました。ただし、それは**グラフが最初から全部揃っている**ことが前提でした。次のような問題ではどうでしょうか。

> 辺が1本ずつ、順番に追加されていきます。追加した瞬間に、両端のノードがすでに何らかの経路でつながっていたら、その辺は「輪っかを作ってしまう余分な1本」です。最初に見つかる、その余分な辺を答えてください。

「辺が追加されるたびに、毎回グラフ全体を DFS で確認する」ことでも解けますが、辺の数だけ DFS を繰り返すことになり、遅くなってしまいます。ここで使うのが Union-Find（またはUnion-Find Forest）という、専用のデータ構造です。

## 「同じグループの代表」という考え方

Union-Find は、それぞれのノードが「自分の属するグループの代表（root）は誰か」という情報だけを持ちます。最初は全員がバラバラなので、**自分自身が自分の代表**です。

辺で2つのノードを繋ぐときは、**それぞれの代表を調べて、片方の代表をもう片方に合わせます。** こうすると、同じグループに属するノードは、たどっていくと必ず同じ代表にたどり着くようになります。

「2つのノードが同じグループか」を調べたいときは、両方の代表を調べて、それが一致するかどうかを見るだけです。**もし新しく繋ごうとしている2つのノードが、すでに同じ代表を持っているなら、その2つはすでにどこかの経路でつながっている**ということです。これが、新しく引こうとしている辺が「余分」だと判定できる理由です。

```python
def find_redundant_connection(edges):
    n = len(edges)
    root = list(range(n + 1))

    def find(x):
        while root[x] != x:
            root[x] = root[root[x]]   # 経路圧縮（簡易版）
            x = root[x]
        return x

    for a, b in edges:
        ra, rb = find(a), find(b)
        if ra == rb:
            return [a, b]              # すでに繋がっていた辺が冗長
        root[ra] = rb
    return []
```

「一直線 + 輪っか」のプリセットを試してみてください。`1-2-3-4` と順番に繋がったあと、最後に `4-1` の辺が来ます。この時点で `4` の代表と `1` の代表はすでに同じグループになっているので、この辺が「余分」だと判定されます。

<Callout type="tip" title="経路圧縮：なぜ ほぼ 定数時間で済むのか">
  `find` 関数の中にある `root[x] = root[root[x]]` という1行が、**経路圧縮**と呼ばれる工夫です。代表を調べるついでに、たどった経路を短くしておくことで、次に同じノードの代表を調べるときの手間を減らします。
  これに加えて「小さいグループを大きいグループにくっつける」というランクによる工夫も組み合わせると、`find` と `union` は理論上、ほぼ定数時間（正確には逆アッカーマン関数という、実用上は定数とみなせるとても小さい値）で終わります。名前だけ知っておけば十分で、証明までは覚える必要はありません。
</Callout>

## なぜ DFS より速いと言えるのか

DFS で閉路を検出する場合、辺が1本追加されるたびに、グラフ全体を歩き直す必要があります。辺の数を `M` とすると、全体では O(M × N) になりかねません。

Union-Find なら、`find` と `union` がそれぞれほぼ定数時間で終わるので、辺を1本追加するたびの処理がほぼ O(1) です。辺が `M` 本あっても、全体でほぼ O(M) で済みます。**「関係性が、あとからどんどん追加されていく」という状況に強い**のが Union-Find の一番の持ち味です。

## この型の計算量

| 操作 | 時間（経路圧縮 + ランクありの場合） | 空間 |
| --- | --- | --- |
| `find`（代表を調べる） | ほぼ O(1) | O(N) |
| `union`（2つのグループを繋げる） | ほぼ O(1) | O(N) |
| 辺が M 本あるときの合計 | ほぼ O(M) | O(N) |

## 「これは Union-Find だ」と気づくためのサイン

- 「グループが**あとから追加される関係**によって、どんどん変わっていく」
- 「2つのものが**同じグループに属するか**」を、何度も繰り返し判定したい
- 「閉路を作ってしまう辺を見つけよ」（`Redundant Connection` のように）
- 「連結成分の**個数**」を求めたいが、グラフが動的に変化する（`Number of Provinces` など）

<Callout type="warn" title="静的なグラフなら、無理に使わなくてよい">
  最初からグラフ全体が揃っていて、一度だけ連結成分を数えればいい場合（`Number of Islands` のような問題）は、DFS や BFS で十分です。Union-Find は「関係性があとから追加されていく」場面や、「同じグループかどうかを何度も問い合わせる」場面で本領を発揮します。どちらの型で解くべきか、問題の性質を見て選んでください。
</Callout>
