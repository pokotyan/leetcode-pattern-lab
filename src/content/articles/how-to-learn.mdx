## この教材が狙っていること

コーディング面接やオンラインのコーディングテストで出る問題は、初見の思いつきで解けるものばかりではない。
**知らなければ絶対に辿り着けない解法**が一定数あり、それを知っているかどうかで結果が変わる。

だからこの教材は、問題を1問ずつ潰すのではなく、**同じ道具で解ける問題群をひとつの「型」としてまとめる**構成にしている。
型が引き出しに入っていれば、初見の問題でも「これは伸ばして縮めるやつだ」「これは条件を満たす限界を探すやつだ」と当たりがつく。

到達目標は次のとおり。

- LeetCode Medium を、**解法の方針が15分以内に立つ**
- 選んだ解法の**時間計算量と空間計算量を、根拠つきで言える**
- なぜ他の解法ではなくそれを選んだのか、**トレードオフを説明できる**

## 各記事の読み方

記事はどれも同じ形をしている。

1. **型の説明** — 何を解決する道具か、どういう問題で顔を出すか
2. **最小形のコード** — 覚えるべき骨格。ここだけは暗記していい
3. **ステップ実行** — コードを1行ずつ進めながら、配列やグラフの状態と変数の変化を同時に見る
4. **ハマりどころ** — 境界条件、重複、オーバーフローなど、実際に落ちる場所
5. **練習問題** — 記事冒頭のリストにある LeetCode の問題を、自力で解く

<Callout type="tip" title="ステップ実行の操作">
  再生ボタンで自動再生、`←` `→` で1手ずつ、`Space` で再生と一時停止。入力欄を書き換えると、
  その場でトレースし直す。**自分で入力を変えて、境界のケースを試すのが一番効く。**
</Callout>

## 学習の順序

上から順に読めば依存関係は満たされるようにしてある。時間が無い場合の優先順位は次のとおり。

| 優先度 | 分野 | 理由 |
| --- | --- | --- |
| 最優先 | 配列・文字列（Two Pointers / Sliding Window） | Medium の出題数が最も多い。習得コストの割に効果が大きい |
| 高 | ハッシュテーブル | 二重ループを O(N) に落とす基本手段。他の型と組み合わせて出る |
| 高 | 二分探索 | 「答えの決めうち」まで含めると応用範囲が広い |
| 高 | グラフ（BFS / DFS） | グリッド問題を含めると Medium での登場率が高い |
| 中 | 木、スタック、ヒープ | 型が少なく、覚えれば確実に取れる |
| 中 | 再帰・バックトラック | 全探索の書き方が固定されている |
| 後回し可 | 動的計画法 | 習得コストが高い。基本形だけ押さえて深追いしない判断もある |

## 1問にかける時間

解けない問題に出会ったとき、**最低20分は自力で考える**。図を書く、極端な入力で考える、
制約から計算量の上限を逆算する。ここを飛ばして解答を読むと、思考の訓練にならない。

そして解答を読んだあとの復習に、**その倍の時間**を使う。

- なぜ自力で解けなかったのか（知らなかったのか、気づけなかったのか）
- どこまでは正しく考えられていたのか
- 次に似た問題を見たとき、何をトリガーにこの解法を思い出すか

3つ目が最も重要になる。型を覚えるとは、**トリガーと解法を結びつけること**を指す。

<Callout type="warn" title="写経は効果が薄い">
  解答のコードを書き写しても、頭の中のイメージをコードに落とす訓練にはならない。
  解説を読んだら一度画面を閉じ、何も見ずに書き直す。
</Callout>

## 計算量の見積もりから制約を逆算する

問題文の制約は、想定解法のヒントになっている。1秒あたりおよそ 10<sup>8</sup> 回の操作が目安。

| 入力サイズ N | 通る計算量の目安 | 典型的な解法 |
| --- | --- | --- |
| N ≤ 10 | O(N!) / O(2<sup>N</sup>) | 全順列、全部分集合の列挙 |
| N ≤ 20 | O(2<sup>N</sup>) | bit 全探索、bit DP |
| N ≤ 500 | O(N<sup>3</sup>) | 三重ループ、Warshall-Floyd |
| N ≤ 5,000 | O(N<sup>2</sup>) | 二重ループ、区間 DP |
| N ≤ 10<sup>5</sup> | O(N log N) | ソート、二分探索、ヒープ |
| N ≤ 10<sup>6</sup> | O(N) | Two Pointers、Sliding Window、累積和 |

`1 <= nums.length <= 10^5` と書いてあれば O(N<sup>2</sup>) は通らない。
この時点で「二重ループ以外の何かが要る」と分かる。**制約を読むのは解法選択の一部**になる。
