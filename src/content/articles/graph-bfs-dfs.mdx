## グラフって、結局なんなのか

「グラフ」と聞くと難しそうに感じるかもしれませんが、正体は単純です。**「モノ」と「モノどうしのつながり」で表せるものは、ぜんぶグラフです。** 「モノ」をノード（頂点）、「つながり」をエッジ（辺）と呼びます。

友達関係も、路線図も、タスクの前後関係も、そして今回扱う「2次元の盤面」も、すべて実はグラフの一種です。この記事では、グラフの中を歩き回る2つの基本操作（BFS と DFS）を身につけ、それをグリッド（盤面）問題と、依存関係を順序に直す問題に応用していきます。

## グラフの持ち方：隣接リスト

グラフをコードで扱うには、「あるノードから、どのノードに行けるか」を表現する必要があります。一番よく使われるのが**隣接リスト**です。`graph[u]` に、`u` から直接行けるノードの一覧を入れておく、というシンプルな形です。

問題では、辺の一覧（`edges = [[a, b], ...]`）として渡されることが多いので、まずこれを隣接リストに変換するところから始めます。

```python
graph = [[] for _ in range(n)]
for a, b in edges:
    graph[a].append(b)
    graph[b].append(a)   # 無向グラフなら両方向
```

<Callout type="warn" title="無向グラフでは、両方向書くのを忘れずに">
  「A と B は友達」のように、向きを持たない関係（無向グラフ）では `graph[b].append(a)` も忘れずに書いてください。片方だけ書くと、「A から B へは行けるが、B から A へは行けない」という間違ったグラフになってしまいます。
  逆に「A を終えないと B に進めない」のように向きがある関係（有向グラフ）なら、片方向だけで正しいです。問題文をよく読んで、向きがあるかどうかを最初に確認する習慣をつけてください。
</Callout>

## BFS と DFS、何が違うのか

グラフを探索する方法として、BFS（幅優先探索）と DFS（深さ優先探索）の2つがあります。どちらも全てのノードを O(N + E) で回れますが、**訪れる順番が違います。**

イメージとしては、BFS は「池に石を投げたときに広がる波紋」のように、始点から近い順に少しずつ範囲を広げていきます。DFS は「迷路を、行き止まりまでとにかく突き進んで、ダメなら1歩戻ってまた進む」ように、1本の道をどこまでも深く進みます。

| | BFS | DFS |
| --- | --- | --- |
| 使うデータ構造 | キュー（`deque`） | 再帰（＝コールスタック） |
| 訪れる順番 | 始点から近い順 | 行けるところまで一気に潜る |
| 得意なこと | **最短距離**を求める、階層ごとに処理する | 連結成分をまとめる、部分木の情報を集約する、閉路を見つける |

<Callout type="tip" title="最短距離を求めたいなら、絶対に BFS を使ってください">
  重みのないグラフで最短距離を DFS で求めようとすると、うまくいきません。DFS はたまたま最初に見つけた経路が最短とは限らないので、結局すべての経路を試すはめになります。
  BFS は近い順に確定していくので、**あるノードに初めて到達した瞬間に、それが最短距離だと保証されます。** この一点だけ覚えておいてください。
</Callout>

## グリッドは、実はグラフです

Medium で一番よく出てくるのが、この形です。二次元配列（グリッド）が与えられたとき、**各マスをノード、隣り合うマスをエッジ**と考えると、これまでのグラフの知識がそのまま使えます。

```python
DIRS = ((-1, 0), (0, 1), (1, 0), (0, -1))   # 上 右 下 左

for dr, dc in DIRS:
    nr, nc = r + dr, c + dc
    if not (0 <= nr < H and 0 <= nc < W):
        continue          # 盤外
    ...
```

グリッド問題では、わざわざ隣接リストを事前に作る必要はありません。**その場で4方向を計算する**のが定石です。

### 連結成分を数える：Number of Islands

> `grid` の各マスは `"1"`（陸）か `"0"`（海）です。上下左右に繋がった陸のかたまり（島）がいくつあるか数えてください。

やることは単純です。**まだ見ていない陸を見つけたら、そこを新しい島としてカウントを1増やし、そこから上下左右に繋がる陸をすべて「訪問済み」にしてしまいます。** こうすれば、同じ島を2回数えることはありません。

```python
def num_islands(grid):
    H, W = len(grid), len(grid[0])
    seen = [[False] * W for _ in range(H)]
    count = 0

    def dfs(r, c):
        if not (0 <= r < H and 0 <= c < W):
            return                  # 盤外
        if grid[r][c] == "0" or seen[r][c]:
            return                  # 海 or 訪問済み
        seen[r][c] = True
        dfs(r - 1, c); dfs(r, c + 1)
        dfs(r + 1, c); dfs(r, c - 1)

    for r in range(H):
        for c in range(W):
            if grid[r][c] == "1" and not seen[r][c]:
                count += 1               # 新しい島を発見
                dfs(r, c)
    return count
```

セルをクリックすると、陸と海を入れ替えられます。島をくっつけたり分けたりしてみて、コールスタックの伸び方がどう変わるかを見てみてください。

<Callout type="warn" title="訪問済みフラグは、いつ立てるか">
  `seen[r][c] = True` は、**再帰に入った直後**に立てます。もし子を呼んだあとに立てようとすると、隣のマスから戻ってきたときにまた同じマスに入り込んでしまい、無限に再帰してしまいます。

  なお、入力の配列を書き換えてよい問題であれば、`seen` という別の配列を用意せず、訪れたマスをそのまま `grid[r][c] = "0"`（海）に変えてしまう手もあります。こうすると余分なメモリを使わずに済みます（再帰スタックの分は除きます）。この工夫は、面接で「メモリを減らせますか」と聞かれたときの定番の答えです。
</Callout>

### 最短距離を求める：グリッド BFS

> `grid` の各マスは `0`（通れる）か `1`（壁）です。左上から右下まで、最短で何マス移動すればいいか求めてください。

ここは BFS の出番です。ポイントは、**キューに入れる時点で、その距離を確定させてしまう**ことです。取り出すときに確定させるのではありません。

```python
from collections import deque

def shortest_path(grid):
    H, W = len(grid), len(grid[0])
    dist = [[-1] * W for _ in range(H)]
    q = deque([(0, 0)])
    dist[0][0] = 0
    while q:
        r, c = q.popleft()                  # 近い順に取り出される
        if (r, c) == (H - 1, W - 1):
            return dist[r][c]
        for dr, dc in ((-1,0),(0,1),(1,0),(0,-1)):
            nr, nc = r + dr, c + dc
            if not (0 <= nr < H and 0 <= nc < W):
                continue
            if grid[nr][nc] == 1 or dist[nr][nc] != -1:
                continue                     # 壁 or 発見済み
            dist[nr][nc] = dist[r][c] + 1
            q.append((nr, nc))
    return -1
```

<GridShortestPathBFS client:visible />

`dist` という1つの配列が、「距離」と「訪問済みフラグ」を兼ねています。`-1` ならまだ見ていないマス、それ以外ならすでに距離が確定したマスです。**一度確定したマスには二度と触らない**というルールが、正しさと速さの両方を支えています。

<Callout type="tip" title="始点が複数あるときも、同じやり方でいけます">
  `Rotting Oranges` や `01 Matrix` のような問題では、**始点が最初から複数**あります。やることは1つだけで、**最初にすべての始点を一度にキューへ入れてから**、あとはまったく同じ BFS のループを回すだけです。すると各マスは「一番近い始点からの距離」として自然に確定していきます。始点ごとに BFS をやり直す必要はありません。
</Callout>

## 依存関係を、実行できる順番に直す

最後に、少し毛色の違う応用を見ます。「A を終えないと B に進めない」というような**依存関係**を、実際に実行できる順番に並べ替える問題です。

> `n` 個の授業があり、`prerequisites` に `[a, b]` という形で「`a` を修了しないと `b` を受けられない」という制約が並んでいます。全部の授業を受けきれるかどうか判定してください。

この問題は「A を終えないと B に進めない」という有向グラフから、**閉路（ぐるっと一周してしまう依存）が無いかどうか**を判定する問題に言い換えられます。

ここでは**入次数**という考え方を使います。入次数とは、あるノードに向かって入ってくる矢印の数のことで、言い換えると「そのノードがまだ待っている、残りの前提条件の数」です。

手順はこうです。まず入次数が 0 のノード（＝前提条件が何もない、今すぐ受けられる授業）をすべてキューに入れます。そこから1つ取り出して確定させるたびに、そこから出ている先のノードの入次数を1つ減らします。減らした結果、入次数が0になったノードがあれば、それも新しくキューに追加します。

```python
from collections import deque

def can_finish(n, prerequisites):
    graph = [[] for _ in range(n)]
    indeg = [0] * n
    for a, b in prerequisites:        # a を終えないと b を取れない
        graph[a].append(b)
        indeg[b] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft()               # 依存先が無くなったものから確定
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1             # u を消したので依存が1つ減る
            if indeg[v] == 0:
                q.append(v)
    return len(order) == n            # 全部並べられたら閉路なし
```

「閉路あり」の例に切り替えてみてください。ぐるっと循環している部分は、どのノードも他のノードが確定するのを待ち続けるので、入次数が永遠に0になりません。結果として、**確定できたノードの数がノード数に届かないまま**キューが空になります。これが「全部消化できた数（`len(order)`）がノード数（`n`）と一致するかどうか」で判定できる理由です。

<Callout type="tip" title="DFS で解くこともできます">
  DFS 派の書き方もあります。各ノードを「未訪問」「探索中」「完了」の3つの状態で管理し、**探索中のノードにもう一度到達してしまったら閉路がある**と判定します。順序は帰りがけに記録して、最後に反転させます。どちらのやり方でも解けるようにしておくと、フォローアップで「別解も書けますか」と聞かれても困りません。
</Callout>

## この型の計算量

| 手法 | 時間 | 空間 |
| --- | --- | --- |
| BFS / DFS（隣接リスト） | O(N + E) | O(N) |
| グリッド BFS / DFS | O(H · W) | O(H · W) |
| トポロジカルソート | O(N + E) | O(N + E) |

グリッドが O(H·W) になるのは、1マスから出ている辺がどんなに多くても高々4本（定数）だからです。

<Callout type="warn" title="再帰の深さにも注意してください">
  グリッドが 1000×1000 マスで、すべて陸だった場合、DFS の再帰は最大で 10<sup>6</sup> 段になります。Python はデフォルトで再帰の上限が1000段なので、このままだとエラーになります。`sys.setrecursionlimit()` で上限を上げるか、スタックを自分で持つ反復版に書き換えるか、そもそも BFS に切り替えるか、いずれかの対応が必要です。面接では、この制約に気づいて一言添えられるだけでも評価が変わります。
</Callout>

## 「これはグラフ探索だ」と気づくためのサイン

- 二次元配列で「隣接するマス」「上下左右」という言葉が出てくる → グリッドのグラフ問題です
- 「**最短**の手数／距離／ステップ数」で、すべての辺の重みが等しい → BFS
- 「いくつのかたまりがあるか」「連結成分」「領域の面積」→ DFS（または Union-Find）
- 「A の前に B」「依存関係」「前提条件」「実行順序」→ トポロジカルソート
- 「閉路があるか」「デッドロックが起きるか」→ トポロジカルソート、または DFS の3状態管理
