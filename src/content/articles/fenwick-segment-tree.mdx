## この記事を読む前に押さえておく型

- **累積和**：この記事は「累積和では困る場面」から始まります。区間の和を引き算1回で取り出せる仕組みと、その代わりに何を諦めているのかを分かっていないと、ここで作る構造が何の問題を解いているのか見えません
- **二分探索**：「区間を半分に割って、必要な側だけ降りる」という構造がセグメント木の骨格です。半分ずつ絞ると深さが log N で済む、という感覚がそのまま効きます
- **二分木（DFS）**：セグメント木は木なので、構築も取得も再帰で書きます。左右の子から値を受け取って自分の値を作る、という帰りがけの集約の形をそのまま使います

## まず、困っている状況を体験してみます

> 配列 `nums` に対して、次の2種類の操作が**交互に、何万回も**飛んできます。
> - `update(i, v)`：`nums[i]` を `v` に書き換える
> - `sumRange(l, r)`：`nums[l]` から `nums[r]` までの合計を返す

ここまでに出てきた道具で、それぞれ考えてみます。

**累積和を使う場合。** `sumRange` は `P[r+1] - P[l]` の引き算1回、つまり O(1) です。ところが `update` が来ると、その位置より後ろの累積和がすべてずれるので、**累積和を作り直す**ことになります。これは O(N) です。

**何もしない場合。** `update` は代入1回で O(1) ですが、`sumRange` は毎回 `r - l + 1` 個を足すので O(N) です。

| やり方 | update | sumRange |
| --- | --- | --- |
| 累積和 | O(N) | O(1) |
| 素直な配列 | O(1) | O(N) |
| **欲しいもの** | **O(log N)** | **O(log N)** |

どちらかが O(1) でも、もう一方が O(N) なら、操作が10万回来た時点で 10<sup>10</sup> になって間に合いません。**両方を log に揃える**ことが必要です。

## 発想を変える：1マスに「ある区間の合計」を持たせる

累積和のマスは「先頭からそこまで」という、とても大きな区間を担当していました。だから1箇所が変わると、後ろの大量のマスが影響を受けました。

逆に、素直な配列のマスは「自分1つ」しか担当していないので、更新は軽い代わりに、合計を出すのに全部を足す必要がありました。

そこで、**中くらいの大きさの区間を担当するマスを用意します。** うまく区間を割り振れば、

- ある1点を含む区間は、log N 個くらいしかない（更新が軽い）
- 任意の区間 `1..r` は、log N 個くらいの担当区間の組み合わせで作れる（取得も軽い）

という状態を作れます。この割り振り方が2種類あり、それが BIT（Fenwick Tree）とセグメント木です。

## BIT：lowbit で担当区間を決める

BIT は、`i` 番目のマスに「`i` の手前 `lowbit(i)` 個の合計」を持たせます。`lowbit(i)` は、`i` を2進法で書いたときの**一番下に立っているビット**です（`i & -i` で取れます）。

| i | 2進法 | lowbit(i) | 担当する区間 |
| --- | --- | --- | --- |
| 1 | 001 | 1 | 1..1 |
| 2 | 010 | 2 | 1..2 |
| 3 | 011 | 1 | 3..3 |
| 4 | 100 | 4 | 1..4 |
| 5 | 101 | 1 | 5..5 |
| 6 | 110 | 2 | 5..6 |
| 7 | 111 | 1 | 7..7 |
| 8 | 1000 | 8 | 1..8 |

この表を見ると、区間の長さが2の冪になっていて、きれいに階層を作っているのが分かります。そして、

- **`1..r` の合計**は、`r` から始めて `i -= lowbit(i)` と飛んでいくと、重なりなく分解できます。たとえば `1..7` は `7..7` と `5..6` と `1..4` の3つです
- **位置 `k` の更新**は、`k` から始めて `i += lowbit(i)` と飛んでいくと、`k` を含むすべての区間を回れます

どちらも、2進法の桁数ぶんしか進まないので O(log N) です。

```python
class BIT:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)     # 1-indexed。tree[i] は i の手前 lowbit(i) 個の合計

    def add(self, i, delta):          # i は 1-indexed
        while i <= self.n:
            self.tree[i] += delta
            i += i & -i               # 自分を覆っている、より大きい区間へ

    def sum(self, i):                 # 1..i の合計
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & -i               # 覆い終えた区間の手前へ飛ぶ
        return s
```

<FenwickTree client:visible />

各マスの下に書いてある `1..4` のような表記が、そのマスの担当区間です。取得の段階で `i` が `6 → 4 → 0` と飛んでいき、`5..6` と `1..4` の2マスだけを足して答えが出る様子を追ってみてください。**6個ぜんぶを足していません。**

<Callout type="warn" title="BIT は 1-indexed で書く、と決め打ちしてください">
  `lowbit(0)` は 0 なので、0 を起点にすると `i += lowbit(i)` が永遠に進まず、無限ループになります。BIT が 1-indexed なのはこのためです。

  実装では、`nums` が 0-indexed なら `add(k + 1, ...)` のように必ず1を足して渡します。ここを混ぜると、原因の分かりにくいずれ方をします。**「外は 0-indexed、BIT の中は 1-indexed、境目で +1 する」**と決めて、その1箇所以外では変換しないのが安全です。

  なお `add` は「その値に書き換える」ではなく「差分を足す」操作です。`nums[k]` を `v` にしたいときは `add(k + 1, v - nums[k])` として、元の配列も忘れずに更新してください。
</Callout>

## BIT の本当の使いどころ：合計ではなく「個数」を数える

ここまでは「区間の和」の話でしたが、BIT が Hard 問題で効いてくるのは、**マスに個数を入れて使う**ときです。

> `nums` の各要素について、**自分より右にあって、自分より小さい値**がいくつあるかを数えてください。

素直に書けば二重ループで O(N²) です。N が 10 万あるので通りません。

ここで、配列を**右から左へ**見ていくことにします。`k` 番目を処理する時点で、すでに処理済みなのは「`k` より右にある要素」です。つまり、知りたいのは「**すでに処理した値の中に、`nums[k]` より小さいものが何個あるか**」です。

これは、「値」を添字にした BIT を用意して、処理した値のところに1を足していけば答えられます。`nums[k]` より小さい値の個数は、`sum(nums[k] - 1)` で取れます。

値がそのまま添字にできないほど大きい場合（負の数や 10<sup>9</sup> など）は、**登場する値だけを小さい番号に振り直します**（座標圧縮）。値の種類は高々 N 個なので、BIT の大きさも N で足ります。

```python
def count_smaller(nums):
    ranks = {v: i + 1 for i, v in enumerate(sorted(set(nums)))}   # 値 -> 1始まりの順位
    tree = [0] * (len(ranks) + 1)

    def add(i):
        while i < len(tree):
            tree[i] += 1
            i += i & -i

    def count(i):                      # 順位 1..i の個数
        s = 0
        while i > 0:
            s += tree[i]
            i -= i & -i
        return s

    ans = [0] * len(nums)
    for k in range(len(nums) - 1, -1, -1):   # 右から左へ見ていく
        r = ranks[nums[k]]
        ans[k] = count(r - 1)          # すでに入れた中で、自分より小さい値の個数
        add(r)                         # 自分を入れる
    return ans
```

<CountOfSmaller client:visible />

`[5, 2, 6, 1]` を右から追ってみます。

1. `1`（順位1）：まだ何も入っていないので 0。`1` を入れる
2. `6`（順位4）：順位3までに入っているのは `1` の1個なので 1。`6` を入れる
3. `2`（順位2）：順位1までに入っているのは `1` の1個なので 1。`2` を入れる
4. `5`（順位3）：順位2までに入っているのは `1` と `2` の2個なので 2。`5` を入れる

答えは `[2, 1, 1, 0]` です。

**「個数を数える器」として BIT を使う**という発想は、そのまま別の Hard 問題に効きます。Reverse Pairs（`nums[i] > 2 × nums[j]` となる組を数える）は、数える条件が変わるだけで骨格は同じです。

<Callout type="tip" title="同じ問題は、マージソートの途中でも数えられます">
  Count of Smaller Numbers After Self や Reverse Pairs は、マージソートの「2つの整列済み列を統合する」場面でも数えられます。左半分の要素が右半分の何個より大きいかは、統合の途中で分かるからです。

  どちらでも O(N log N) ですが、BIT のほうが「何を数えているか」がコードに直接現れるぶん、条件が変わったときに直しやすいという利点があります。面接でどちらを選んでも構いませんが、**選んだ理由を説明できるようにしておいてください。**
</Callout>

## セグメント木：区間を半分に割る木

BIT は「合計」のように、**足し算で後から引き算もできる**演算にしか使えません。区間の**最大値**を持ちたい場合、いったん入れた値を取り消せないので BIT では困ります。

そこで使うのがセグメント木です。考え方はもっと素直で、**区間を半分ずつ割っていき、各節点にその区間の答えを持たせます。**

```
                 [0..7]
          [0..3]        [4..7]
      [0..1] [2..3]  [4..5] [6..7]
      ...
```

- **更新**：葉から根まで登り直す。深さは log N
- **取得**：根から降りていき、探している区間に完全に含まれる節点に当たったらその値を返す。はみ出す節点だけ左右に分かれて降りる。触る節点は高々 4 log N 個

持たせる値を合計にすれば区間和、最大値にすれば区間最大、最小値にすれば区間最小です。**「2つの子の答えから、親の答えを作れる」演算なら何でも載せられる**のがセグメント木の強みです。この「左右の子から受け取って自分の答えを作る」形は、二分木の記事でやった帰りがけの集約そのままです。

| | BIT | セグメント木 |
| --- | --- | --- |
| 実装量 | 10行程度 | 40行程度 |
| 載せられる演算 | 和（逆演算がある操作） | 和・最大・最小・gcd など、結合的な演算全般 |
| 区間更新 | 工夫が要る | 遅延評価で対応できる |
| 定数倍 | 速い | BIT よりは重い |

**まず BIT で足りないかを考え、足りないときにセグメント木に切り替える**、という順番で判断するのが実戦的です。区間の和しか要らないなら、短く書ける BIT のほうが事故が起きません。

## この型の計算量

| 操作 | 累積和 | 素直な配列 | BIT | セグメント木 |
| --- | --- | --- | --- | --- |
| 1点の更新 | O(N) | O(1) | O(log N) | O(log N) |
| 区間の取得 | O(1) | O(N) | O(log N) | O(log N) |
| 構築 | O(N) | O(1) | O(N log N)（1つずつ add）／O(N)（工夫すれば） | O(N) |
| 空間 | O(N) | O(N) | O(N) | O(4N) |

## 「これは区間クエリ構造だ」と気づくためのサイン

- 更新と問い合わせが**交互に**来る（すべての更新が先に終わるなら、差分配列や累積和で足ります）
- 「配列の値が変わる」と明記されている（Mutable）
- 「自分より右（左）にあって、条件を満たす要素の個数」を全要素について求める
- 素直に書くと O(N²) で、N が 10<sup>5</sup> 規模
- 区間の最大・最小を何度も聞かれ、区間が動く（窓が固定幅なら単調キューで足ります）

<Callout type="warn" title="この構造が要らない場面を見分けてください">
  更新と取得を log に揃えるのは強力ですが、実装は重くなります。次の場合は、もっと軽い道具で足ります。

  - **更新がすべて先に来て、取得は最後だけ** → 差分配列
  - **更新が無い（読み取り専用）** → 累積和
  - **区間が固定幅の窓で、右へずれるだけ** → 単調キュー（最大・最小）や Sliding Window（和）
  - **区間ではなく、集合への追加と最小値の取り出し** → ヒープ

  「何が更新されるのか」「取得はいつ来るのか」を問題文から先に切り分けると、選ぶべき道具が決まります。
</Callout>
