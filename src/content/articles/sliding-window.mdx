## まず「連続する部分配列」って何なのか、確認します

`nums = [7, 1, 5, 9, 6, 4]` という配列があったとき、「連続する部分配列」とは `[7]`、`[7, 1]`、`[1, 5, 9]`、`[9, 6, 4]` のように、**配列の中から途切れずに続けて取り出した一部分**のことです。`[7, 5, 6]` のように飛び飛びで選んだものは含まれません。

こういう「連続する部分配列（部分文字列）について、和や長さや種類数を求めよ」という問題は、LeetCode に驚くほどたくさんあります。まずは、これを素直に解こうとすると何が起きるかを見てみます。

```python
for i in range(n):
    for j in range(i, n):
        total = sum(nums[i:j+1])   # O(N^3)
```

始点 `i` と終点 `j` の組み合わせが O(N²) あり、そのたびに `sum()` で区間の中身を毎回1から足し合わせると、さらに O(N) かかります。合計で O(N³) です。N が 10万ある問題ではまったく歯が立ちません。

## 何が無駄だったのか

よく考えると、区間 `[i, j]` の和と、その隣の区間 `[i, j+1]` の和は、ほとんど同じです。違いは `nums[j+1]` が足されるかどうかだけです。それなのに、毎回ゼロから `sum()` で計算し直しているのが無駄の正体でした。

Sliding Window は、**区間を毎回作り直すのをやめて、端っこで足し引きするだけで隣の区間に移る**というテクニックです。左端と右端という2つのポインタで区間（窓＝ウィンドウ）を作り、右端を伸ばしたり左端を縮めたりしながら答えを探します。

区間そのものに意味がある点が、前の記事で見た Two Pointers との違いです。動きの理屈は同じで、ポインタが戻らないぶんだけ全体で O(N) になります。

## 固定長：窓のサイズが決まっている場合

まずは一番シンプルな形から。窓の幅 `k` が問題文であらかじめ決まっているケースです。

> `nums = [7, 1, 5, 9, 6, 4]` から、連続する3個の合計の最大値を求めてください（`k = 3`）。

素朴に考えると、`[7,1,5]`、`[1,5,9]`、`[5,9,6]`、`[9,6,4]` の4つの区間それぞれで `sum()` を呼びたくなります。でも、隣り合う区間を見比べてみてください。

- `[7,1,5]` の和は `13`
- `[1,5,9]` の和は、`13` から `7`（外れた要素）を引いて `9`（新しく入った要素）を足すだけで `13 - 7 + 9 = 15` と求まります

**わざわざ3個を足し直さなくても、1つ引いて1つ足すだけで次の窓の和がわかる**わけです。これをそのままコードにします。

```python
def find_max_average(nums, k):
    cur = sum(nums[:k])        # 最初のウィンドウ
    best = cur
    for i in range(k, len(nums)):
        cur += nums[i]         # 右端を入れる
        cur -= nums[i - k]     # 左端を出す
        best = max(best, cur)
    return best / k
```

<MaxAverageFixedWindow client:visible />

「入れてから出す」という順番になっている点に注目してください。一瞬だけ窓の幅が `k + 1` に膨らみ、そのあとすぐ `k` に戻ります。ステップを1手ずつ進めて、幅が戻る瞬間を確認してみてください。

<Callout type="tip" title="累積和と似ているけれど、使い分けがあります">
  この問題は、事前に累積和を作っておく方法でも解けます。「区間の和を何度も、いろんな位置で問い合わせたい」なら累積和、「端から順番に1つずつずらしていくだけでいい」なら Sliding Window のほうが、余分な配列を作らないぶん空間 O(1) で済みます。累積和については別の記事で扱います。
</Callout>

## 可変長：伸ばして、条件が壊れたら縮める

Medium で本当によく出るのは、実はここからです。窓の幅が問題文で指定されておらず、**「ある条件を満たす、連続する部分配列の最長（または最短）」を求めよ**というパターンです。

骨格はどの問題でも共通しています。

```python
left = 0
for right in range(n):
    # 1. right を1つ伸ばして、状態を更新する
    while 条件が壊れている:      # または「条件を満たしている間」
        # 2. left を進めて、状態を戻す
        left += 1
    # 3. この時点のウィンドウで答えを更新する
```

この骨格の中で、**「最長を求めるのか、最短を求めるのか」によって while の書き方が変わります。** ここが一番混乱しやすいところなので、表で整理しておきます。

| 求めたいもの | while の中身 | 答えを更新するタイミング |
| --- | --- | --- |
| 条件を満たす**最長** | 条件が**壊れている**あいだだけ縮める | while を抜けたあと |
| 条件を満たす**最短** | 条件を**満たしているあいだずっと**縮める | while の中 |

言葉だけだとピンとこないと思うので、それぞれ実際の問題で確かめていきます。

### 最長を求める場合：重複のない最長部分文字列

> 文字列 `s` の中から、同じ文字が2回登場しない、連続する部分文字列の最長の長さを求めてください。

`s = "abcabcbb"` で考えてみます。`a`, `b`, `c` と1文字ずつ窓を伸ばしていくと `abc` までは重複がありません。次に4文字目の `a` を見ると、これはすでに窓の中にある `a`（1文字目）と重複してしまいます。**ここで初めて「条件が壊れた」状態になります。**

こうなったら、窓の左端を、重複していた `a` の1つ右まで一気に動かします。これで窓の中は再び重複のない状態に戻ります。この「見つけた位置の次まで飛ばす」やり方を毎回繰り返せば、どの文字も `left` と `right` それぞれで高々1回ずつしか触られないので、全体で O(N) に収まります。

```python
def length_of_longest_substring(s):
    last = {}          # 文字 -> 最後に見た index
    left = 0
    best = 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1    # 重複をウィンドウの外へ追い出す
        last[ch] = right
        best = max(best, right - left + 1)
    return best
```

<LongestSubstringNoRepeat client:visible />

<Callout type="warn" title="last[ch] >= left の条件を、絶対に落とさないでください">
  入力を `tmmzuxt` に変えてみてください。最後の文字 `t` を見たとき、`last['t']` には最初の `t`（index 0）が記録されたままになっています。でも、その時点で `left` はすでに 0 より右に進んでいて、最初の `t` はもう**窓の外**にあります。
  もし `last[ch] >= left` のチェックを忘れると、「もう窓の外にある」文字のせいで `left` が過去に巻き戻ってしまい、答えが壊れます。辞書ではなく集合（`set`）で管理し、`while ch in seen:` で1文字ずつ外していく書き方もありますが、その場合は巻き戻りは起きない代わりに `left` が1つずつしか進めないので、コードが少し長くなります。
</Callout>

### 最短を求める場合：和が target 以上になる最短の部分配列

さっきとは逆に、最短を求める問題を見てみます。

> `nums` から、合計が `target` 以上になる連続する部分配列のうち、一番短いものの長さを求めてください。

`nums = [2, 3, 1, 2, 4, 3]`、`target = 7` で考えます。右端を伸ばしていき、合計が7以上になったら、**そこから縮められるだけ縮めて、一番短い形を記録します。** 縮めたことで合計が7未満に落ちたら、また右端を伸ばす作業に戻ります。

最長のときは「壊れているあいだ縮める」でしたが、今回は逆で、**「満たしているあいだ縮め続けて、縮めるたびに答えを更新する」**という書き方になります。

```python
def min_sub_array_len(target, nums):
    left = 0
    cur = 0
    best = float("inf")
    for right in range(len(nums)):
        cur += nums[right]          # 右を伸ばす
        while cur >= target:        # 条件を満たす間だけ
            best = min(best, right - left + 1)
            cur -= nums[left]       # 左を縮める
            left += 1
    return 0 if best == float("inf") else best
```

<MinSizeSubarraySum client:visible />

なぜ答えの更新が `while` の**外**ではなく**中**にあるのか、疑問に思うかもしれません。最短を求めたいので、「縮められるギリギリの形」こそが答えの候補です。縮めたあとに更新してしまうと、その時点ではもう条件を満たさなくなっているかもしれないので、縮める**前**（＝まだ条件を満たしている最後のタイミング）に記録する必要があるのです。

## なぜ for の中に while があるのに O(N) なのか

コードを見ると `for` の中に `while` が入っているので、O(N²) に見えるかもしれません。でも実際には O(N) で済みます。理由は単純で、**`left` は一方向に増え続けるだけで、一度も後戻りしない**からです。

`right` が動く回数は最大で N 回、`left` が動く回数もトータルで最大 N 回です。合計しても 2N 回なので、O(N) になります。「ポインタが戻らない」という性質が計算量の根拠になっているのは、前の記事の Two Pointers とまったく同じ理屈です。

<Callout type="warn" title="この型が使えないパターンもあります">
  Sliding Window がうまくいくのは、**窓を伸ばすと条件が単調に厳しくなる（または緩くなる）**場合だけです。

  たとえば、負の数を含む配列で「合計がちょうど k になる部分配列」を探そうとすると、窓を伸ばしても合計は単調に増えたり減ったりしません。この場合は縮めるべきかどうかが判断できないので、Sliding Window は使えません。累積和とハッシュテーブルを組み合わせた別の方法を使います（累積和の記事で扱います）。
</Callout>

## カウントを持つ発展形

最後に、`Longest Repeating Character Replacement` のように、ウィンドウの中の**文字ごとの個数**を数える発展形も紹介します。基本の骨格はまったく同じで、持っている状態が1つの数値からカウンタに変わっただけです。

```python
from collections import Counter

def character_replacement(s, k):
    count = Counter()
    left = 0
    best = 0
    for right, ch in enumerate(s):
        count[ch] += 1
        # 窓の幅 - 最頻文字の個数 = 置換が必要な数
        while (right - left + 1) - max(count.values()) > k:
            count[s[left]] -= 1
            left += 1
        best = max(best, right - left + 1)
    return best
```

「壊れている（置換が k 回を超える）あいだだけ縮める」なので、これは最長パターンに当てはまります。骨格が同じだと気づけるかどうかが、初見の問題を素早く解く鍵になります。

## この型の計算量

| 形 | 時間 | 空間 |
| --- | --- | --- |
| 固定長（和や平均） | O(N) | O(1) |
| 可変長（数値の状態） | O(N) | O(1) |
| 可変長 + カウンタ | O(N · A) | O(A)（A は文字の種類数） |

`max(count.values())` は文字種の数 A に比例した時間がかかるので、厳密には O(N·A) です（最頻値を毎回全部から探すのではなく、差分で持てば O(N) まで削れます）。

## 「これは Sliding Window だ」と気づくためのサイン

- 「**連続する**部分配列」「部分文字列」というキーワード（連続でなければ、この型は使えません）
- 「最長の」「最短の」「ちょうど k 個の」
- 「**高々 k 個まで**」「k 回まで変更してよい」→ そのまま可変長の制約になります
- 制約が N ≤ 10<sup>5</sup> 以上で、二重ループが通らないと分かっている

<Callout type="tip" title="固定長か可変長か、迷ったらここを見る">
  問題文に窓の幅が**数値**で書いてあれば固定長です。「最長」「最短」を求めるなら可変長です。
  「ちょうど k 種類だけを含む部分配列」を求めるタイプは、**「k 種類以下」の個数から「k−1 種類以下」の個数を引く**と考えると、可変長の Sliding Window を2回使うだけで解けます。
</Callout>
