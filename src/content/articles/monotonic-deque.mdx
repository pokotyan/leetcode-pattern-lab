## この記事を読む前に押さえておく型

- **Sliding Window**：この記事でやるのは「窓を動かす」ことそのものではなく、**窓の中の最大値を安く取り出す道具**の話です。窓を右へ伸ばし、条件を満たさなくなったら左を縮める、という骨格が体に入っていることが前提になります
- **単調スタック**：「自分より小さい要素は、これから先どの場面でも最大になれないので捨てる」という捨て方は、単調スタックとまったく同じ考え方です。単調スタックが「右側で最初に自分より大きい要素」を全員分まとめて求められる理由を説明できるなら、この記事は半分読めています

## まず、困っている状況を体験してみます

> 配列 `nums = [1, 3, -1, -3, 5, 3, 6, 7]` の上を、幅 `k = 3` の窓が左から右へ1つずつ動きます。窓の位置ごとに、その中の最大値を並べて返してください。

窓は全部で6個あり、答えは `[3, 3, 5, 5, 6, 7]` です。素直に書くなら、窓ごとに中身を見て最大値を取ります。

```python
for i in range(n - k + 1):
    res.append(max(nums[i:i + k]))     # 窓ごとに k 個ぜんぶ見る
```

窓の数がおよそ N 個、1つの窓で k 個を見るので、全体では O(N × k) です。この問題の制約は N が 10 万、k も最大で 10 万なので、掛け算すると 100 億回。制限時間を大幅に超えます。

何が無駄なのでしょうか。窓が1つ右へずれたとき、中身のうち変わるのは**両端の2つだけ**です。1つが出ていって、1つが入ってくる。残りの `k - 2` 個はまったく同じままなのに、`max()` はそれを毎回すべて見比べています。

<Callout type="tip" title="ヒープではだめなのか">
  「最大値を取り出すならヒープでは」と思うかもしれません。実際、窓に入る値をヒープに入れていけば最大値は取れます。ところが問題は**出ていく値**です。ヒープは先頭（最大）しか取り出せないので、窓から出ていく要素が途中にあると消せません。

  「消したい要素をあとで無視する」（遅延削除）という工夫を入れれば O(N log N) では解けます。ただし、この記事の型を使えば O(N) で済みます。
</Callout>

## 発想を変える：最大になれない要素を、先に捨てる

ここで、次のような状況を考えてみてください。窓の中に `3` が入っていて、その**右隣**に `5` が入ってきました。

この `3` は、これから先の窓で最大値になれるでしょうか。なれません。`3` がまだ窓の中にいるということは、`3` より右にある `5` は**必ず窓の中にいます**（窓は右へしか動かないので、`3` が残っているなら、より右の `5` も残っています）。`3` より大きい `5` が常に一緒にいるなら、`3` が最大として選ばれる場面は永遠に来ません。

つまり、**新しく入ってきた値以下の古い値は、その場で捨ててしまってよい**のです。この「捨てる」を続けると、手元に残るのは次のような列になります。

> 左から右へ、値が必ず減っていく（単調減少の）候補の列。左端が現在の窓の最大値。

この列を両端から出し入れするので、両端キュー（deque）を使います。これが単調キューです。操作は3つだけです。

1. **末尾から捨てる**：新しい値以下の要素を、末尾から取り除く（最大になれないので）
2. **末尾に足す**：新しい値を末尾に入れる
3. **先頭から捨てる**：先頭の要素が窓の外へ出たら取り除く

```python
from collections import deque

def max_sliding_window(nums, k):
    dq = deque()                      # index を入れる。値は単調減少に保つ
    res = []
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()                  # 自分より小さい値は、もう最大になれない
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()              # 窓から出た index を捨てる
        if i >= k - 1:
            res.append(nums[dq[0]])   # 先頭がこの窓の最大値
    return res
```

## なぜ O(N) になるのか、数えて確かめます

一見すると、`while dq and ...` という内側のループがあるので、O(N × k) のままに見えるかもしれません。実際には違います。

注目するのは、**各要素がキューに出入りする回数**です。

- どの要素も、キューに**入るのはちょうど1回**（`dq.append(i)` は i につき1回）
- どの要素も、キューから**出るのは高々1回**（末尾から捨てられるか、先頭から捨てられるか、最後まで残るか）

つまり、内側の `while` が何回まわろうと、**全体を通した総回数は N 回を超えられません。** ある回で `while` が5回まわったなら、それは過去に入れた5個を消費したということで、その5個はもう二度と消えません。ならして考えれば、1要素あたりの仕事は定数回です。全体で O(N) になります。

この「1つの要素が入るのも出るのも1回だけなので、内側ループがあっても合計は O(N)」という数え方は、単調スタックのときとまったく同じです。

`[1, 3, -1, -3, 5, 3, 6, 7]`、`k = 3` を手で追ってみます（キューには index を入れますが、読みやすいように値で書きます）。

| i | 値 | 末尾から捨てる | キュー（値） | 窓の最大 |
| --- | --- | --- | --- | --- |
| 0 | 1 | なし | [1] | まだ窓が揃わない |
| 1 | 3 | 1 を捨てる | [3] | まだ揃わない |
| 2 | -1 | なし（3 > -1） | [3, -1] | **3** |
| 3 | -3 | なし | [3, -1, -3] | **3** |
| 4 | 5 | -3, -1, 3 を全部捨てる | [5] | **5** |
| 5 | 3 | なし | [5, 3] | **5** |
| 6 | 6 | 3, 5 を捨てる | [6] | **6** |
| 7 | 7 | 6 を捨てる | [7] | **7** |

答えは `[3, 3, 5, 5, 6, 7]` です。i = 4 の行で3個まとめて捨てていますが、その3個は i = 1〜3 で1回ずつ入れたものなので、入れた回数と捨てた回数はきちんと釣り合っています。

<Callout type="warn" title="値ではなく index を入れる。等号を付ける位置にも注意">
  - **キューに入れるのは index です。** 値を入れてしまうと「先頭の要素が窓から出たかどうか」を判定できません。同じ値が複数あると、どちらが古いのか区別がつかなくなります
  - 末尾を捨てる条件は `nums[dq[-1]] <= x` です。**等号を含めて**構いません。同じ値なら新しいほうを残したほうが、窓から出ていくのが遅くなるぶん得だからです。`<` にしても答えは合いますが、キューが無駄に長くなります
  - 先頭を捨てる条件 `dq[0] <= i - k` は、「窓の左端は `i - k + 1` なので、それより手前なら外」という意味です。ここは `<` と `<=` を間違えやすいので、`i - k + 1` を紙に書いてから判定式を作ってください
  - 答えを記録し始めるのは `i >= k - 1` になってからです。窓の幅が k に満たないうちは、窓自体が存在していません
</Callout>

## 最小値も同時に欲しいときは、2本持つ

単調キューは、Sliding Window の内側に道具として差し込めます。窓の伸縮そのものは今まで通りで、「窓の中の最大・最小を O(1) で引ける」という部分だけが強化される、という理解が正確です。

> 配列から、**最大値と最小値の差が `limit` 以下**になる連続部分配列のうち、最長のものの長さを求めてください。

窓を右に伸ばし、条件（最大 − 最小 ≤ limit）が崩れたら左を縮める。この骨格は Sliding Window そのままです。唯一の問題は、「いまの窓の最大と最小」を毎回どう知るかでした。ここに単調キューを2本置きます。最大用は減少順、最小用は増加順です。

```python
from collections import deque

def longest_subarray(nums, limit):
    max_dq, min_dq = deque(), deque()   # max_dq は減少順、min_dq は増加順
    left = 0
    best = 0
    for right, x in enumerate(nums):
        while max_dq and max_dq[-1] < x:
            max_dq.pop()
        max_dq.append(x)
        while min_dq and min_dq[-1] > x:
            min_dq.pop()
        min_dq.append(x)
        while max_dq[0] - min_dq[0] > limit:
            if max_dq[0] == nums[left]:
                max_dq.popleft()
            if min_dq[0] == nums[left]:
                min_dq.popleft()
            left += 1                   # 条件を満たすまで左を縮める
        best = max(best, right - left + 1)
    return best
```

ここでは値をそのまま入れています。窓の左端が動くとき、`nums[left]` と各キューの先頭を見比べて、**一致したときだけ**取り除いているからです。先頭に無い値は、すでに「最大（最小）になれない」として捨てられているので、何もしなくて構いません。

「同じ値が続く」という入力を選んで、左端を縮める場面を見てみてください。`4, 2, 2, 2, ...` のように同じ値が並ぶと、キューの中にも同じ値が複数残ります。このとき `popleft()` は1つだけ取り除くので、残りの同じ値がきちんと窓の中の要素に対応し続けます。

## 累積和と組み合わせる：負の数がある場合の最短部分配列

単調キューが最も効くのは、Sliding Window が**そのままでは使えない**場面です。

> 和が `k` 以上になる連続部分配列のうち、最短のものの長さを求めてください。**配列には負の数が含まれます。**

負の数が無ければ、窓を伸ばすと和が必ず増えるので、Sliding Window がそのまま使えます。負の数があると「伸ばしたのに和が減る」ことが起きるため、窓の伸縮では正しく判定できません。

そこで累積和 `P` を作り、問題を言い換えます。「和が k 以上の区間 `[i, j)`」は、「`P[j] - P[i] >= k` を満たす組」です。各 `j` について、**`P[i] <= P[j] - k` を満たす、できるだけ右にある `i`** を探したいわけです。

ここで、候補の `i` について2つのことが言えます。

- `P[i] >= P[j]` である古い `i` は、これから先いつまでも使い道がありません。より右にあって値も小さい `j` のほうが常に優れているからです → **末尾から捨ててよい**
- 一度 `P[i] <= P[j] - k` を満たして答えに使った `i` は、これ以降は「より短い区間」を作れません → **先頭から捨ててよい**

末尾から捨て、先頭から捨てる。単調キューそのものです。累積和を増加順に保った単調キューを1本持つだけで、この Hard 問題が O(N) で解けます。

<Callout type="tip" title="動的計画法の遷移を速くする道具としても出てきます">
  `dp[i] = nums[i] + max(dp[i-k] ... dp[i-1])` のように、**直前 k 個の最大値**を使う遷移式は珍しくありません（Jump Game VI、Constrained Subsequence Sum）。この `max` を素直に書くと O(N × k) ですが、中身は「幅 k の窓の最大値」そのものなので、単調キューで O(N) に落ちます。

  DP の記事で出てくる遷移式を見て「この max は窓の最大値だ」と気づけると、Hard の一群がまとめて解けるようになります。
</Callout>

## この型の計算量

| やり方 | 時間 | 空間 | 内訳 |
| --- | --- | --- | --- |
| 窓ごとに max を取る | O(N × k) | O(1) | 窓の数 × 窓の幅 |
| ヒープ + 遅延削除 | O(N log N) | O(N) | 取り出した要素が窓の外かどうかを都度確認する |
| 単調キュー | **O(N)** | O(k) | 各要素の出入りが1回ずつ。キューの長さは高々 k |

## 「これは単調キューだ」と気づくためのサイン

- 「**幅 k の窓**」＋「その中の**最大値／最小値**」
- 窓の中の「最大 − 最小」に条件が付いている
- DP の遷移式に「直前 k 個の max（または min）」が出てくる
- 累積和を取ったあと、「ある値以下で、できるだけ右にある位置」を探したくなる
- 素直に書くと O(N × k) になり、N も k も 10<sup>5</sup> 規模である

<Callout type="warn" title="単調スタックとの使い分け">
  どちらも「もう使えない要素を捨てて、単調な並びを保つ」型ですが、出入り口が違います。

  - **単調スタック**：片側（末尾）からしか出し入れしません。「右側で最初に自分より大きい要素」のように、**位置関係**を全員分まとめて求めるときに使います
  - **単調キュー**：末尾から捨てるだけでなく、**先頭からも捨てます**。先頭から捨てる理由は「窓の外に出たから」です。つまり、**範囲の制限（窓）がある問題**では単調キューになります

  問題文に「幅 k」や「区間の長さの上限」といった制限があるかどうかが、そのまま見分け方になります。
</Callout>
