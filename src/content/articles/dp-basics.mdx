## DP は、実は難しいことをしていません

「動的計画法（DP）」と聞くと身構えてしまうかもしれませんが、正体はとてもシンプルです。**一度計算した答えを覚えておいて、あとで再利用する**というだけのことです。

まずは、DP を使わない再帰がどれくらい無駄をしているかを見てみます。フィボナッチ数（`fib(n) = fib(n-1) + fib(n-2)`）を素直に再帰で計算するとします。

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)` を計算する過程で、`fib(2)` が何度も呼ばれることに気づくはずです。同じ入力に対して、まったく同じ計算を何度も繰り返しているのです。この無駄を消すために、**一度計算した値を配列（または辞書）にメモしておく**のが DP です。

## 状態と遷移式

DP で一番大事なのは、「**何を状態として、その状態に対する答えをどう定義するか**」を決めることです。フィボナッチなら、状態は「何番目か（`n`）」で、答えは「その番目のフィボナッチ数」です。

そして、状態と状態のあいだの関係を表す式を**遷移式**と呼びます。フィボナッチなら `dp(n) = dp(n-1) + dp(n-2)` がそれです。この2つ（状態の定義と遷移式）さえ決まれば、あとはそのままコードに落とすだけです。

## "i番目"ではなく"i番目まで"を状態にする

DP に慣れないうちは、「配列の `i` 番目の値」を状態にする問題は素直に思いつけても、**「`i` 番目"まで"見たときの答え」**を状態にする問題には気づきにくいものです。ここが最初の壁になるので、実際の問題でじっくり確認します。

> 一列に並んだ家から、金品を盗みます。ただし**隣り合う家を連続して盗むと警報が鳴ってしまいます。** 盗める金額の合計を最大にしてください。

まずは、鉄則どおり小さい例から考えます。

- 家が1軒しかない場合：選択肢はそれを盗むことだけです
- 家が2軒の場合：隣同士は盗めないので、どちらか片方だけ。大きいほうを選びます
- 家が3軒の場合：3軒目をどうするか、で考えてみましょう。**3軒目を盗むなら、2軒目は諦めるしかありません**（隣だから）。なので「1軒目までの最大額」＋「3軒目の金額」が候補になります。**3軒目を盗まないなら**、答えは「2軒目までの最大額」とまったく同じです。この2つの大きいほうが、3軒目までの答えです

ここまで来ると、`dp(i)` を「`i` 番目の家**まで**見たときに盗める最大額」と定義すれば、遷移式が立てられることに気づきます。

> `dp(i) = max( dp(i-1)（i番目を盗まない）, dp(i-2) + nums[i]（i番目を盗む） )`

```python
def rob(nums):
    n = len(nums)
    dp = [0] * n          # dp[i]: i番目の家まで見たときの、盗める最大額
    for i in range(n):
        if i == 0:
            dp[i] = nums[0]
        elif i == 1:
            dp[i] = max(nums[0], nums[1])
        else:
            # i番目を "盗まない" なら dp[i-1] のまま
            # i番目を "盗む" なら、i-1番目は盗めないので dp[i-2] + nums[i]
            dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
    return dp[-1] if n else 0
```

`dp` 配列が左から右へ、1マスずつ確定していく様子を見てください。**それぞれのマスは、直前の2マスの答えだけを見て決まっています。** 3軒目より前の、もっと古い情報は一切必要ありません。これが「一度計算した答えを再利用する」ということの、具体的な意味です。

<Callout type="tip" title="なぜ dp(i-1) と dp(i-2) だけで足りるのか">
  「i番目を盗む」を選んだ場合、隣のi-1番目は絶対に盗めません。だから「i-2番目までの最大額」に、i番目の金額をそのまま足せば安全です。**もっと前の家（i-3番目より前）まで見返す必要は無い**ことに注目してください。i-2番目までの答えである `dp(i-2)` そのものが、「i-2番目までで最も良い選び方」をすでに内包しているからです。
</Callout>

## DP の書き方には2つの流儀があります

`House Robber` の書き方は、**「未知の答えを求めるために、既知の答えをもらいにいく」**という形でした。これを「貰う DP」と呼びます（対照的に、既知の値が決まった時点で、それを使う未来の値に先回りして足し込んでいく「配る DP」という書き方もあります）。フィボナッチのような単純な問題ではどちらでも書けますが、多くの人にとっては「貰う DP」のほうが直感的に書きやすいです。まずはこちらに慣れることをお勧めします。

## この型の計算量

| 用途 | 時間 | 空間 |
| --- | --- | --- |
| 一次元 DP（House Robber など） | O(N) | O(N) |
| 空間を圧縮した場合 | O(N) | O(1) |

`dp(i)` の計算に直前の2つしか使わないなら、配列全体を持たなくても、**変数2つ（`prev`、`pprev`）だけで**同じ計算ができます。これは面接のフォローアップで「メモリを減らせますか」と聞かれたときの定番の答えです。実際に書いてみると、次のようになります。

```python
def rob(nums):
    prev, pprev = 0, 0
    for num in nums:
        prev, pprev = max(prev, pprev + num), prev
    return prev
```

## 「これは一次元 DP だ」と気づくためのサイン

- 「**i番目まで**見たときの、最大／最小／通り数」を求めたい
- 「隣り合う要素は選べない」「直前の選択に制約がある」（House Robber のような制約）
- 答えを求めるのに、**同じ部分問題を何度も計算する無駄**がありそう（素朴な再帰で確認できます）
- Two Pointers や Sliding Window のような「一直線に進む」構造はあるが、**単純な貪欲（毎回その場で最善を選ぶ）では正しい答えにならない**

<Callout type="warn" title="貪欲法とDPを混同しない">
  「毎回、今見えている中で一番得なものを選ぶ」という貪欲な戦略は、House Robber ではうまくいきません。たとえば `[2, 1, 1, 2]` で「大きいほうを毎回選ぶ」と、最初の `2` を選んだ時点で隣の `1` は選べず、最後の `2` との組み合わせを見逃す可能性があります。**「今の選択が、未来の選択肢を狭める」**関係にある問題では、貪欲ではなく DP で全部の分岐を正しく比較する必要があります。
</Callout>
