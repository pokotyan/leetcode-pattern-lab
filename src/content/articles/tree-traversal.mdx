## 二分木は、グラフの中でも特に扱いやすい形です

前の記事で見たグラフの探索は、そのまま二分木にも使えます。二分木は「1つのノードが、子を最大2つまでしか持たない」という特別な形のグラフだからです。各ノードは `val`（値）、`left`（左の子）、`right`（右の子）の3つを持ちます。

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```

木の問題を解くときにまず整理しておきたいのが、**再帰関数が「何を受け取り、何を返すか」を先に決める**という考え方です。これさえ決まれば、あとは「自分の子に、同じ関数を呼んで任せる」だけで済みます。

## 「行きがけ」と「帰りがけ」

再帰でノードを訪れるとき、実は2つのタイミングがあります。**行きがけ**（そのノードに初めて到達した瞬間）と、**帰りがけ**（そのノードの子の処理がすべて終わって、呼び出し元に戻る瞬間）です。

- 行きがけの情報：根からそのノードまでの経路上で分かること（今までの合計、今までの最大値、など）
- 帰りがけの情報：そのノードを根とする**部分木全体**を見終わって初めて分かること（部分木の深さ、部分木に含まれる値の合計、など）

「木の深さを求めよ」のような問題は、**部分木全体を見ないと答えが出ない**ので、帰りがけの情報を使います。ここが二分木の再帰で一番大事な考え方なので、実際の問題でじっくり確認していきます。

## 部分木の情報を、帰りがけに集約する：木の深さ

> 二分木の根が与えられます。木の深さ（根から一番遠い葉までの距離）を求めてください。

まず、**再帰関数がすでにあると仮定してみます。** `max_depth(node)` を呼べば、`node` を根とする部分木の深さが返ってくる、というふうにです。すると、あるノードの深さは何で決まるでしょうか。

「左の子を根とする部分木の深さ」と「右の子を根とする部分木の深さ」の、**大きいほうに 1 を足したもの**です。これはまさに `max_depth(node.left)` と `max_depth(node.right)` を呼び出して、その結果を使えばいいということです。子の答えが先に決まらないと自分の答えが決まらない、というのが「帰りがけ」の意味です。

```python
def max_depth(root):
    if not root:
        return 0
    left = max_depth(root.left)    # 左の部分木の深さ
    right = max_depth(root.right)  # 右の部分木の深さ
    return max(left, right) + 1    # 自分を含めた深さを返す
```

<MaxDepthBinaryTree client:visible />

ステップを進めると、**まず左側を一番深いところまで潜ってから、戻りながら数字を確定させていく**動きが見えます。ノードの右上に出るバッジが、その時点で確定した部分木の深さです。値が確定するのは、必ず両方の子を見終わったあと（帰りがけ）だという点を確認してください。

<Callout type="tip" title="この型で、部分木に関するほとんどの問題が解けます">
  「木の直径を求めよ」（各ノードで、左の深さ＋右の深さを答えの候補にする）、「バランスの取れた木かどうか判定せよ」（左右の深さの差が1以下かを、深さの計算とあわせて確認する）なども、まったく同じ「子の答えをもらって、自分の答えを作る」という骨格です。`return` する値と、答えの記録場所（`return` するのか、外側の変数に書き込むのか）が変わるだけです。
</Callout>

## 階層ごとに処理する：BFS

帰りがけの DFS が「部分木の情報を集める」のに強いのに対して、**「階層ごとにまとめて処理したい」**場合は BFS が向いています。グラフの記事で見た BFS を、そのまま二分木に当てはめます。

> 二分木の根が与えられます。ノードの値を、階層ごとに1つの配列としてまとめた、二次元配列を返してください。

BFS の基本形はグラフの記事と同じくキューを使いますが、ここでは一工夫必要です。ただキューから1個ずつ取り出すだけでは、「どこまでが同じ階層か」の境目がわかりません。そこで、**次の階層に進む前に、今のキューの中に何個あるかを先に数えておきます。**

```python
from collections import deque

def level_order(root):
    if not root:
        return []
    result = []
    queue = deque([root])
    while queue:
        level_size = len(queue)      # 「今の階層」に何個あるか、先に数えておく
        level = []
        for _ in range(level_size):
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)          # 1階層ぶんをまとめて追加
    return result
```

<LevelOrderTraversal client:visible />

`level_size` を数えたあとに、新しく追加された子ノードたちがキューに紛れ込んでも、`for _ in range(level_size)` は最初に数えた回数しか回らないので、**今の階層だけを正しく処理できます。** この「サイズを先に数えておく」というテクニックは、木以外のグラフの BFS でも「階層ごとの距離」を扱うときに使えます。

<Callout type="warn" title="Right Side View との関係">
  `Binary Tree Right Side View`（右から見たときに見える値の列を求める）は、この BFS の型で「各階層の**最後**の要素だけを記録する」だけで解けます。DFS で「右の子を先に訪れて、その階層を初めて訪れたときの値を記録する」という解き方もありますが、BFS のほうが発想はシンプルです。
</Callout>

## この型の計算量

| 手法 | 時間 | 空間 |
| --- | --- | --- |
| 帰りがけ DFS（深さ、直径など） | O(N) | O(H)（H は木の高さ。再帰スタック分） |
| BFS（階層ごとの処理） | O(N) | O(N)（最大幅の階層をキューに持つ） |

木が偏っていて一直線に近い形（連結リストのような形）だと、DFS の再帰スタックは最悪 O(N) まで伸びます。逆に完全に balanced な木なら O(log N) です。面接では「木の形によって空間計算量が変わる」ことに触れられると評価が上がります。

## 「これは帰りがけ DFS だ／BFS だ」と気づくためのサイン

- 「**部分木**の情報」「木の深さ」「直径」「部分木の和」→ 帰りがけ DFS
- 「**階層ごとに**」「レベルごとに」「上から k 段目」「右から見た景色」→ BFS
- 「根からある1点までの経路」の情報が必要 → 行きがけ（引数で下に渡す）
- 2つのノードの**共通の祖先**を求めたい → 帰りがけ DFS（両方が見つかった地点が答え）
