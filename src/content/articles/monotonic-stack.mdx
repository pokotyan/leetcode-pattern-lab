## 「次に大きい要素」を、全員分求めたいとき

こんな問題を考えます。

> `temperatures = [73, 74, 75, 71, 69, 72, 76, 73]` という気温の記録があります。それぞれの日について、「何日後に、今日より暖かい日が来るか」を求めてください。今日より暖かい日が二度と来ない場合は `0` とします。

たとえば0日目（気温73）の答えは `1`。翌日の気温が74で、今日より高いからです。3日目（気温71）の答えは `2`。4日目は69でまだ低いですが、5日目が72で71より高いからです。

これを素直に解くなら、それぞれの日について、**自分より右側を1つずつ見ていって、最初に自分より気温が高い日を探す**ことになります。

```python
for i in range(n):
    for j in range(i + 1, n):
        if temps[j] > temps[i]:
            ans[i] = j - i
            break
```

これは O(N²) です。N が大きい問題では通りません。

## 無駄はどこにあるのか

ここでちょっと考えてみてください。3日目（気温71）を調べるときも、4日目（気温69）を調べるときも、**両方とも「この先で初めて気温が上がる日」を探している**という点では同じ作業です。しかも4日目のほうが調べる範囲は狭いだけで、やっていることの本質は同じです。

さらに言うと、5日目（気温72）が見つかった瞬間、実は3日目にとっても4日目にとっても「答えが確定する」ことがあります。**1回の発見が、複数の「まだ答えが決まっていない日」に同時に効く**わけです。この「複数の未解決の問題が、1つの新しい情報で一気に解決する」という構造を活かすのが、単調スタックです。

## スタックに「まだ答えが決まらない人」を並べておく

発想を変えます。左から日付を1つずつ見ていきながら、**「まだ答えが決まっていない日」を、気温が低い順にスタックに積んでおきます。** そして新しい日を見るたびに、その日の気温が「スタックの一番上で待っている日」より高ければ、待っていた日の答えが確定するので、スタックから降ろします。これを、スタックの一番上がもう自分より気温が高くなる（＝もう答えが決まらない）まで繰り返します。

`temperatures = [73, 74, 75, 71, 69, 72, 76, 73]` の一部を手で追ってみます。

1. 0日目（73）：スタックは空なので、そのまま積む。`stack = [0]`
2. 1日目（74）：スタックの一番上は0日目（73）。74 > 73 なので、0日目の答えが確定します（`1 - 0 = 1` 日後）。0日目を降ろし、代わりに1日目を積む。`stack = [1]`
3. 2日目（75）：同様に1日目（74）の答えが確定（`2 - 1 = 1`）。`stack = [2]`
4. 3日目（71）：スタックの一番上は2日目（75）。71 < 75 なので、まだ答えは決まりません。そのままスタックに積む。`stack = [2, 3]`
5. 4日目（69）：スタックの一番上は3日目（71）。69 < 71 なので、これもまだ決まりません。積む。`stack = [2, 3, 4]`
6. 5日目（72）：スタックの一番上は4日目（69）。72 > 69 なので、4日目の答えが確定（`5 - 4 = 1`）。降ろすと、次のスタックの一番上は3日目（71）。72 > 71 なので、**続けて**3日目の答えも確定します（`5 - 3 = 2`）。降ろすと、次は2日目（75）。72 < 75 なので、ここでストップ。`stack = [2, 5]`

「1つ降ろして終わり」ではなく、**降ろしたあとも、まだスタックの上と比較を続ける**というのがポイントです。この「降ろせるだけ降ろす」動きのおかげで、5日目という1つの情報だけで、4日目と3日目という2人分の答えが一気に確定しました。

```python
def daily_temperatures(temps):
    n = len(temps)
    ans = [0] * n
    stack = []                 # index を積む。下から上へ気温が減る順に保つ
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()     # 今日より寒かった日が見つかった
            ans[j] = i - j      # その日から今日までの日数
        stack.append(i)
    return ans
```

<Callout type="tip" title="なぜ「単調」スタックと呼ぶのか">
  スタックの中身を、下から上へ順番に眺めてみてください。**気温は必ず、下から上に向かって減っていく順番になっています。** これは「まだ答えが決まっていない日」だけが残るように保たれているからです。この「積まれている値が常にある順番を保っている」という性質から、単調（モノトニック）スタックと呼ばれます。
</Callout>

## なぜ二重ループなのに O(N) なのか

コードを見ると、`for` の中に `while` があるので O(N²) に見えるかもしれません。でも、ここでもスタック記事で見た「push と pop はそれぞれ高々1回ずつ」という考え方が効いてきます。

**どの日も、スタックに積まれるのは1回だけです。** そして、一度降ろされたら二度と積まれません。つまり `push` の合計回数は N 回、`pop` の合計回数も最大で N 回です。合計しても O(N) にしかなりません。「1回の `while` は何回も回るように見えて、実は全体を通した回数には上限がある」という、Sliding Window の記事でも見た考え方がここでも成り立っています。

## 「これは単調スタックだ」と気づくためのサイン

- 「**次に自分より大きい（小さい）要素**」を、全要素について求めたい
- 「何日後に」「どのくらい先で」のように、**距離や差分**を答える形になっている
- 素直に書くと二重ループになりそうだが、**1つの発見が複数の未解決の答えを一気に解決する**構造がある

<Callout type="warn" title="単調スタックは値ではなく index を積む">
  スタックに積むのは温度そのものではなく、**index** です。こうしておくことで、答えを計算するときに「今の index － 積んであった index」で距離が求まります。値だけを積んでしまうと、距離を求める手段が無くなってしまうので注意してください。
</Callout>
