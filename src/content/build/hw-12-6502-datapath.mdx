## なぜ 2 つめの CPU を作るのか

Hack は教材として設計された CPU です。命令が 2 種類しかなく、すべての命令が 1 サイクルで終わり、アドレス計算が単純です。**理解しやすいように、現実の面倒を取り除いてあります。**

6502 は 1975 年に実際に売られ、Apple II、コモドール、そして**ファミコン**に載った CPU です。ここには現実の面倒がすべてあります。

| | Hack | 6502 |
| --- | --- | --- |
| データ幅 | 16 ビット | **8 ビット** |
| アドレス幅 | 15 ビット | **16 ビット** |
| レジスタ | A, D | A, X, Y, S, P |
| 命令長 | 固定 2 バイト相当 | **1〜3 バイト可変** |
| 1 命令のサイクル数 | 常に 1 | **2〜7** |
| アドレッシングモード | 実質 2 種類 | **13 種類** |
| フラグ | zr, ng（外に出るだけ） | **7 ビットのレジスタとして保持** |

2 つを並べると、**何が本質で何が便宜だったのか**が分かります。そして Track 3 でこの CPU をソフトウェアで再現するとき、回路として理解しているかどうかが効いてきます。

## レジスタ構成

```
  A   累算器（Accumulator）       8 ビット   計算の結果が入る唯一の場所
  X   インデックスレジスタ          8 ビット   アドレス計算の添字、ループカウンタ
  Y   インデックスレジスタ          8 ビット   同上
  S   スタックポインタ             8 ビット   $0100 + S がスタックの位置
  P   ステータスレジスタ           7 ビット   フラグの集まり
  PC  プログラムカウンタ           16 ビット  唯一の 16 ビットレジスタ
```

**計算結果が入るのは A だけ**です。X と Y で足し算はできません（インクリメント・デクリメントはできます）。Hack で D が唯一の計算用レジスタだったのと同じ制約ですが、6502 はさらに厳しい。

<Callout type="note" title="なぜレジスタが少ないのか">
  1975 年当時、トランジスタは高価でした。6502 は約 3500 トランジスタで作られ、
  競合の半分以下の価格で売られました。**レジスタを削ったぶんを価格に回した**設計です。

  代わりに、**ゼロページ**（アドレス $0000〜$00FF）へのアクセスが 1 バイト短く 1 サイクル速い、
  という仕組みが用意されました。「メモリの先頭 256 バイトを、追加のレジスタとして使う」
  という発想です。
</Callout>

## ステータスレジスタ

Hack の ALU はフラグを出力するだけで、保持しませんでした。6502 は**レジスタとして持ちます**。

```
  7   6   5   4   3   2   1   0
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ N │ V │ - │ B │ D │ I │ Z │ C │
└───┴───┴───┴───┴───┴───┴───┴───┘
```

| ビット | 名前 | 意味 |
| --- | --- | --- |
| **N** | Negative | 結果の bit7 が 1（負） |
| **V** | Overflow | 符号付きの桁あふれ |
| B | Break | BRK 命令による割り込みか |
| D | Decimal | 10 進補正モード（NES では無効） |
| I | Interrupt disable | IRQ を禁止する |
| **Z** | Zero | 結果が 0 |
| **C** | Carry | 符号なしの桁あふれ / 借り |

第 1 章で見た C と V の違いが、ここで実物として出てきます。**同じ足し算の結果を、符号なしとして見るか符号付きとして見るかで、あふれの判定が変わる**ので、両方を別のフラグとして持ちます。

```ts
// src/nes/flags.ts
export type Flags = {
  n: 0 | 1; v: 0 | 1; d: 0 | 1; i: 0 | 1; z: 0 | 1; c: 0 | 1
}

/** 加算のフラグ。C と V の求め方が違うことを確かめる */
export const addFlags = (a: number, b: number, carryIn: 0 | 1) => {
  const sum = a + b + carryIn                       // 9 ビットぶん
  const result = sum & 0xff
  return {
    result,
    c: (sum > 0xff ? 1 : 0) as 0 | 1,               // 符号なしのあふれ
    z: (result === 0 ? 1 : 0) as 0 | 1,
    n: ((result >> 7) & 1) as 0 | 1,
    // 符号付きのあふれ：入力の符号が同じなのに、出力の符号が違う
    v: ((~(a ^ b) & (a ^ result) & 0x80) !== 0 ? 1 : 0) as 0 | 1,
  }
}
```

<Callout type="tip" title="V フラグの式">
  `~(a ^ b)` は「a と b の符号が同じ」、`(a ^ result)` は「a と結果の符号が違う」。
  両方が成り立つときだけ符号付きオーバーフローです。

  正 + 正 = 負、または 負 + 負 = 正 のときにだけ立ちます。
  正 + 負 では絶対に起きないので、この式で除外されます。
</Callout>

## データパス：バスという考え方

Hack の CPU では、各部品を直接配線しました。6502 は**内部バス**を使います。

```
        ┌─────────────────── 内部データバス（8 ビット） ───────────────────┐
        │        │        │        │         │          │                │
      ┌─┴─┐    ┌─┴─┐    ┌─┴─┐    ┌─┴─┐     ┌─┴──┐    ┌──┴───┐        ┌───┴────┐
      │ A │    │ X │    │ Y │    │ S │     │ P  │    │ ALU  │        │ メモリ   │
      └───┘    └───┘    └───┘    └───┘     └────┘    └──────┘        │ 入出力   │
                                                                     └────────┘
```

**各レジスタは、バスに出す（読み）か、バスから取り込む（書き）かを制御されます。** ある瞬間にバスへ出せるのは 1 つだけです。

この方式の利点は、**配線が劇的に減る**ことです。n 個のレジスタ同士を直接つなぐと n² 本の配線が要りますが、バス経由なら n 本で済みます。

代償は、**1 サイクルに 1 つの転送しかできない**ことです。だから 6502 の命令は複数サイクルかかります。

<Callout type="warn" title="バスは共有資源">
  2 つのレジスタが同時にバスへ出力すると、電気的に衝突します（実物では発熱や故障の原因）。
  「同時に 1 つだけ」を保証するのは、制御部の責任です。

  第 6 章で見た「複数のスレッドが同じメモリに書き込むと壊れる」と、構造的には同じ問題です。
  排他が必要な共有資源、という点で同じです。
</Callout>

## アドレス計算の経路

Hack では、ジャンプ先もメモリのアドレスも常に A レジスタでした。6502 は、命令ごとに違う方法でアドレスを組み立てます。

代表的な経路を並べます。

| モード | 書き方 | アドレスの作り方 |
| --- | --- | --- |
| Immediate | `LDA #$42` | アドレスではない。命令の次のバイトが値そのもの |
| Zero Page | `LDA $10` | `$0010`。上位バイトは常に 0 |
| Zero Page,X | `LDA $10,X` | `($10 + X) & $FF`。**上位に繰り上がらない** |
| Absolute | `LDA $1234` | 次の 2 バイト（リトルエンディアン） |
| Absolute,X | `LDA $1234,X` | `$1234 + X`。**ページをまたぐと 1 サイクル増える** |
| Indirect,X | `LDA ($10,X)` | `$10+X` の位置から 2 バイト読んで、それをアドレスにする |
| Indirect,Y | `LDA ($10),Y` | `$10` の位置から 2 バイト読み、それに Y を足す |

**この 13 種類が、6502 の面倒さの中心です。**

回路としては、アドレスを組み立てるための専用の加算器と、上位 / 下位バイトを保持する一時レジスタが必要になります。

```ts
// src/nes/addressing.ts
/** Zero Page,X：8 ビットで折り返す */
export const zeroPageX = (base: number, x: number): number => (base + x) & 0xff

/** Absolute,X：16 ビット。ページをまたぐと余計に 1 サイクルかかる */
export const absoluteX = (base: number, x: number) => {
  const addr = (base + x) & 0xffff
  const crossed = (base & 0xff00) !== (addr & 0xff00)
  return { addr, extraCycle: crossed }
}
```

<Callout type="note" title="ページ境界で 1 サイクル増える理由">
  6502 は 8 ビット CPU なので、16 ビットのアドレス計算を**下位バイトと上位バイトに分けて**行います。

  下位バイトに X を足して、繰り上がりがなければそれで確定（上位はそのまま）。
  繰り上がりがあったときだけ、**もう 1 サイクル使って上位バイトを +1** します。

  「普段は速く、たまに遅い」という設計です。
  そしてこの 1 サイクルのずれが、ファミコンのゲームでは
  **画面のちらつき**として見えることがあります。
  Track 3 では、このサイクル数まで正確に再現する必要があります。
</Callout>

## 最小のデータパスを組む

制御信号を手で与えて、レジスタ間の転送と計算ができる形を作ります。

```ts
// src/nes/datapath.ts
export class Datapath {
  a = 0; x = 0; y = 0; s = 0xfd
  pc = 0
  flags = { n: 0, v: 0, d: 0, i: 1, z: 0, c: 0 } as const as Flags

  private bus = 0

  /** バスへ出す */
  drive(from: 'a' | 'x' | 'y' | 's' | 'mem', memValue = 0) {
    this.bus = from === 'mem' ? memValue : this[from]
  }

  /** バスから取り込む。同時にフラグも更新する（6502 の LDA / LDX / LDY の動作） */
  latch(to: 'a' | 'x' | 'y' | 's', setFlags = true) {
    this[to] = this.bus & 0xff
    if (setFlags) {
      this.flags.z = this[to] === 0 ? 1 : 0
      this.flags.n = (this[to] >> 7) & 1 ? 1 : 0
    }
  }
}
```

`TAX`（A を X にコピー）は、2 つの操作になります。

```ts
dp.drive('a')
dp.latch('x')
```

**これが 1 命令 2 サイクルの中身です。** Hack なら 1 サイクルで済んだ転送が、バス経由なので 2 段階に分かれます。

## テストを書く

```ts
// src/nes/datapath.check.ts
import { strict as assert } from 'node:assert'
import { addFlags } from './flags'
import { Datapath } from './datapath'

// --- フラグの検証：C と V が別物であること ---
assert.deepEqual(addFlags(0x50, 0x50, 0), { result: 0xa0, c: 0, z: 0, n: 1, v: 1 })
//  80 + 80 = 160。符号なしなら正常（C=0）、符号付きなら 80+80=-96 でおかしい（V=1）

assert.deepEqual(addFlags(0xd0, 0xd0, 0), { result: 0xa0, c: 1, z: 0, n: 1, v: 0 })
//  208 + 208 = 416 で符号なしはあふれ（C=1）、
//  符号付きなら -48 + -48 = -96 で正しい（V=0）

assert.deepEqual(addFlags(0xff, 0x01, 0), { result: 0x00, c: 1, z: 1, n: 0, v: 0 })
console.log('ok   C と V が独立に動く')

// --- データパス ---
const dp = new Datapath()
dp.a = 0x42
dp.drive('a'); dp.latch('x')
assert.equal(dp.x, 0x42, 'TAX')
assert.equal(dp.flags.z, 0)
assert.equal(dp.flags.n, 0)

dp.a = 0x00
dp.drive('a'); dp.latch('x')
assert.equal(dp.flags.z, 1, '0 を転送すると Z が立つ')

dp.a = 0x80
dp.drive('a'); dp.latch('y')
assert.equal(dp.flags.n, 1, 'bit7 が 1 なら N が立つ')
console.log('ok   バス経由の転送とフラグ更新')

// --- アドレッシング ---
import { absoluteX, zeroPageX } from './addressing'
assert.equal(zeroPageX(0xf0, 0x20), 0x10, 'Zero Page,X は折り返す')
assert.deepEqual(absoluteX(0x20f0, 0x20), { addr: 0x2110, extraCycle: true })
assert.deepEqual(absoluteX(0x2010, 0x20), { addr: 0x2030, extraCycle: false })
console.log('ok   アドレッシングの境界')

console.log('\n全部通りました')
```

`zeroPageX(0xf0, 0x20)` が `0x10` になることが重要です。**`0x110` にはなりません。** ゼロページは 256 バイトで折り返します。この仕様を知らずにエミュレータを書くと、一部のゲームだけが動かない、という症状になります。

## 演習

1. **`addFlags` の V の式を、条件分岐で書き直す**。「両方正で結果が負」か「両方負で結果が正」かを直接書いて、ビット演算版と一致することを確かめてください
2. **減算のフラグを実装する**。6502 の `SBC` は `A + (~M) + C` として計算されます。C が「借りがない」ことを表す点に注意してください
3. **Indirect,Y を実装する**。`($10),Y` で、ページ境界をまたぐケースも扱ってください
4. **有名なバグを再現する**。6502 の `JMP ($xxFF)` は、上位バイトを `$xx00` から読むという実装バグがあります。これを再現してください（ゲームがこの挙動に依存していることがあります）

<Callout type="warn" title="演習 4 は本当に必要">
  ハードウェアのバグが仕様として固定され、それに依存したソフトウェアが存在する。
  だからエミュレータは**バグまで再現しなければなりません**。

  第 2 章で読んだ「ISA は契約」という話の、影の部分です。
  契約書に書いていない実装の癖が、事実上の契約になってしまうことがあります。
</Callout>
