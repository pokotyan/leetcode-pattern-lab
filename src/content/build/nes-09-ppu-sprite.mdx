## 背景とは別の仕組み

背景はタイル単位の格子に固定されています。8 ピクセル単位でしか動かせません。

**キャラクタは 1 ピクセル単位で動く必要があります。** そこで、背景とは別の仕組みが用意されています。**スプライト**です。

## OAM

スプライトの情報は **OAM**（Object Attribute Memory）という 256 バイトの専用メモリに置かれます。

**1 スプライトあたり 4 バイト、最大 64 個**です。

| バイト | 内容 |
| --- | --- |
| 0 | **Y 座標 - 1** |
| 1 | タイル番号 |
| 2 | 属性 |
| 3 | X 座標 |

属性バイトの中身です。

| ビット | 意味 |
| --- | --- |
| 0-1 | パレット番号（4〜7 を使う） |
| 2-4 | 未使用 |
| 5 | **優先度**（0 = 背景の手前、1 = 背景の奥） |
| 6 | **水平反転** |
| 7 | **垂直反転** |

<Callout type="warn" title="Y 座標が 1 ずれている">
  OAM に入っている Y 座標は、**実際に表示される位置より 1 小さい**値です。

  スプライトの評価が 1 スキャンライン前に行われるという、
  ハードウェアの都合によるものです。

  つまり、`y = oam[0] + 1` が実際の位置です。
  そして `oam[0]` が 239 以上なら、画面外なので描画されません。
</Callout>

## 反転

水平・垂直の反転は、**タイルのデータを読む向きを変える**だけで実現します。

```ts
function spritePixel(tile: number[][], px: number, py: number, flipH: boolean, flipV: boolean) {
  const row = flipV ? 7 - py : py
  const col = flipH ? 7 - px : px
  return tile[row]![col]!
}
```

**同じタイルを左右反転して使い回せる**ので、キャラクタの左向き・右向きを 1 組のデータで表現できます。CHR ROM の節約になります。

## 描画の合成

各ピクセルで、背景とスプライトのどちらを表示するかを決めます。

| 背景 | スプライト | 優先度 | 結果 |
| --- | --- | --- | --- |
| 透明（色 0） | 透明 | - | **共通背景色** |
| 透明 | 不透明 | どちらでも | **スプライト** |
| 不透明 | 透明 | - | **背景** |
| 不透明 | 不透明 | 手前 (0) | **スプライト** |
| 不透明 | 不透明 | 奥 (1) | **背景** |

```ts
function composite(bg: number, bgOpaque: boolean, sp: number, spOpaque: boolean, behind: boolean) {
  if (!bgOpaque && !spOpaque) return backdropColor
  if (!bgOpaque) return sp
  if (!spOpaque) return bg
  return behind ? bg : sp
}
```

**「色 0 = 透明」という約束が、ここで効いてきます。** 第 7 回で見たパレットの構造が、そのまま重なり順の判定に使われています。

## スプライト同士の重なり

複数のスプライトが重なったとき、**OAM の番号が小さいほうが手前**になります。

```ts
// 番号の小さい順に走査し、最初に見つかった不透明なピクセルを採用する
for (let i = 0; i < visibleSprites.length; i++) {
  const color = spritePixel(...)
  if (color !== 0) { chosen = color; chosenIndex = i; break }
}
```

だから、ゲームは重要なキャラクタを OAM の先頭に置きます。

## 1 ラインあたり 8 個の制限

**同じスキャンライン上に表示できるスプライトは、最大 8 個**です。

9 個以上あると、9 個目以降は**表示されません**。そして、`$2002` の bit5（スプライトオーバーフローフラグ）が立ちます。

この制限は、PPU が 1 スキャンライン分のスプライトを保持する内部バッファ（**セカンダリ OAM**）が 32 バイト = 8 スプライト分しかないことから来ています。

<Callout type="tip" title="ちらつきの正体">
  ファミコンのゲームで、キャラクタが多いときに**ちらつく**ことがあります。

  これは、制限を回避するために **毎フレーム OAM の順番を入れ替えている**からです。
  交互に表示することで、「全部が半分の頻度で表示される」状態にします。
  完全に消えるよりましだ、という判断です。

  **ハードウェアの制約に対する、ソフトウェア側の工夫が、
  そのまま見た目の特徴になっています。**
</Callout>

## スプライト 0 ヒット

最も重要な機能です。

> **OAM の 0 番のスプライトの不透明なピクセルと、背景の不透明なピクセルが重なると、`$2002` の bit6 が立つ。**

一見すると当たり判定のように見えますが、**用途はまったく違います**。

実際には、**画面のどこを描画中かを知るため**に使われます。

```asm
; VBlank でスクロールを 0 にする（ステータスバーを固定表示）
WaitSprite0:
    BIT $2002
    BVC WaitSprite0      ; スプライト 0 ヒットを待つ

    ; ここまで来たら、画面の特定の位置まで描画が進んでいる
    LDA scrollX
    STA $2005            ; ここからスクロールを有効にする
```

スプライト 0 をステータスバーの下端に置いておけば、**そこを描画した瞬間が分かります**。そのタイミングでスクロール量を変えると、画面の上半分は固定、下半分はスクロール、という表示ができます。

<Callout type="warn" title="これが正確でないとゲームが止まる">
  スプライト 0 ヒットが発生しないと、ゲームは `BVC` のループから
  **永遠に抜けられません**。

  「タイトル画面は出るが、ゲームを始めると固まる」という症状の、
  最も多い原因がこれです。
  実装するときは、**フラグを立てる条件とタイミングの両方**を正確にする必要があります。

  条件：スプライト 0 かつ、背景とスプライトの両方が不透明、かつ x が 255 でない、
  かつ両方の描画が有効。
</Callout>

## 8 × 16 スプライト

`$2000` の bit5 を立てると、スプライトが 8 × 16 ピクセルになります。

このとき、タイル番号の意味が変わります。

```ts
if (sprite8x16) {
  const table = (tileIndex & 1) ? 0x1000 : 0x0000     // bit0 でパターンテーブルを選ぶ
  const top = tileIndex & 0xfe                         // bit0 を落とす
  const bottom = top + 1
}
```

**タイル番号の bit0 が、どのパターンテーブルを使うかの指定に転用されます。** 上下 2 枚のタイルは連番です。

垂直反転するときは、**上下も入れ替える**必要があります。細かい落とし穴です。

## OAM への転送

OAM に 256 バイト書くのに `$2003`/`$2004` を使うと、1 バイトずつになって遅すぎます。

そこで **DMA** を使います（第 4 回）。

```asm
LDA #$02
STA $4014       ; $0200〜$02FF の 256 バイトを OAM へ一括転送
```

513 サイクルで完了します。ゲームは RAM 上にスプライト情報を組み立てておき、VBlank で一気に転送します。

## テストを書く

```ts
// src/nes/sprite.check.ts
import { strict as assert } from 'node:assert'

// 基本の描画
{
  const ppu = makeTestPpu()
  setSolidTile(ppu, 1)                    // タイル 1 を全ピクセル色 1 にする
  ppu.oam.set([50, 1, 0, 100], 0)         // Y=50, タイル=1, 属性=0, X=100
  ppu.writeVram(0x3f11, 0x27)             // スプライトパレット 0 の色 1

  const frame = render(ppu)
  assert.equal(frame[51 * 256 + 100], 0x27, 'Y は OAM の値 + 1')
  assert.equal(frame[50 * 256 + 100], backdrop, '1 つ上は描かれない')
  console.log('ok   スプライトの位置')
}

// 水平反転
{
  const ppu = makeTestPpu()
  setLeftHalfTile(ppu, 1)                 // 左 4 ピクセルだけ色 1
  ppu.oam.set([50, 1, 0x40, 100], 0)      // bit6 = 水平反転

  const frame = render(ppu)
  assert.equal(frame[51 * 256 + 104], 0x27, '反転で右半分に出る')
  assert.equal(frame[51 * 256 + 100], backdrop)
  console.log('ok   水平反転')
}

// 優先度
{
  const ppu = makeTestPpu()
  setSolidBackground(ppu)                 // 背景を不透明にする
  setSolidTile(ppu, 1)

  ppu.oam.set([50, 1, 0x00, 100], 0)      // 手前
  assert.equal(render(ppu)[51 * 256 + 100], spriteColor)

  ppu.oam.set([50, 1, 0x20, 100], 0)      // bit5 = 奥
  assert.equal(render(ppu)[51 * 256 + 100], bgColor, '背景が優先される')
  console.log('ok   優先度')
}

// 8 個制限
{
  const ppu = makeTestPpu()
  setSolidTile(ppu, 1)
  for (let i = 0; i < 10; i++) {
    ppu.oam.set([50, 1, 0, i * 8], i * 4)     // 同じ Y に 10 個並べる
  }
  const frame = render(ppu)
  assert.notEqual(frame[51 * 256 + 0], backdrop, '1 個目は描かれる')
  assert.notEqual(frame[51 * 256 + 56], backdrop, '8 個目は描かれる')
  assert.equal(frame[51 * 256 + 64], backdrop, '9 個目は描かれない')
  assert.notEqual(ppu.status & 0x20, 0, 'オーバーフローフラグが立つ')
  console.log('ok   1 ラインあたり 8 個の制限')
}

// スプライト 0 ヒット
{
  const ppu = makeTestPpu()
  setSolidBackground(ppu)
  setSolidTile(ppu, 1)
  ppu.oam.set([50, 1, 0, 100], 0)
  render(ppu)
  assert.notEqual(ppu.status & 0x40, 0, 'スプライト 0 ヒットが立つ')
}
{
  const ppu = makeTestPpu()
  // 背景が透明なら当たらない
  setSolidTile(ppu, 1)
  ppu.oam.set([50, 1, 0, 100], 0)
  render(ppu)
  assert.equal(ppu.status & 0x40, 0, '背景が透明なら当たらない')
  console.log('ok   スプライト 0 ヒットの条件')
}

console.log('\n全部通りました')
```

**「9 個目が描かれない」テストが重要です。** 制限を実装し忘れても、ほとんどの場面で見た目は正しく見えます。しかし、ちらつきを前提にしたゲームでは挙動が変わります。

## 演習

1. **8 × 16 スプライトを実装する**。垂直反転で上下が入れ替わることも含めて
2. **OAM をダンプする**。64 個のスプライトの位置とタイル番号を表で出してください
3. **スプライトの左端 8 ピクセルを隠す設定**（`$2001` の bit2）を実装します
4. **スプライト 0 ヒットのタイミングを正確にする**。フレーム単位ではなく、スキャンライン単位で立てるようにしてください
5. **ちらつきを再現する**。OAM を毎フレーム回転させるテストプログラムを書いてみてください

## 次回
