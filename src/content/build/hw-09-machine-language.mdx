## 向きが変わる

これまでは「部品を作る」話でした。ここからは **「作った部品で何ができるかを、言葉として定義する」** という設計の話になります。

ここで決めることが、次回作る CPU の配線をすべて決定します。逆に言えば、**CPU の設計とは、命令セットを決めることとほぼ同義**です。

## 何ができるか、を数え上げる

手元にある部品と、それらができることを並べます。

| 部品 | できること |
| --- | --- |
| ALU | 2 つの値から 18 種類の計算 |
| Register × 2 | 値を 2 つ覚える（A と D と呼ぶことにする） |
| RAM | アドレスを指定して 1 語読み書き |
| PC | 次の命令の場所。ジャンプもできる |

やりたいことを書き出すと、こうなります。

1. **定数をレジスタに入れたい**（`x = 5`）
2. **計算したい**（`x = y + z`）
3. **メモリを読み書きしたい**（`x = arr[i]`）
4. **条件によってジャンプしたい**（`if`、`for`）

問題は、**16 ビットにこれらをどう詰め込むか**です。

## まず、定数をどうするか

`x = 12345` をやりたい。12345 を表すには 14 ビット必要です。「何をするか」の指定も要るので、16 ビットでは足りません。

そこで割り切ります。

> **命令を 2 種類にする。片方は定数を入れるためだけの命令にする。**

先頭 1 ビットで種類を区別します。

| 先頭ビット | 種類 | 中身 |
| --- | --- | --- |
| **0** | **A 命令** | 残り 15 ビットが定数。それを A レジスタに入れる |
| **1** | **C 命令** | 残り 15 ビットで、計算と代入と分岐を指定する |

```
0 vvvvvvvvvvvvvvv        A 命令：15 ビットの値を A に入れる
1 11 a cccccc ddd jjj    C 命令：計算して、どこかに入れて、場合によっては飛ぶ
```

A 命令では 0〜32767 の定数を扱えます。負数や大きい数は、A 命令で正の値を入れてから C 命令で符号を反転させます。

<Callout type="note" title="A レジスタが 2 役を担う">
  A レジスタは、**定数の置き場所**であり、同時に **メモリのアドレス**でもあります。

```asm
@100        ; A = 100
D=M         ; D = RAM[100]   ← A がアドレスとして使われた
```
```asm
@100        ; A = 100
D=A         ; D = 100        ← A が値として使われた
```
  レジスタが少ないので、1 本に複数の役割を持たせています。
  さらに、ジャンプ先アドレスの置き場所でもあります。
  **この兼用が、Hack の設計を極端に小さくしています。**
</Callout>

## C 命令の中身

15 ビットの内訳です。先頭の `11` は使いません（将来の拡張用に予約）。

```
1 1 1 a c1 c2 c3 c4 c5 c6 d1 d2 d3 j1 j2 j3
      └────────┬────────┘ └──┬──┘ └──┬──┘
           何を計算するか   どこに入れる  飛ぶか
```

### a と cccccc：何を計算するか

`cccccc` の 6 ビットは、**そのまま ALU の制御線**です。第 5 回で作った `zx nx zy ny f no` です。

ALU の入力 `x` は常に **D レジスタ**。入力 `y` は、`a` ビットで選びます。

| a | y に入るもの |
| --- | --- |
| 0 | **A レジスタの値** |
| 1 | **RAM[A] の値**（M と書く） |

つまり `a` は、「A を値として使うか、アドレスとして使うか」の切り替えです。

計算できるものの一覧です（`M` は `RAM[A]` のこと）。

| 式 | a | cccccc |
| --- | --- | --- |
| 0 | 0 | 101010 |
| 1 | 0 | 111111 |
| -1 | 0 | 111010 |
| D | 0 | 001100 |
| A | 0 | 110000 |
| **M** | **1** | 110000 |
| !D | 0 | 001101 |
| -D | 0 | 001111 |
| D+1 | 0 | 011111 |
| D-1 | 0 | 001110 |
| D+A | 0 | 000010 |
| **D+M** | **1** | 000010 |
| D-A | 0 | 010011 |
| **D-M** | **1** | 010011 |
| A-D | 0 | 000111 |
| D&A | 0 | 000000 |
| D\|A | 0 | 010101 |

**`A` と `M` で `cccccc` が同じ**ことに注目してください。違うのは `a` ビットだけです。ALU にとっては「y の入力」でしかなく、それがレジスタから来るかメモリから来るかは関係ありません。

### ddd：どこに入れるか

3 ビットが、それぞれ独立した「書き込むかどうか」のフラグです。

| ビット | 立っていたら |
| --- | --- |
| d1 | **A** に書く |
| d2 | **D** に書く |
| d3 | **M**（RAM[A]）に書く |

独立なので、複数同時に書けます。

| 書き方 | d1 d2 d3 |
| --- | --- |
| （どこにも書かない） | 000 |
| `M=` | 001 |
| `D=` | 010 |
| `MD=` | 011 |
| `A=` | 100 |
| `AMD=` | 111 |

### jjj：飛ぶかどうか

ALU の出力と 0 を比べた結果で、ジャンプするかを決めます。**ジャンプ先は常に A レジスタの値**です。

| ビット | 条件 |
| --- | --- |
| j1 | out **< 0** なら飛ぶ |
| j2 | out **= 0** なら飛ぶ |
| j3 | out **> 0** なら飛ぶ |

組み合わせで 8 通りになります。

| 記法 | j1 j2 j3 | 意味 |
| --- | --- | --- |
| （なし） | 000 | 飛ばない |
| `JGT` | 001 | > 0 |
| `JEQ` | 010 | = 0 |
| `JGE` | 011 | ≥ 0 |
| `JLT` | 100 | < 0 |
| `JNE` | 101 | ≠ 0 |
| `JLE` | 110 | ≤ 0 |
| `JMP` | 111 | **常に飛ぶ** |

<Callout type="tip" title="3 ビットの独立なフラグが、8 通りの条件を作る">
  `JGE`（≥ 0）が `011` なのは、「= 0 のとき飛ぶ」と「> 0 のとき飛ぶ」の**両方を立てた**からです。
  `JMP` が `111` なのは、3 つ全部を立てたので必ずどれかに当てはまるからです。

  条件を列挙するのではなく、**基本の 3 条件の論理和として表現している**。
  ここでも、第 5 章で見た ALU の設計と同じ「組み合わせで作る」発想が使われています。
</Callout>

## 書き方

機械語のビット列を直接書くのは辛いので、人間向けの記法（アセンブリ）を決めます。

```asm
@値              ; A 命令
dest = comp ; jump    ; C 命令。dest と jump は省略可
```

例です。

```asm
@100        ; A = 100
D=M         ; D = RAM[100]
@200
D=D+M       ; D = D + RAM[200]
@300
M=D         ; RAM[300] = D
```

条件分岐です。

```asm
@0
D=M         ; D = RAM[0]
@SKIP
D;JLE       ; D ≤ 0 なら SKIP へ飛ぶ
@1
M=1         ; RAM[1] = 1
(SKIP)      ; ラベル
```

`(SKIP)` は**ラベル**で、機械語には変換されません。「この行の位置」を名前で参照するための印です。次の回のアセンブラが、これを実際のアドレスに変換します。

無限ループはこう書きます。

```asm
(END)
@END
0;JMP       ; 計算結果 0 を捨てて、常に END へ飛ぶ
```

`0;JMP` の `0` は、ALU に何か計算させないと命令にならないので置いている**ダミー**です。結果はどこにも代入されません。

<Callout type="warn" title="プログラムの終わりは無限ループ">
  Hack には「停止する」命令がありません。CPU は永遠に命令を読み続けます。
  終わりたければ、その場で回り続けるしかありません。

  実際の CPU には `HLT` 命令があり、割り込みが来るまで停止します。
  組み込みの世界では、今もメインループの最後が無限ループになっているのが普通です。
</Callout>

## 手でアセンブルしてみる

`D=D+M` を 16 ビットに変換します。

```
先頭         111
a            1        （M を使うので）
cccccc       000010   （D+A の行）
ddd          010      （D に書く）
jjj          000      （飛ばない）

→ 1111 0000 1001 0000 = 0xF090
```

`@100` はこうです。

```
先頭         0
値           000000001100100   （100 の 15 ビット表現）

→ 0000 0000 0110 0100 = 0x0064
```

## 全部書いてみる

RAM[0] と RAM[1] を足して RAM[2] に入れるプログラムです。

```asm
@0
D=M         ; D = RAM[0]
@1
D=D+M       ; D = D + RAM[1]
@2
M=D         ; RAM[2] = D
(END)
@END
0;JMP
```

機械語にすると 8 語です。

```
0000000000000000    @0
1111110000010000    D=M
0000000000000001    @1
1111000010010000    D=D+M
0000000000000010    @2
1110001100001000    M=D
0000000000000110    @END  (アドレス 6)
1110101010000111    0;JMP
```

**これが、次回作る CPU が実行するものです。**

## テストを書く

この回に「動くコード」はありませんが、手でアセンブルした結果を確かめられます。

```ts
// src/instruction.check.ts
import { strict as assert } from 'node:assert'

/** 命令のビット列を人間向けに分解して表示する */
const decode = (word: number): string => {
  const b = word.toString(2).padStart(16, '0')
  if (b[0] === '0') return `A 命令  値 = ${parseInt(b.slice(1), 2)}`
  return [
    `C 命令`,
    `a=${b[3]}`,
    `comp=${b.slice(4, 10)}`,
    `dest=${b.slice(10, 13)}`,
    `jump=${b.slice(13, 16)}`,
  ].join('  ')
}

const PROGRAM = [
  0b0000000000000000,   // @0
  0b1111110000010000,   // D=M
  0b0000000000000001,   // @1
  0b1111000010010000,   // D=D+M
  0b0000000000000010,   // @2
  0b1110001100001000,   // M=D
  0b0000000000000110,   // @END
  0b1110101010000111,   // 0;JMP
]

for (const [i, w] of PROGRAM.entries()) {
  console.log(String(i).padStart(2), w.toString(2).padStart(16, '0'), decode(w))
}

// 手で確かめた値と突き合わせる
assert.equal(PROGRAM[1], 0xFC10, 'D=M')
assert.equal(PROGRAM[3], 0xF090, 'D=D+M')
assert.equal(PROGRAM[5], 0xE308, 'M=D')
assert.equal(PROGRAM[7], 0xEA87, '0;JMP')
console.log('\nビット配置が期待どおりです')
```

```bash
npx tsx src/instruction.check.ts
```

## 演習

1. **`AMD=D+1` を手でアセンブルする**。3 箇所同時に書き込む命令です
2. **`D=D-M;JNE` を手でアセンブルする**。計算と代入と分岐を同時に行います
3. **RAM[0] の符号を反転して RAM[1] に入れる**プログラムを書き、機械語に変換してください
4. **`if (RAM[0] > RAM[1]) RAM[2] = RAM[0]; else RAM[2] = RAM[1];`** をアセンブリで書いてください。ラベルが 2 つ要ります
5. **使われていないビットを数える**。C 命令の `11`（2 ビット）は常に固定です。ここに機能を足すとしたら何を足すか考えてください
