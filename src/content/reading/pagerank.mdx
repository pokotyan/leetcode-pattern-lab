## まず、素朴な案から始めます

ウェブページに順位をつけたいとします。検索語との関連度（BM25）だけでは、内容が薄いページと権威あるページを区別できません。**ページそのものの重要度**を測る指標が要ります。

素朴な案は「**リンクされている数が多いページほど偉い**」です。被リンク数を数えるだけなので簡単ですが、すぐ壊れます。

1. **自作自演に弱い。** 適当なページを 1 万枚作って全部からリンクすれば、被リンク数 1 万になります
2. **リンク元の質を見ていない。** 有名な新聞社からの 1 本と、無名のページからの 1 本が同じ重みになります

2 番目を直そうとすると、話が一気に難しくなります。「リンク元が偉いほど、そのリンクは重い」と決めると、**偉さを決めるのに偉さが要る**という循環に陥るからです。

## 発想を変える：値を配り合って、落ち着くまで待つ

循環をそのまま受け入れます。定義はこうです。

> あるページの重要度は、**そのページにリンクしているページの重要度を、リンク数で割って足したもの**

「自分の持っている値を、出ていくリンクに等分して渡す」と読み替えると、手順になります。

1. 最初は全ページに同じ値を配る（合計が 1 になるように）
2. 各ページが、自分の値を出リンクの本数で割って、リンク先に渡す
3. 全員が受け取った値を、新しい値とする
4. 値がほとんど動かなくなるまで 2〜3 を繰り返す

循環参照があっても、この手順は問題なく回ります。**方程式を解く代わりに、収束するまで回す**という方針です。

```python
def pagerank(graph, n, d=0.85, iters=20):
    rank = [1 / n] * n                      # 最初は全員同じ値
    out = [len(graph[i]) for i in range(n)]
    for _ in range(iters):
        nxt = [(1 - d) / n] * n             # どこからでも飛んでくる分
        for u in range(n):
            if out[u] == 0:
                continue
            share = d * rank[u] / out[u]    # 自分の値を出リンクに等分する
            for v in graph[u]:
                nxt[v] += share
        rank = nxt
    return rank
```

「1点に集まる」を選んで、値が特定のノードへ寄っていき、数回で動かなくなる様子を見てください。**リンクされている数ではなく、偉いページからリンクされているかで順位が決まっている**ことが分かります。

## ランダムに歩く人、として読む

この計算には、別の読み方があります。

> ウェブを当てもなく歩き回る人がいる。いまいるページのリンクを 1 本ランダムに選んでクリックする。これを延々と続けたとき、**その人がいまページ X にいる確率**が、X の PageRank

「値を配る」という操作は、確率が移動していく様子そのものです。だから、

- 値の合計は常に **1**（どこかのページには必ずいる）
- リンクが集まるページには、歩く人が高い確率で滞在する

という性質が自然に出てきます。確率と期待値のノートで見た「確率の遷移」を、そのままウェブに当てはめた形です。

<Callout type="tip" title="d（減衰係数）が何をしているのか">
  コードの `d = 0.85` と `(1 - d) / n` は、次の状況に対応しています。

  > 歩いている人は、85% の確率でリンクをクリックするが、**15% の確率で飽きて、どこか適当なページへ飛ぶ**

  この「飽きて飛ぶ」は、2つの困った状況を同時に解決します。

  1. **行き止まり（出リンクが無いページ）。** そこに入った確率が永久に閉じ込められ、合計が 1 でなくなってしまう
  2. **閉じたグループ。** 数ページが互いにリンクし合っているだけで外に出ないと、そこに全部の値が吸い込まれる（自作自演への対策でもあります）

  どこからでも全ページへ飛べるようになるので、**「どの状態からどの状態へも到達できる」**という条件が保証され、収束が約束されます。0.85 という値は経験的なもので、これといった導出があるわけではありません。
</Callout>

## 行列のべき乗として見る

ここまでの反復は、行列累乗のノートの内容そのものです。

リンク構造を行列 `M` で表します（`M[v][u] = 1/out[u]`、つまり u から v へ渡る割合）。すると 1 回の反復は、

```
rank ← M × rank
```

という掛け算 1 回です。したがって `k` 回の反復は `M^k × rank₀` であり、**遷移行列のべき乗**にほかなりません。

行列累乗のノートで「隣接行列の k 乗が k 歩の経路数になる」と書いたのと、同じ構造です。違いは、足し合わせるのが経路の本数か確率か、という点だけです。

<Callout type="warn" title="実際には行列累乗では計算しません">
  理屈の上では `M^k` を繰り返し二乗法で求めれば O(log k) 回の行列積で済みます。ところが実務ではそうしません。

  ウェブの規模ではノード数 `n` が数十億あり、`n × n` の行列は**そもそも持てません**（10<sup>18</sup> 要素）。一方で、実際のリンクは各ページから数十本しか出ていない**疎なグラフ**です。

  だから、行列積の形ではなく**辺をたどって値を配る**形（上のコード）で計算します。1 回の反復が O(辺の数) で済み、反復は数十回で十分収束します。

  「数学的にはこう書けるが、実装は別の形になる」という乖離は、規模が大きくなると頻繁に起きます。**式の形と、それを計算する手順は別物**だと切り分けてください。
</Callout>

## 収束はどれくらいで止めるか

反復を何回まわすかは、**値の変化量**で決めます。

```python
if sum(abs(nxt[i] - rank[i]) for i in range(n)) < 1e-8:
    break
```

実用上は、数十回で十分に落ち着きます。理由は、1 回の反復で誤差がおよそ `d` 倍（0.85 倍）に縮むからです。`0.85^50` は約 0.0003 なので、50 回も回せば初期値の影響はほぼ消えます。

これは等比数列の話です。**「毎回一定の割合で縮むなら、必要な回数は log で決まる」**という、数列のノートの見積もりがそのまま使えます。

## 何に応用できるか

PageRank の考え方は、ウェブ以外にも移せます。共通しているのは、「**つながりの構造から、各要素の重要度を決めたい**」という状況です。

| 対象 | ノード | 辺 |
| --- | --- | --- |
| ウェブ検索 | ページ | ハイパーリンク |
| 論文の影響力 | 論文 | 引用 |
| SNS の影響力 | ユーザー | フォロー |
| 不正検知 | 口座 | 送金 |
| 推薦（Personalized PageRank） | 商品・ユーザー | 購入・閲覧 |

最後の Personalized PageRank は、「飽きて飛ぶ」先を全ページ均等ではなく**特定のユーザーが見たページに偏らせる**やり方です。そのユーザーから見た重要度が出るので、そのまま推薦に使えます。式の 1 箇所を変えるだけで、用途が変わります。

## まとめ

- 被リンク数を数えるだけでは、自作自演とリンク元の質に対応できない
- 「リンク元の重要度を分け合う」と定義すると循環するが、**反復すれば収束する**
- 値の正体は、ランダムに歩く人がそこにいる確率。だから合計は 1
- 減衰係数は、行き止まりと閉じたグループへの対策
- 数式としては遷移行列のべき乗だが、実装は疎なグラフを辺に沿ってたどる形になる
