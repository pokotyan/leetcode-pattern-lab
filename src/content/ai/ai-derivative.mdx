## AI は「少し動かすとどうなるか」を知りたい

ニューラルネットワークの中身は、大量の数の組です。この数を**重み**（weight）と呼びます。学習とは、重みを少しずつ調整して、出力と正解のずれ（**誤差**、または**損失**）を小さくしていく作業です。

調整するには、重みの 1 つ 1 つについて次の問いに答える必要があります。

> この重みをほんの少し増やしたら、誤差は増えるのか、減るのか。どれくらいの勢いで変わるのか。

増えるなら減らす方向へ、減るなら増やす方向へ動かせばよいからです。この「ほんの少し動かしたときの変わり方の勢い」を数で表したものが**微分**（derivative）です。

この回では、微分を次の順に見ていきます。

1. 2 点を結ぶ直線の傾き（平均の変化率）
2. 2 点を限りなく近づけたときの傾き（接線の傾き＝微分）
3. 記号の読み方と、よく使う公式
4. 計算機で微分を近似する方法と、その落とし穴
5. ニューラルネットワークでよく使う関数（活性化関数）の微分

## 平均の変化率：2 点を結ぶ直線の傾き

出発点は、中学校で習う「直線の傾き」です。

関数 f（入力 x を受け取って、出力 f(x) を返す決まり）のグラフ上に、2 つの点を取ります。1 つは x、もう 1 つはそこから h だけ右の x + h です。この 2 点を結ぶ直線を**割線**（かっせん）と呼びます。割線の傾きは「縦の変化 ÷ 横の変化」です。

```text
            f(x + h) − f(x)
割線の傾き = ─────────────────
                  h
```

**この式が言っていること**：x を h だけ動かしたら、出力が f(x + h) − f(x) だけ変わった。それを h で割れば、「x を 1 動かすあたり、出力がどれだけ変わったか」という平均の勢いになる。

小さな数で 1 回計算してみます。f(x) = x²（x を 2 回掛ける関数）で、x = 3、h = 1 とします。

```text
f(3 + 1) − f(3)     16 − 9
─────────────── = ──────── = 7
       1              1
```

x を 3 から 4 に動かすと、出力は 9 から 16 に 7 増えました。この区間では、平均すると「x を 1 動かすと出力が 7 増える」勢いです。

## 2 点を近づける：接線の傾き

ただし、知りたいのは「区間の平均」ではなく「x = 3 というその一点での勢い」です。そこで h をどんどん小さくしていきます。

| h | 割線の傾き ((3 + h)² − 9) / h |
| --- | --- |
| 1 | 7 |
| 0.1 | 6.1 |
| 0.01 | 6.01 |
| 0.001 | 6.001 |

h を小さくするほど、傾きは 6 に近づいていきます。h を 0 に「限りなく近づけた」ときに行き着く値（**極限**と呼びます）が、x = 3 での**微分**です。図で言えば、2 点がくっついて割線が**接線**（その点でグラフにちょうど触れる直線）になったときの傾きです。

下の図で確かめてください。幅 h を小さくすると、破線の割線が実線の接線に重なり、下のグラフの白抜きの点（割線の傾き）が塗りつぶした点（接線の傾き）に重なります。

<TangentSlope client:visible />

<Callout type="note" title="h = 0 をそのまま代入してはいけない">
  割線の式に h = 0 を入れると、分母が 0 になって計算できません。微分は「h = 0 のときの値」ではなく、「h を 0 に近づけていったときに、値がどこへ向かうか」です。この区別のために、数学では極限（limit）という言葉を使います。
</Callout>

## 記号の読み方

微分には 2 通りの書き方があり、どちらもよく出てきます。

| 書き方 | 読み方 | 意味 |
| --- | --- | --- |
| f′(x) | エフ・ダッシュ・エックス（英語では f prime） | 関数 f を微分したもの。x を入れると、その点での傾きが返る |
| dy/dx | ディー・ワイ・ディー・エックス | y = f(x) のとき、「x の小さな変化 dx に対する y の小さな変化 dy の比」 |

dy/dx は分数のように見えますが、「d がついた量どうしの比の極限」を表す 1 つの記号として読みます。それでも分数のように扱うと直感に合う場面が多く、後の回で出てくる連鎖律（ai-backprop で扱います）はその典型です。

f′(x) のように、各点の傾きを返す関数そのものを**導関数**と呼びます。図の下のグラフが導関数です。

## 定義から計算する：x² の微分

さきほどの表では h を具体的な数にしましたが、文字のまま計算すると、どの x でも使える答えが出ます。

```text
(x + h)² − x²     x² + 2xh + h² − x²     2xh + h²
───────────── = ──────────────────── = ───────── = 2x + h
      h                   h                 h
```

最後の式 2x + h で h を 0 に近づけると、2x が残ります。つまり

```text
f(x) = x²   のとき   f′(x) = 2x
```

x = 3 なら 2 × 3 = 6 で、表の行き着く先と一致します。表の 6.1、6.01、6.001 は、まさにこの「2x + h」の h の部分が残っていた値です。

**この結果が言っていること**：x² は、x が大きいところほど急に増える。x = 1 では傾き 2、x = 10 では傾き 20。x が負のところでは傾きが負で、右へ進むほど値が減っている。

## よく使う公式

毎回定義から計算するのは大変なので、よく出る形は公式として覚えておきます。

| 関数 f(x) | 微分 f′(x) | 一言で |
| --- | --- | --- |
| c（定数） | 0 | 動かない値は、変化しない |
| c × g(x) | c × g′(x) | 何倍かした関数の傾きも、同じだけ何倍かになる |
| g(x) + k(x) | g′(x) + k′(x) | 足した関数の傾きは、傾きどうしの和 |
| xⁿ | n × xⁿ⁻¹ | x² なら 2x、x³ なら 3x² |
| eˣ | eˣ | 微分しても形が変わらない、特別な関数 |
| log x（自然対数） | 1 / x | x が大きいほど、増え方がゆるやかになる |
| sin x | cos x | 図の「sin x」で確かめられる |

e はおよそ 2.718 の定数で、eˣ は「x が 1 増えるたびに e 倍になる」関数です。eˣ は後で出てくるシグモイドや softmax（ai-softmax-entropy で扱います）の中に入っています。log x は eˣ の逆で、「e を何乗したら x になるか」を返す関数です。確率を扱う回で、掛け算を足し算に変える道具として何度も出てきます。

関数を組み合わせたもの（関数の中に関数が入っている形）の微分には、もう 1 つ**連鎖律**という規則が要ります。これがニューラルネットワークの学習の要なので、独立した回（ai-backprop）で扱います。

## 傾きが 0 の所は山か谷

微分が教えてくれるもう 1 つの大事なことは、**山の頂上と谷の底では、傾きが 0 になる**という事実です。

図で x² を選び、点 x を左から右へ動かしてください。x が負の間は傾きが負（下り坂）、x = 0 で傾きがちょうど 0、正になると傾きが正（上り坂）です。x = 0 が谷の底です。sin x を選ぶと、山の頂上（x ≈ 1.57）でも傾きが 0 になるのが見えます。

学習の目標は「誤差がいちばん小さくなる重みを見つける」ことでした。誤差を重みの関数として見ると、これは**誤差のグラフの谷の底を探す**ことです。谷の底では傾きが 0 です。そして傾きが負なら右へ、正なら左へ進めば底に近づきます。次の回（ai-gradient-descent）では、この考え方をそのまま学習の手順にした勾配降下法を見ます。

<Callout type="warn" title="傾き 0 は「いちばん低い所」とは限らない">
  傾きが 0 になるのは、谷の底だけではありません。山の頂上でも、坂の途中の平らな踊り場でも 0 になります。さらに、谷が複数あれば、そのうちの 1 つの底にいるだけかもしれません。傾きは「今いる場所のすぐ近く」のことしか教えてくれない、という限界は覚えておいてください。
</Callout>

## 数値微分：計算機で近似する

公式が分かっている関数なら、微分は式で求められます。しかし、プログラムの中の複雑な処理には、微分の式がすぐには手に入らないこともあります。そのときの素朴な方法が、定義をそのまま計算機で実行する**数値微分**です。h を十分小さな数（たとえば 0.00001）にして、割線の傾きを計算します。

よく使われる形は 2 つあります。

```text
前進差分：  (f(x + h) − f(x)) / h
中心差分：  (f(x + h) − f(x − h)) / (2h)
```

中心差分は x の左右に同じ幅ずつ取るので、左右の曲がり方の影響が打ち消し合い、同じ h でも誤差がずっと小さくなります。

### 手元で確かめる：h を小さくしすぎると壊れる

「h は小さいほど正確」と思いたくなりますが、計算機ではそうなりません。f(x) = sin x の x = 1 での微分（正しい値は cos 1 = 0.5403023058681398）を、h を 0.1 から 10⁻¹⁵ まで変えて計算しました（Python 3.14.0、Apple M1 Pro / macOS 26.2）。

```text

   1e-04          0.5402602314186211    4.2e-05            0.5403023049677103    9.0e-10
   1e-05          0.5402980985058647    4.2e-06            0.5403023058569989    1.1e-11
```

誤差の列を上から読むと、はじめは h を 10 分の 1 にするごとに誤差も減っていきます。前進差分は 10 分の 1 ずつ、中心差分は 100 分の 1 ずつです。ところが、前進差分は h = 10⁻⁸ 付近、中心差分は h = 10⁻⁵ 付近を境に、**h を小さくするほど誤差が増えはじめます**。誤差を縦に並べると U 字の形になり、h = 10⁻¹⁵ では小数第 2 位から間違っています。

原因は、計算機が小数を有限の桁で持っていることです（低レイヤの<a href={`${import.meta.env.BASE_URL}lowlevel/ll-04-float/`}>第 4 回「小数を表す」</a>で扱っています）。Python の文書は、1.0 のすぐ上に表せる数との差（機械イプシロン）を「difference between 1.0 and the least value greater than 1.0 that is representable as a float」と説明しています（[Python: sys.float_info](https://docs.python.org/3/library/sys.html#sys.float_info)）。この値はおよそ 2.2 × 10⁻¹⁶ で、1 付近の数はそれより細かい違いを持てません。h = 10⁻¹⁵ のときに実際に何が起きているかを出力すると、次のようになりました。

```text
h=1e-15: sin(1+h) = 0.8414709848078971
         sin(1)   = 0.8414709848078965
         差       = 5.551115123125783e-16  (1 ulp of sin(1) = 1.1102230246251565e-16)
         1+h      = 1.000000000000001  (実際に足された量 1.1102230246251565e-15)
```

- 1 + 10⁻¹⁵ は正確には表せず、実際に足されたのは 1.11 × 10⁻¹⁵ でした
- sin(1 + h) と sin(1) の差は、最後の桁（ulp。Python の文書の言葉では「ULP stands for “Unit in the Last Place”」、[Python: math.ulp](https://docs.python.org/3/library/math.html#math.ulp)）のちょうど 5 つ分しかありません

差がもともと最後の桁 5 つ分しかないので、丸めで 1 つずれるだけで答えが 2 割変わります。それを小さな h で割るので、誤差が何倍にも拡大されます。**近い 2 つの数を引き算すると、上の桁が打ち消し合って、意味のある桁がほとんど残らない**という現象で、数値計算では「桁落ち」と呼ばれます。

つまり数値微分には 2 種類の誤差があり、引っ張り合っています。

| 誤差の種類 | h を小さくすると | 原因 |
| --- | --- | --- |
| 打ち切り誤差 | 減る | 割線は接線そのものではない（極限を取り切っていない） |
| 丸め誤差 | 増える | 近い数の引き算で、有効な桁が消える |

<Callout type="tip" title="AI の学習で数値微分を使わない理由">
  重みが 100 万個あれば、数値微分は 1 回の学習の 1 歩ごとに関数を 100 万回以上計算し直すことになり、そのうえ上のような誤差を抱えます。実際の学習では、式の形から微分を正確に、しかも全部の重みについてまとめて求める方法（誤差逆伝播。ai-backprop で扱います）を使います。数値微分は、その実装が正しいかを小さな例で確かめる「答え合わせ」の道具として使われます。
</Callout>

## 活性化関数の微分

ニューラルネットワークでは、重みを掛けて足した値を、**活性化関数**と呼ばれる関数に通します。直線（足し算と掛け算）だけを重ねても、全体は直線にしかならないので、曲がった関数を挟んで表現力を持たせるためです（ai-mlp-backprop で詳しく扱います）。学習では、この活性化関数の微分も必要になります。代表的な 2 つを見ておきます。

### シグモイド

```text
            1
σ(x) = ──────────        σ は「シグマ」と読む
        1 + e⁻ˣ
```

どんな x を入れても 0 と 1 の間の値を返す、なだらかな S 字の関数です。微分を計算すると、次のきれいな形になります。

```text
σ′(x) = σ(x) × (1 − σ(x))
```

**この式が言っていること**：シグモイドの傾きは、シグモイド自身の値だけから計算できる。値が 0.5 のときにいちばん大きく、0 や 1 に近づくと小さくなる。

実際に計算すると、次のとおりです。

| x | σ(x) | σ′(x) |
| --- | --- | --- |
| 0 | 0.5 | 0.25 |
| 2 | 0.880797 | 0.104994 |
| 5 | 0.993307 | 0.006648 |

傾きの最大値は 0.25 です。図で「シグモイド」を選び、点 x を端のほうへ動かすと、下のグラフの傾きがほぼ 0 に張り付くのが見えます。

この性質は、層を何段も重ねたときに問題になります。後の回で見るとおり、層をさかのぼるたびに傾きが掛け算されるので、0.25 以下の数を 10 回掛けると 0.25¹⁰ ≈ 0.00000095 になります。入力に近い層の重みは「少し動かしても誤差がほとんど変わらない」ように見えてしまい、学習が進みません。これは**勾配消失**と呼ばれ、深いネットワークの学習を長く難しくしていた原因の 1 つです。

### ReLU

```text
ReLU(x) = max(0, x)        x が負なら 0、正ならそのまま
```

ReLU（レル、Rectified Linear Unit）は、負の入力を 0 に切り捨てるだけの関数です。微分も単純です。

```text
ReLU′(x) = 0   （x < 0）
           1   （x > 0）
```

正の側の傾きはいつも 1 なので、何段重ねても掛け算で小さくなっていきません。シグモイドの勾配消失を避けられることが、深いネットワークで ReLU が広く使われるようになった理由の 1 つです（ai-cnn で扱う AlexNet がその例です）。

<Callout type="note" title="x = 0 での ReLU の傾き">
  図で ReLU を選び、点 x を 0 に合わせると、接線の傾きが「定まらない」と表示されます。x = 0 の左側では傾き 0、右側では傾き 1 で、グラフがそこで折れているからです。数学的にはこの点で微分できません。計算機では、入力がちょうど 0 になることはまれなので、実装はこの点の傾きを 0 か 1 のどちらかに決めておいて先へ進みます。
</Callout>

## AI ではどこで使うか

ここまでの道具を、学習の言葉に置き換えておきます。

| この回の言葉 | 学習での意味 |
| --- | --- |
| 関数 f | 重みを入れると、誤差を返す関数 |
| x | 重み（実際には 1 個ではなく何百万個もある） |
| 微分 f′(x) | 重みを少し動かしたときの、誤差の変わり方の勢い |
| 傾きが 0 の所 | 誤差の谷の底（の候補） |
| 活性化関数の微分 | 誤差の変わり方を、層をさかのぼって伝えるときに掛け算される数 |

実際の重みは 1 個ではありません。重みが 2 個以上あると、「どの重みを動かしたときの傾きか」を区別する必要があり、それらを並べたものを**勾配**と呼びます。次の回では、この勾配を使って誤差の谷を下っていく勾配降下法を見ます。

## まとめ

- 微分は、入力を少し動かしたときに出力がどれだけの勢いで変わるかを表す数。グラフで言えば、その点での接線の傾き
- 2 点を結ぶ割線の傾き (f(x + h) − f(x)) / h で、h を 0 に限りなく近づけた行き先が微分
- f(x) = x² の微分は 2x。定義から計算すると、割線の傾き 2x + h の h が消えて得られる
- 定数倍・和・xⁿ・eˣ・log x などの公式を使えば、毎回定義から計算しなくてよい
- 山の頂上と谷の底では傾きが 0 になる。学習は誤差の谷の底を探すこと
- 計算機で h を小さくしすぎると、近い数の引き算で桁が消え、数値微分は逆に不正確になる。実測では、中心差分の誤差は h = 10⁻⁵ 付近がいちばん小さかった
- シグモイドの傾きは最大でも 0.25 で、層を重ねると掛け算で小さくなる（勾配消失）。ReLU は正の側で傾きがいつも 1
