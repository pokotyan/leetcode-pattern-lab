## 何を求めたいのか

<a href={`${import.meta.env.BASE_URL}ai/ai-gradient-descent/`}>勾配と勾配降下法</a>の回で、学習とは「損失（予測の外れ具合を 1 つの数にしたもの）を、重みを少しずつ動かして小さくしていくこと」だと見ました。動かす向きを決めるには、重みの 1 つ 1 つについて次の量が要ります。

> その重みをほんの少し増やしたとき、損失はどれだけ増えるか（減るか）

これが損失をその重みで微分した値で、<a href={`${import.meta.env.BASE_URL}ai/ai-derivative/`}>微分</a>の回で見た「傾き」です。重みが 2 つや 3 つなら、1 つずつ少し動かして損失を計算し直せば求まります。しかし大きなモデルの重みは数十億あります。1 つ動かすたびにモデル全体を計算し直していたら、1 回の学習の 1 歩すら終わりません。

この回で見る**誤差逆伝播**（backpropagation。逆伝播とも）は、重みがいくつあっても、**モデルを前から 1 回計算し、後ろから 1 回戻るだけで、すべての重みの傾きを一度にそろえる**方法です。土台になっているのは、高校で習う微分の公式の 1 つ、連鎖律だけです。

## 合成関数：出力を次の入力に入れる

まず言葉を 1 つ用意します。ある関数の出力を、別の関数の入力にすることを**合成**と呼び、できた関数を**合成関数**と呼びます。

たとえば「2 倍する」関数 g と「1 を足す」関数 f があるとき、x を g に入れてから f に入れると、

```
y = g(x) = 2x
z = f(y) = y + 1
→ z = f(g(x)) = 2x + 1
```

となります。f(g(x)) は「x を g に通し、その結果を f に通す」と読みます。

ニューラルネットワークは、この合成を何十段、何百段と重ねたものです。入力に重みを掛ける、足す、曲げる（活性化関数）、また重みを掛ける……と続き、最後に損失が出てきます。だから「重みを少し動かすと損失がどれだけ変わるか」は、**合成関数の微分**の問題になります。

## 連鎖律：回転比を掛け算する

連鎖律は、合成関数の微分を、部品ごとの微分の掛け算で求める規則です。

```
dz/dx = dz/dy × dy/dx
```

記号を読み下します。`dz/dx` は「x を少し動かしたとき、z がその何倍動くか」です。`dy/dx` は「x を少し動かしたとき y が何倍動くか」、`dz/dy` は「y を少し動かしたとき z が何倍動くか」です。式が言っているのは、**x から z への影響は、途中の y を経由した影響の掛け算になる**ということです。

歯車で考えると分かりやすくなります。歯車 A を 1 回転させると歯車 B が 3 回転し、B が 1 回転すると歯車 C が 2 回転するとします。A を 1 回転させたとき C は何回転するか。3 × 2 = 6 回転です。途中の歯車の回転比を、順に掛ければよいわけです。連鎖律は、この回転比の掛け算を、なめらかに曲がる関数に対して言ったものです。曲がっている関数でも、ごく小さな動きに限れば回転比（傾き）は一定とみなせるので、同じように掛け算できます。

先の例で確かめます。`y = 2x` なので `dy/dx = 2`、`z = y + 1` なので `dz/dy = 1`。掛けると `dz/dx = 2` で、`z = 2x + 1` の傾き 2 と一致します。

## 計算を箱に分ける：計算グラフ

連鎖律を機械的に使うために、計算を小さな箱に分けて、箱どうしを矢印でつないだ図を描きます。これを**計算グラフ**と呼びます。

1 つのニューロン（重み w、入力 x、ずらし b）に正解 y を与えて、二乗誤差を損失にする場合で考えます。

```
L = (w·x + b − y)²
```

これを 1 つの演算ずつの箱に分けます。

| 箱 | 計算 | 意味 |
| --- | --- | --- |
| 掛け算 | m = w × x | 入力に重みを掛ける |
| 足し算 | a = m + b | ずらしを足す。これが予測 |
| 引き算 | d = a − y | 予測と正解のずれ |
| 2 乗 | L = d² | ずれの大きさ。これを小さくしたい |

それぞれの箱については、「入力を少し動かすと出力がどれだけ動くか」（局所的な傾き）が簡単に分かります。

| 箱 | 出力 | 局所的な傾き |
| --- | --- | --- |
| 掛け算 m = w × x | w を動かしたとき | x（相手の値） |
| | x を動かしたとき | w（相手の値） |
| 足し算 a = m + b | m、b のどちらを動かしても | 1 |
| 引き算 d = a − y | a を動かしたとき | 1 |
| | y を動かしたとき | −1 |
| 2 乗 L = d² | d を動かしたとき | 2d |

掛け算の箱の傾きが「相手の値」になるのは、たとえば m = w × 2 なら w を 1 増やすと m は 2 増えるからです。

## 前から値を、後ろから勾配を

計算グラフが描ければ、手順は 2 回の通り抜けだけです。

1. **順方向**：入力から出力へ向かって、箱ごとに値を計算する
2. **逆方向**：出力から入力へ向かって、「L をこの箱の出力で微分した値」を受け取り、それに箱の局所的な傾きを掛けて、入力側へ渡す

逆方向で各箱がしていることは、連鎖律そのものです。L を d で微分した値を受け取った 2 乗の箱は、それに自分の傾き 2d を掛けて「L を（d の手前の値で）微分した値」を作り、手前へ渡します。手前の箱も同じことを繰り返します。歯車の例で言えば、出力側の歯車から順に回転比を掛け合わせていくことになります。

この「L をその値で微分したもの」を、以下では**勾配**と呼びます（厳密には勾配は全部の重みについての微分を並べたベクトルを指しますが、その成分の 1 つずつも慣例でこう呼びます）。

### 手で 1 回計算する

SIM と同じ数で、表にしておきます。順方向は次のとおりです。

```
m = w × x     = 0.5 × 2       = 1.0
a = m + b     = 1.0 + 0.1     = 1.1
d = a − y     = 1.1 − 2       = −0.9
L = d²        = (−0.9)²       = 0.81
```

予測は 1.1、正解は 2 なので、0.9 だけ足りません。逆方向は L から始めます。

```
∂L/∂L = 1                          出発点
∂L/∂d = 2d × 1     = 2 × (−0.9)    = −1.8
∂L/∂a = ∂L/∂d × 1                  = −1.8
∂L/∂y = ∂L/∂d × (−1)               = +1.8
∂L/∂m = ∂L/∂a × 1                  = −1.8
∂L/∂b = ∂L/∂a × 1                  = −1.8
∂L/∂w = ∂L/∂m × x  = −1.8 × 2      = −3.6
∂L/∂x = ∂L/∂m × w  = −1.8 × 0.5    = −0.9
```

`∂L/∂w = −3.6` は「w を少し増やすと、L はその 3.6 倍の速さで**減る**」という意味です。予測が足りないのだから、w を増やせば予測が増えてずれが縮む、という直感と合っています。勾配降下法では、重みを勾配と逆の向きに動かします。学習率 0.05 なら w は 0.5 − 0.05 × (−3.6) = 0.68、b は 0.1 − 0.05 × (−1.8) = 0.19 になり、計算し直すと L は 0.81 から 0.2025 に下がります。SIM の最後の手がこの更新です。

なお `∂` は「ラウンド d」や「デル」と読み、変数が複数あるときに「ほかの変数は止めて、この 1 つだけを動かした」微分（偏微分）であることを示す記号です。

## 箱ごとの配り方の規則

手計算をすると、箱の種類ごとに勾配の配り方が決まっていることに気づきます。

- **足し算の箱は、受け取った勾配をそのまま全員に配る**。どの入力を 1 増やしても出力は 1 増えるからです
- **掛け算の箱は、受け取った勾配に「相手の値」を掛けて配る**。w へは x を、x へは w を掛けます
- **引き算の箱は、引かれる側へは符号を反転して配る**
- **関数の箱（2 乗、シグモイドなど）は、その関数の傾きを掛けて配る**

どれも箱の中だけで決まる規則で、グラフ全体を見る必要がありません。だから、どれほど大きなモデルでも、箱の種類ごとに「順方向の計算」と「逆方向の配り方」の 2 つを書いておけば、勾配は自動で求まります。これが PyTorch や JAX などの道具が持っている**自動微分**（automatic differentiation）の仕組みです。

### 同じ値が 2 か所で使われたら、足し合わせる

1 つの値が 2 つの箱に入っていく場合があります。たとえば `z = a × a + a` では、a が掛け算の箱に 2 回、足し算の箱に 1 回入っています。

この場合、a を少し動かすと、3 本の経路のそれぞれを通って z が動きます。全体の影響は、**経路ごとの影響の合計**です。逆方向では、a に戻ってきた勾配をすべて足し合わせます。

```
掛け算の箱から（左の a として）: 相手の値 a = 3
掛け算の箱から（右の a として）: 相手の値 a = 3
足し算の箱から:                    1
合計 dz/da = 3 + 3 + 1 = 7
```

`z = a² + a` を普通に微分すると `2a + 1` で、a = 3 なら 7 です。一致します。

ニューラルネットワークでは、1 つの入力や中間の値が次の層のすべてのニューロンに入っていくので、この「足し合わせ」が至るところで起きます。

## 手元で確かめる：60 行の自動微分

上の規則が正しく動くかを、Python 3.14.0（Apple M1 Pro / macOS 26.2、外部ライブラリなし）で確かめました。値と勾配を 1 つずつ持つ `Value` という小さなクラスを書き、足し算・掛け算・2 乗・シグモイドの 4 種類の箱について、順方向の計算と逆方向の配り方を定義しています。逆方向は、グラフを後ろから順にたどって各箱の配り方を呼ぶだけです。

```python
def __mul__(self, other):
    out = Value(self.data * other.data, (self, other), '*')
    def backward():
        self.grad += other.data * out.grad    # 相手の値を掛けて配る
        other.grad += self.data * out.grad
    out._backward = backward
    return out
```

`+=` になっているのが、「同じ値が何度使われても足し合わせる」の実装です。

先の 1 ニューロンの例で、逆伝播で求めた勾配と、各変数を 0.000001 だけ前後に動かして L の変化を直接測った値（数値微分）を並べると、次のようになりました。

```text
== L = (w*x + b - y)^2,  w=0.5 x=2.0 b=0.1 y=2.0
L = 0.8100
dL/dw (逆伝播) = -3.600000
dL/dx (逆伝播) = -0.900000
dL/db (逆伝播) = -1.800000
dL/dy (逆伝播) = +1.800000
dL/dw (数値微分) = -3.600000
dL/dx (数値微分) = -0.900000
dL/db (数値微分) = -1.800000
dL/dy (数値微分) = +1.800000

== z = a*a + a, a=3
dz/da (逆伝播) = 7.0   (2a + 1 = 7)
```

手計算の値と、逆伝播と、数値微分がすべて一致しています。

## なぜ逆向きなのか

連鎖律は掛け算なので、前から掛けていっても後ろから掛けていっても、答えは同じです。それでも学習では後ろから掛けます。理由は、**入力（重み）がたくさんあって、出力（損失）が 1 つしかない**からです。

前から掛けていく方法（前進モード）では、「w を少し動かしたら、その影響が各箱をどう伝わるか」を前へ運びます。これで分かるのは**動かした 1 つの重み**についての傾きだけです。重みが n 個あれば、n 回通す必要があります。

後ろから掛けていく方法（逆向きのモード）では、「損失がこの値にどれだけ敏感か」を後ろへ運びます。損失は 1 つなので、1 回戻るだけで、途中で出会ったすべての値についての傾きが同時にそろいます。

自動微分の解説論文 Baydin らはこれを、「An important advantage of the reverse mode is that it is significantly less costly to evaluate (in terms of operation count) than the forward mode for functions with a large number of inputs.」（入力の数が多い関数では、逆向きのモードは演算の回数で見て前進モードよりかなり安く済む、という重要な利点を持つ）と書いています（[Baydin et al., Automatic differentiation in machine learning: a survey, JMLR 2018](https://arxiv.org/abs/1502.05767)、3.2 節）。同じ節は、逆向きのモードでかかる計算量を、元の関数の計算量の定数倍で、その定数は 6 未満、典型的には 2〜3 程度だとしています。

### 数えて確かめる

重みが n 個の線形モデル `L = (w₁x₁ + w₂x₂ + … + wₙxₙ − 1)²` で、箱の計算の回数を数えました。逆伝播は、順方向で箱を 1 回ずつ計算し、逆方向で箱ごとに 1 回ずつ配ります。数値微分は、重み 1 つにつき前後 2 回、モデル全体を計算し直します。

```text
 重みの数   順方向の箱   逆伝播の配り   合計      数値微分(2N 回の順方向)  勾配の最大の差
      10          22            22        44                      440   3.6e-11
     100         202           202       404                    40400   2.6e-09
    1000        2002          2002      4004                  4004000   2.0e-08
   10000       20002         20002     40004                400040000   6.6e-08
```

逆伝播の手間は、重みの数に比例して増えるだけです（順方向のちょうど 2 倍）。数値微分の手間は、重みの数の 2 乗に比例して増えます。重み 1 万個で、すでに 1 万倍の差がついています。重みが数十億あるモデルでは、逆伝播以外の方法は現実的ではありません。右端の列は、両方の方法で求めた勾配の差の最大値で、数値微分の丸め誤差の範囲で一致しています。

<Callout type="note" title="数値微分は検算に使う">
  数値微分は、どんな関数にも使えて実装が簡単なので、自分で書いた逆伝播が正しいかを確かめる道具として今も使われます。上の表の右端の列がその使い方です。ただし、動かす幅を小さくしすぎると、計算機の桁の丸めで答えが不正確になります。学習そのものに使うには遅すぎ、不正確すぎます。
</Callout>

## 掛け算が続くと、勾配が消える

逆伝播は「局所的な傾きの掛け算」なので、掛ける数がどれも 1 より小さいと、後ろから戻るほど勾配は小さくなっていきます。

その典型が**シグモイド**です。シグモイドは σ(x) = 1 / (1 + e⁻ˣ) という関数で、どんな数も 0 と 1 の間に押し込めます。かつてはニューラルネットワークの「曲げる」部分の定番でした。この関数の傾きは σ(x)(1 − σ(x)) で、最大でも x = 0 のときの 0.25 です。つまり、シグモイドの箱を 1 つ通るたびに、勾配は少なくとも 4 分の 1 になります。

先の自動微分で、入力 0.5 にシグモイドを n 段重ねたとき、出力を入力で微分した値を測りました。

```text
== シグモイドを n 段重ねたときの d(出力)/d(入力)、入力 0.5
 段数     出力        勾配
   1  0.622459  2.350e-01
   2  0.650778  5.341e-02
   3  0.657186  1.203e-02
   5  0.658952  6.080e-04
  10  0.659046  3.483e-07
  15  0.659046  1.995e-10
  20  0.659046  1.143e-13
```

10 段で約 1000 万分の 1、20 段で約 10 兆分の 1 です。入力に近い側の重みは、損失がほとんど伝わってこないので、ほぼ動かなくなります。これが**勾配消失**です。反対に、掛ける数が 1 より大きいと、勾配は段ごとに膨らんで発散します（勾配爆発）。

Glorot と Bengio は 2010 年の論文で、深いネットワークの学習が難しい原因を調べ、「We find that the logistic sigmoid activation is unsuited for deep networks with random initialization because of its mean value, which can drive especially the top hidden layer into saturation.」（ロジスティックシグモイドの活性化は、ランダムに初期化した深いネットワークには向かない。その平均値のせいで、特に最上位の隠れ層が飽和に追い込まれうる）と述べています（[Glorot and Bengio, Understanding the difficulty of training deep feedforward neural networks, AISTATS 2010](https://proceedings.mlr.press/v9/glorot10a.html)）。「飽和」とは、シグモイドの出力が 0 か 1 に張り付き、傾きがほぼ 0 になった状態のことです。

その後の深層学習は、この掛け算の連鎖を壊れにくくする工夫を積み重ねてきました。傾きが 0 か 1 しかない活性化関数（ReLU）を使う、重みの初期値の大きさを層の幅に合わせて選ぶ、層ごとに値の大きさをそろえ直す（正規化）、入力をそのまま先へ足し込む近道を作る（残差接続。足し算の箱は勾配をそのまま配るので、近道を通る勾配は小さくならない）、といった工夫です。どれがいつ、どの論文で出てきたかは、歴史トラックの回でたどります。

## まとめ

- ニューラルネットワークは合成関数を何段も重ねたもので、学習にはすべての重みについての損失の傾き（勾配）が要る
- 連鎖律は、合成関数の傾きを、途中の部品の傾き（回転比）の掛け算で求める規則
- 計算を小さな箱に分けた計算グラフにすると、各箱の局所的な傾きはその箱だけで決まる
- 順方向で値を前から計算し、逆方向で「損失をこの値で微分したもの」を後ろから配る。足し算はそのまま、掛け算は相手の値を掛けて、関数はその傾きを掛けて配る
- 同じ値が複数の箇所で使われたら、戻ってきた勾配を足し合わせる
- 出力が 1 つで入力が多いので、後ろから戻れば 1 往復で全部の勾配がそろう。手間は順方向の定数倍で、数値微分のように重みの数に比例して何度も計算し直さない
- 1 より小さい傾きを何度も掛けると勾配が消える。シグモイドの傾きは最大 0.25 で、20 段で約 10 兆分の 1 になった
