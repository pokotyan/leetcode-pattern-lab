## まず、困っている状況を体験してみます

> `a = 1071` と `b = 462` の最大公約数を求めてください。

学校で習ったやり方は、たぶんこうです。両方を素因数分解して、共通する素因数を掛け合わせる。

`1071 = 3 × 3 × 7 × 17`、`462 = 2 × 3 × 7 × 11`

共通するのは 3 と 7 なので、答えは 21 です。正しく求まりました。

問題は、この方法が**素因数分解を必要とする**ことです。素因数分解は O(√N) かかります。`a` と `b` が 10<sup>18</sup> まであると、√N は 10<sup>9</sup> になり、1組を調べるだけで終わりません。

しかも、私たちが欲しいのは「共通する素因数の一覧」ではなく、**最大公約数という1つの数**だけです。素因数分解は、必要以上の情報を求めていることになります。

## 発想を変える：余りで置き換える

ここで、公約数について1つの性質を確かめます。

> `a` と `b` の公約数は、`b` と `a % b` の公約数と**完全に一致する**

なぜでしょうか。`a` を `b` で割った商を `q`、余りを `r` とすると、`a = qb + r` です。

- `b` と `r` の両方を割り切る数 `d` があれば、`a = qb + r` の右辺は両方 `d` の倍数なので、`a` も `d` で割り切れます
- 逆に `a` と `b` の両方を割り切る `d` があれば、`r = a - qb` の右辺は両方 `d` の倍数なので、`r` も `d` で割り切れます

つまり、**公約数の集合そのものが同じ**です。最大公約数も当然同じになります。

この置き換えを繰り返すと、数はどんどん小さくなります。`a % b` は必ず `b` より小さいからです。いつかは 0 になり、そのとき残っているほうが答えです（`gcd(x, 0) = x`。0 はどんな数でも割り切れるため）。

```python
def gcd(a, b):
    while b:
        a, b = b, a % b          # 大きいほうを「余り」で置き換える
    return a

def lcm(a, b):
    return a // gcd(a, b) * b    # 先に割ってから掛ける（あふれ対策）
```

<EuclidGcd client:visible />

`1071` と `462` を選んで、数がどれだけ速く小さくなるか見てみてください。

1. `gcd(1071, 462)` → `1071 % 462 = 147`
2. `gcd(462, 147)` → `462 % 147 = 21`
3. `gcd(147, 21)` → `147 % 21 = 0`
4. `b` が 0 になったので、答えは `21`

**わずか3回の割り算**です。素因数分解は一度もしていません。

<Callout type="tip" title="なぜこんなに速いのか">
  互除法の回数は、多くても `O(log(min(a, b)))` です。

  理由の要点だけ書くと、2回の置き換えで値が**半分以下になる**からです。`a % b` は `b` より小さいので、`a` が `b` の2倍以上なら余りは一気に小さくなりますし、`a` が `b` の2倍未満なら `a % b = a - b` が `a/2` 未満になります。どちらにしても、2ステップで半分です。

  最悪ケースは連続するフィボナッチ数（`gcd(F(n+1), F(n))`）で、このとき回数がちょうど `n` になります。それでも `10^18` の範囲で 87 回程度です。
</Callout>

<Callout type="warn" title="最小公倍数は、掛けてから割ってはいけません">
  `lcm(a, b) = a × b / gcd(a, b)` は正しい式ですが、**この順番で書くと危険**です。`a` と `b` がどちらも 10<sup>9</sup> 程度あると、`a × b` は 10<sup>18</sup> になり、言語によってはあふれます。

  ```python
  a * b // gcd(a, b)      # 先に掛けるのであぶない
  a // gcd(a, b) * b      # 先に割るので安全
  ```

  `a` は `gcd(a, b)` で必ず割り切れるので、先に割っても誤差は出ません。**割れると分かっているものは先に割る**、という習慣にしておくと事故が減ります。

  なお、3つ以上の最小公倍数は `lcm(lcm(a, b), c)` と順に畳めますが、**結果が爆発的に大きくなる**ことがあります。問題文に余りを取る指示があるかどうかを確認してください。
</Callout>

## 数字で確かめる：3つ以上の GCD

GCD は結合的なので、3つ以上でもそのまま畳めます。

`gcd(12, 18, 30) = gcd(gcd(12, 18), 30) = gcd(6, 30) = 6`

Python なら `math.gcd` に複数渡すか、`functools.reduce` で畳みます。

```python
from functools import reduce
from math import gcd

g = reduce(gcd, nums)
```

ここで知っておくと便利な性質が1つあります。**GCD は、要素を足していくと単調に減る（または変わらない）**ということです。一度 1 になったら、それ以降は何を足しても 1 のままです。「全体の GCD が 1 かどうか」を聞く問題（Check If It Is a Good Array）では、この性質でループを打ち切れます。

## 典型的な使いどころ

### 周期をそろえる

> `str1` と `str2` がどちらも、同じ文字列 `t` の繰り返しでできているとき、最長の `t` を求めてください。

答えの長さは、**`len(str1)` と `len(str2)` の GCD** です。`t` の長さは両方の長さを割り切らなければならず、その中で最大のものを選ぶからです。

```python
def gcd_of_strings(str1, str2):
    if str1 + str2 != str2 + str1:      # そもそも同じ t から作れるか
        return ""
    return str1[:gcd(len(str1), len(str2))]
```

最初の1行が効いています。`str1 + str2 == str2 + str1` が成り立つのは、2つが同じ文字列の繰り返しであるとき**だけ**です。これを確認してしまえば、あとは長さの GCD を取るだけで答えの長さが決まります。

### 既約分数にそろえる

> 平面上の点が与えられます。同一直線上にある点の最大数を求めてください。

2点を結ぶ直線の傾きをキーにして数えたいのですが、傾きを浮動小数点で持つと誤差で一致判定が壊れます。そこで、**分数のまま持ちます。**

```python
dx = x2 - x1
dy = y2 - y1
g = gcd(abs(dx), abs(dy))
key = (dx // g, dy // g)        # 既約分数にそろえる
```

`gcd` で割らないと、`(1, 2)` と `(2, 4)` が別のキーになってしまい、同じ傾きなのに別々に数えられます。

<Callout type="warn" title="符号の正規化も忘れずに">
  既約分数にしただけでは足りません。`(1, 2)` と `(-1, -2)` は同じ傾きですが、キーとしては別物です。

  ```python
  if dx < 0 or (dx == 0 and dy < 0):
      dx, dy = -dx, -dy          # 向きをそろえる
  ```

  「分母（`dx`）が負なら両方の符号を反転する」と決めて、`dx == 0` の場合（垂直な直線）も別途そろえます。**キーにする前に、同じものが必ず同じ形になるまで正規化する**、というのはハッシュを使う問題すべてに共通する注意点です。
</Callout>

## この知識を使う場面

| 場面 | 使い方 |
| --- | --- |
| 「繰り返しでできているか」 | 長さの GCD が周期の候補 |
| 傾き・比率をキーにする | GCD で割って既約分数にし、符号もそろえる |
| 「同時に起きるのはいつか」 | 周期の LCM |
| 「公約数が 1 より大きい数をつなぐ」 | GCD > 1 を辺と見なして Union-Find |
| 「操作で作れる数は何か」 | 全体の GCD の倍数がすべて作れる |

最後の行は、一次不定方程式の性質から来ています。詳しくは拡張ユークリッドのノートで扱いますが、**「`a` と `b` を足したり引いたりして作れる数は、`gcd(a, b)` の倍数だけ」**という事実は、単独でもよく使います。
