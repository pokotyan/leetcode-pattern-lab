## まず、困っている状況を体験してみます

> `1` から `n` までの数が入った、長さ `n + 1` の配列があります。**重複している数を 1 つ見つけてください。**

「本当に重複があるのか」を確かめる必要はありません。**必ずあります。** 入る値は `n` 通りしかないのに、要素は `n + 1` 個あるからです。

これが鳩の巣原理です。

> `n` 個の箱に `n + 1` 個のものを入れると、**2 個以上入っている箱が必ず存在する**

当たり前に見えますが、この当たり前が強力なのは、**探す前に「ある」と言い切れる**点です。存在が保証されていれば、あとは「どこにあるか」を探すだけの問題になります。

この記事では、こうした「数える前に結論が出る」道具を 3 つ扱います。どれも、**探索を始める前に問題の形を変えてしまう**ために使います。

## 鳩の巣原理：箱より多く入れれば重なる

使い方の型は、いつも同じです。

1. **何が「箱」か**を決める（取りうる値の種類）
2. **何が「もの」か**を決める（調べる対象の個数）
3. もの > 箱 なら、重なりが必ず存在する

典型例を見ます。

> 配列の中に、**連続する部分配列で和が `k` の倍数になるもの**があるか判定してください。長さは 2 以上とします。

累積和 `P[0], P[1], ..., P[n]` を考えます。区間 `[l, r]` の和が `k` の倍数であることは、

`P[r+1] − P[l] ≡ 0 (mod k)`、つまり `P[r+1] ≡ P[l] (mod k)`

と言い換えられます。**累積和を `k` で割った余りが同じ 2 箇所を見つければよい**わけです。

ここで箱と物を数えます。余りは `0` から `k−1` までの **`k` 通り**（箱）。累積和は **`n+1` 個**（もの）。したがって `n + 1 > k` なら、**必ずどこかに同じ余りの組が存在します。**

```python
def check_subarray_sum(nums, k):
    seen = {0: -1}                 # 余り -> それが最初に出た位置
    total = 0
    for i, x in enumerate(nums):
        total = (total + x) % k    # 余りは k 通りしかない
        if total in seen:
            if i - seen[total] >= 2:
                return True        # 同じ余りが2回 = その間の和が k の倍数
        else:
            seen[total] = i
    return False
```

<PrefixModPigeonhole client:visible />

<Callout type="warn" title="seen に最初の位置だけを残す理由">
  `else: seen[total] = i` となっていて、**すでにある余りは上書きしません。** これは意図的です。

  求めたいのは「長さ 2 以上」という条件を満たす組なので、同じ余りが複数回出るなら、**いちばん古い位置**と組むのが最も長くなり、条件を満たしやすくなります。上書きしてしまうと、間隔が短くなって取りこぼします。

  また、`seen = {0: -1}` という初期値も重要です。「先頭からの部分配列」を扱うために、位置 `-1` に余り 0 が入っていることにしています。これを忘れると、配列の先頭から始まる答えを見落とします。
</Callout>

## パリティ：偶数か奇数かだけを見る

2 つ目の道具は、**偶奇（パリティ）**です。細かい値を捨てて「偶数か奇数か」だけを追うと、不可能なことが一瞬で分かる場合があります。

> 8 × 8 のチェス盤から、**対角の 2 マス**を取り除きました。残り 62 マスを、1 × 2 のドミノで隙間なく敷き詰められますか。

面積は 62 で偶数なので、31 枚で足りそうに見えます。ところが**できません。**

チェス盤を白黒に塗り分けると、対角の 2 マスは**必ず同じ色**です。つまり残りは「白 30・黒 32」のように偏ります。一方、ドミノは 1 枚で必ず白 1・黒 1 を覆います。31 枚なら白 31・黒 31 でなければならず、矛盾します。

**数え上げも探索も一切せずに「不可能」と結論できました。** これがパリティの威力です。

競技プログラミングでよく出る形はこうです。

- 「この操作を繰り返して状態 A から状態 B にできるか」→ 操作で**変わらない偶奇**を探す
- 「2 人が交互に取るゲームでどちらが勝つか」→ 手数の偶奇で決まることが多い
- 「入れ替えで並べ替えられるか」→ 置換の偶奇（転倒数の偶奇）は入れ替え 1 回で必ず反転する

## 不変量：操作しても変わらない量を探す

パリティを一般化したものが**不変量**です。

> 何度操作をしても**値が変わらない量**を見つけられれば、その値が違う 2 つの状態は、絶対に行き来できない

`Valid Parenthesis String` を例にします。

> `(`、`)`、`*` からなる文字列があります。`*` は `(`、`)`、空文字のどれにでもなれます。全体が正しい括弧列になりうるか判定してください。

`*` の解釈が 3 通りあるので、全探索すると 3<sup>n</sup> です。ここで、**「開いたままの括弧の数」が取りうる範囲**を不変量として持ちます。

- `lo`：`*` をすべて `)` と解釈したときの、開いている数
- `hi`：`*` をすべて `(` と解釈したときの、開いている数

1 文字進むごとに、この範囲を更新します。

```python
def check_valid_string(s):
    lo = hi = 0
    for ch in s:
        lo += 1 if ch == '(' else -1
        hi += 1 if ch != ')' else -1
        if hi < 0:
            return False        # どう解釈しても閉じすぎ
        lo = max(lo, 0)         # 負の開き数はありえない
    return lo == 0              # 0 を作れるか
```

**範囲そのものを状態として持つ**ことで、3<sup>n</sup> の探索が O(N) になりました。各文字で `lo` と `hi` がどう動くかという規則が、ここでの不変量です。

<Callout type="tip" title="不変量を探す手順">
  「操作を繰り返して目標に到達できるか」という問題を見たら、次を順に試してください。

  1. **総和**は変わるか。変わるなら、どう変わるか（毎回 +2 なら偶奇が不変）
  2. **偶奇**は変わるか
  3. **何かで割った余り**は変わるか
  4. **順序に関する量**（転倒数など）は変わるか
  5. **範囲**（取りうる値の最小と最大）で表せるか

  1 つでも「操作しても変わらない」ものが見つかれば、出発点と目標でその値を比べるだけで、可能・不可能が決まります。
</Callout>

## 存在の保証と、場所の特定を分ける

冒頭の重複を探す問題に戻ります。

> `1` から `n` までの数が入った長さ `n+1` の配列から、重複している数を見つけてください。**配列は変更できず、O(1) の追加メモリで。**

鳩の巣原理から、重複の**存在**は保証されています。残るのは「どこか」を O(1) メモリで特定する部分です。

ここで発想を変えます。`i` 番目の要素の値を「次に行く場所」と読むと、配列が**連結リスト**になります。値は `1` から `n` なので、位置 0 から出発すると必ずその範囲をぐるぐる回ります。そして重複があるということは、**2 箇所から同じ場所へ入る道がある**、つまりサイクルがあるということです。

サイクルの入口を求める問題になったので、連結リストのノートでやった Floyd の速さの違う 2 つのポインタがそのまま使えます。

**「存在は鳩の巣で保証し、特定は別の道具で行う」**という分担が、この問題の設計です。数学が探索の前提を作り、アルゴリズムがその中で動く、という関係になっています。

## この知識を使う場面

| 見かけた形 | 使う道具 |
| --- | --- |
| 「必ず存在することを示せ」「重複が必ずある」 | 鳩の巣原理（箱の数 vs ものの数） |
| 「和が k の倍数になる部分配列」 | 累積和の余りで鳩の巣 |
| 「この操作で目標に到達できるか」 | 不変量・パリティ |
| 「敷き詰められるか」「塗り分け」 | パリティ（市松模様） |
| 交互に手を打つゲーム | 手数の偶奇 |
| 有限の状態をたどり続ける | 必ずサイクルに入る |
