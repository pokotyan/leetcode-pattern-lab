## まず、困っている状況を体験してみます

数え上げの問題を解いていると、こういう一文に必ず出会います。

> 答えは非常に大きくなる可能性があるため、**10<sup>9</sup> + 7 で割った余り**を返してください。

初めて見たとき、これは「答えが大きいので、適当に小さくしてほしいという主催者の都合」に見えます。実際そうなのですが、なぜ**その形**でなければならないのかを考えると、もう少し事情があります。

具体的に困ってみましょう。「1 から 5 までの数を好きな順に並べる方法は何通りか」なら 120 通りです。では 25 個ではどうでしょうか。

`25! = 15,511,210,043,330,985,984,000,000`

26 桁です。コンピュータが普通に扱える整数（64 bit）で表せるのは、だいたい 19 桁までです。つまり `21!` あたりで**すでにあふれています**。あふれた値は、言語によって静かに壊れた数になったり（C++ や Java）、勝手に多倍長へ切り替わって極端に遅くなったり（Python）します。

数え上げの問題で答えが 10<sup>100</sup> を超えるのは珍しくありません。**そもそも答えそのものを持てない**のです。

## 発想を変える：答えの「余り」だけを持ち歩く

そこで、答えの代わりに「ある数 M で割った余り」を持ちます。余りなら必ず 0 以上 M 未満なので、どれだけ計算しても大きさが一定に保たれます。

ただし、これが成立するには条件があります。**途中で余りを取ってしまって、最後の答えの余りと一致するのか**、という点です。

ここは、実際に確かめてみるのが早いです。次の関係が成り立ちます。

```
(a + b) % M == ((a % M) + (b % M)) % M
(a - b) % M == ((a % M) - (b % M) + M) % M
(a * b) % M == ((a % M) * (b % M)) % M
```

つまり、**足し算・引き算・掛け算は、いつ余りを取っても結果が変わりません。** 最後にまとめて取っても、毎回取っても同じです。

<ModDistribute client:visible />

左が素直に掛け続けた値、右が毎回余りに畳んだ値です。左は桁数がどんどん増えていくのに、右は常に 10 桁以内に収まっています。そして最後、左を MOD で割った余りは右と一致します。**大きい数を経由する必要が、そもそも無かった**わけです。

<Callout type="warn" title="引き算だけは、そのままだと負になります">
  `(a - b) % M` を素直に書くと、`a % M` が `b % M` より小さいときに**負の値**が出てきます。Python の `%` は結果が必ず 0 以上になるので気づきにくいのですが、C++ や Java では負のまま返ります。

  ```python
  x = (a - b) % M          # Python なら問題ない
  x = ((a - b) % M + M) % M  # どの言語でも安全な書き方
  ```

  余りを扱うコードでは、**引き算のたびに M を足してからもう一度余りを取る**と決めてしまうのが安全です。配列の添字に使う場合、負の値は静かに末尾を指すので、原因の分かりにくいバグになります。
</Callout>

## なぜ 10<sup>9</sup> + 7 なのか

割る数として 10<sup>9</sup> + 7 が選ばれるのには、はっきりした理由があります。

1. **素数である。** これが最大の理由です。あとで出てくる「割り算の代わり」が、素数のときにだけ簡単に作れます
2. **32 bit に収まる。** 10<sup>9</sup> + 7 は約 2 × 10<sup>9</sup> より小さいので、int の範囲に入ります
3. **2乗しても 64 bit に収まる。** 余り同士の掛け算は最大で (10<sup>9</sup>)<sup>2</sup> = 10<sup>18</sup> 程度になります。64 bit の上限は約 9.2 × 10<sup>18</sup> なので、ぎりぎり収まります

3 番目が効いています。もし割る数が 10<sup>18</sup> だったら、余り同士を掛けた瞬間にあふれてしまい、意味がありません。**「掛け算しても壊れない上限」から逆算して選ばれた数**なのです。

同じ理由で 998244353 という数もよく使われます（こちらは高速フーリエ変換と相性がよいという別の事情があります）。

## べき乗を速くする：繰り返し二乗法

余りの世界での計算のうち、足し算と掛け算は素直に書けます。困るのは**べき乗**です。

> `a^b mod M` を求めてください。ただし `b` は 10<sup>18</sup> まであります。

`a` を `b` 回掛ければ答えは出ますが、10<sup>18</sup> 回のループは終わりません。

ここで、指数を**2進法で分解**します。たとえば `b = 13` は 2進法で `1101` なので、

`a^13 = a^8 × a^4 × a^1`

と書けます。そして `a^1 → a^2 → a^4 → a^8` は、**前の値を2乗するだけ**で順に作れます。必要なのは「2乗する回数」と「掛け合わせる回数」だけなので、どちらも指数の**ビット数ぶん**、つまり O(log b) で済みます。

```python
def power(a, b, mod):
    result = 1
    a %= mod
    while b > 0:
        if b & 1:                 # b の一番下のビットが 1 なら
            result = result * a % mod
        a = a * a % mod           # a を2乗して、担当する桁を1つ上げる
        b >>= 1                   # b を1ビット右へ送る
    return result
```

<FastPow client:visible />

`b = 13` のとき、ビットは下から `1, 0, 1, 1` です。0 の桁では `result` に何も掛けず、`a` を2乗するだけで通過している様子を確認してみてください。10<sup>18</sup> 回のループが、たった 60 回程度になります。

<Callout type="tip" title="Python には組み込みの pow があります">
  Python では `pow(a, b, mod)` と3つ目の引数を渡すだけで、この繰り返し二乗法が走ります。実務でもコンテストでも、これを使って構いません。

  それでも仕組みを知っておく価値があるのは、**同じ形が「行列のべき乗」にそのまま使えるから**です。数をかけ算するところを行列の積に置き換えるだけで、線形漸化式の DP を O(log N) にできます。これは別のノートで扱います。
</Callout>

## 割り算はどうするのか：逆元

足す・引く・掛けるは余りと交換できました。では**割り算**はどうでしょうか。

```
(a / b) % M == ((a % M) / (b % M)) % M     ← 成り立ちません
```

`6 / 3 = 2` を M = 5 で考えると、左辺は `2 % 5 = 2` です。右辺は `(6 % 5) / (3 % 5) = 1 / 3` となり、そもそも整数ですらありません。**割り算だけは、余りの世界にそのまま持ち込めません。**

ところが、数え上げの問題では割り算が必要になります。組合せの数 <sub>n</sub>C<sub>r</sub> は `n! / (r! × (n-r)!)` なので、階乗の割り算が出てくるからです。

そこで、**割り算を掛け算に置き換えます。** 実数の世界で「3 で割る」ことと「1/3 を掛ける」ことが同じであるように、余りの世界にも「掛けると 1 になる相手」があります。

> `b × x ≡ 1 (mod M)` を満たす `x` を、`b` の**逆元**と呼び、`b⁻¹` と書きます。

この `x` が見つかれば、`a / b` の代わりに `a × x` を計算すればよいことになります。

M が**素数**のとき、逆元はフェルマーの小定理から簡単に求まります。

> M が素数で、b が M の倍数でないなら、`b^(M-1) ≡ 1 (mod M)`

両辺を `b` で割った形にすると、`b^(M-2) ≡ b⁻¹` です。つまり、**逆元は `b` の `M-2` 乗**であり、さきほどの繰り返し二乗法でそのまま計算できます。

```python
def inv(b, mod):
    return pow(b, mod - 2, mod)   # mod が素数のときだけ使える
```

小さい数で確かめてみます。M = 7、b = 3 のとき、逆元は `3^5 mod 7` です。

`3^5 = 243`、`243 mod 7 = 5`

検算すると `3 × 5 = 15`、`15 mod 7 = 1`。確かに 1 になりました。シミュレーターの「逆元 3^5 mod 7」の入力で、この計算を1手ずつ追えます。

<Callout type="warn" title="逆元が使える条件を、毎回確認してください">
  `pow(b, M - 2, M)` で逆元が求まるのは、**M が素数**で、かつ **b が M の倍数でない**ときだけです。

  - M が素数でない場合（たとえば M = 12）は、この式は使えません。拡張ユークリッドの互除法を使います（別のノートで扱います）
  - b が M の倍数のとき（`b % M == 0`）は、逆元がそもそも存在しません。0 で割ろうとしているのと同じです

  LeetCode の問題はほぼ例外なく 10<sup>9</sup> + 7 を使うので、実戦では「素数だからフェルマーで済む」と考えて問題ありません。**なぜ素数だと楽なのか**を説明できる状態にしておけば十分です。
</Callout>

## この知識を使う場面

| 場面 | 使い方 |
| --- | --- |
| 数え上げの DP | 遷移のたびに `dp[i] = (dp[i] + dp[j]) % MOD` と畳む |
| 組合せの数 | 階乗を前計算し、割り算は逆元の掛け算に置き換える |
| ローリングハッシュ | 文字列を大きな整数と見なし、余りで潰して比較する |
| 巨大なべき乗 | 繰り返し二乗法。指数が 10<sup>18</sup> でも 60 回程度 |
| 周期の利用 | 「N 回後の状態」を、周期で割った余りに置き換える |
