## まず、困っている状況を体験してみます

剰余演算のノートで、逆元をフェルマーの小定理から求めました。

```python
def inv(b, mod):
    return pow(b, mod - 2, mod)   # mod が素数のときだけ使える
```

条件が付いていました。**`mod` が素数でなければ使えません。**

たとえば `mod = 12` のとき、`5` の逆元（`5x ≡ 1 (mod 12)` を満たす `x`）は存在します（`x = 5`。`25 = 24 + 1` なので）。しかしフェルマーの小定理は素数を前提にしているので、この方法では求まりません。

必要なのは、もっと一般的な道具です。

## ベズーの等式：ax + by = gcd(a, b) には必ず解がある

出発点は、次の事実です。

> 任意の整数 `a`、`b` に対して、`ax + by = gcd(a, b)` を満たす整数 `x`、`y` が**必ず存在する**

`a = 240`、`b = 46` なら `gcd = 2` で、`240 × (−1) + 46 × 5 = −240 + 230 = −10`……これは違います。正しくは `240 × 6 + 46 × (−31) = 1440 − 1426 = 14`……これも違います。手で探すのは大変です。

ここで重要なのは、**互除法の計算そのものが、この係数を教えてくれる**という点です。

## 拡張ユークリッド：戻りながら係数を作る

互除法は `gcd(a, b) = gcd(b, a % b)` を繰り返して `b` が 0 になるまで降りていきました。降りきったところでは、

`gcd(a, 0) = a`、つまり `a × 1 + 0 × 0 = a`

なので、係数は `x = 1`、`y = 0` だと分かります。あとは、ここから**1 段ずつ戻りながら係数を作り直します。**

1 段下（`b`, `a % b`）の答えが `b × x₁ + (a % b) × y₁ = g` だったとします。ここに `a % b = a − (a // b) × b` を代入すると、

```
b × x₁ + (a − (a // b) × b) × y₁ = g
a × y₁ + b × (x₁ − (a // b) × y₁) = g
```

`a` と `b` の係数として読み直せば、

- `x = y₁`
- `y = x₁ − (a // b) × y₁`

です。これをコードにすると、そのまま再帰になります。

```python
def ext_gcd(a, b):
    if b == 0:
        return a, 1, 0               # a×1 + 0×0 = a
    g, x1, y1 = ext_gcd(b, a % b)
    x = y1
    y = x1 - (a // b) * y1           # 係数を1段ぶん戻す
    return g, x, y
```

行が下に伸びていくのが「降りる」段階、下から色が付いていくのが「戻る」段階です。各段で `ax + by` を計算した列が、常に `gcd` と一致していることを確認してみてください。

<Callout type="tip" title="逆元は、この係数の x そのものです">
  `ax + by = 1`（`a` と `b` が互いに素なとき）という式を、`mod b` で見てみます。`by` の項は `b` の倍数なので余りの世界では消えて、

  `ax ≡ 1 (mod b)`

  つまり **`x` が `a` の逆元**です。

  ```python
  def inv(a, m):
      g, x, _ = ext_gcd(a, m)
      if g != 1:
          return None          # 互いに素でなければ逆元は存在しない
      return x % m             # 負になりうるので余りを取り直す
  ```

  `mod` が素数である必要はありません。必要なのは **`a` と `mod` が互いに素**であることだけです。素数の場合はどの `a`（`mod` の倍数を除く）でも互いに素になるので、フェルマーが使える、という関係になっています。

  最後に `x % m` としているのは、`x` が負で返ることがあるためです。ここを忘れると、配列の添字などで静かに壊れます。
</Callout>

## 一次不定方程式：`ax + by = c` が解ける条件

ベズーの等式から、もう 1 つ重要な結論が出ます。

> `ax + by = c` が整数解を持つのは、**`c` が `gcd(a, b)` の倍数**であるとき、かつそのときに限る

「そのときに限る」の部分は簡単です。`a` も `b` も `gcd(a,b)` の倍数なので、左辺は必ず `gcd(a,b)` の倍数になります。したがって `c` がそうでなければ解けません。

逆に `c = k × gcd(a,b)` なら、ベズーの解を `k` 倍すれば解になります。

これが `Water and Jug Problem` の正体です。

> 容量 `x` と `y` の 2 つの水差しを使って、ちょうど `z` リットルを量れますか。

水を移す操作は、結局「`x` を足す・引く」「`y` を足す・引く」の組み合わせなので、作れる量は `ax + by` の形です。したがって、**`z` が `gcd(x, y)` の倍数**であれば作れます（かつ `z ≤ x + y` であれば）。

```python
def can_measure_water(x, y, z):
    if z > x + y:
        return False
    return z % gcd(x, y) == 0
```

**水の移し替えを1回もシミュレートせずに、判定が終わりました。** 不変量の考え方（鳩の巣原理・パリティ・不変量のノート）とも通じます。「操作で作れる量は gcd の倍数だけ」という不変量を見つけた、と読めます。

## 中国剰余定理：余りの条件をまとめる

最後に、複数の余りの条件を 1 つにまとめる道具です。

> `x ≡ 2 (mod 3)`、`x ≡ 3 (mod 5)`、`x ≡ 2 (mod 7)` を満たす最小の正の整数 `x` は？

答えは `23` です。素直に探すなら 1 から順に試せばよく、実際 `mod` が小さければそれで十分です。

中国剰余定理は、**`mod` どうしが互いに素であれば、解が `mod` の積の範囲にちょうど 1 つ存在する**ことを保証します。上の例なら `3 × 5 × 7 = 105` の範囲にちょうど 1 つ、つまり `23` です（`128`、`233` なども条件を満たしますが、これらは `23 + 105k` の形です）。

2 つの式をまとめる手順だけ示します。

```python
def crt(r1, m1, r2, m2):
    # x ≡ r1 (mod m1), x ≡ r2 (mod m2) をまとめる
    g, p, _ = ext_gcd(m1, m2)
    if (r2 - r1) % g != 0:
        return None, None            # 解なし
    lcm = m1 // g * m2
    tmp = (r2 - r1) // g * p % (m2 // g)
    r = (r1 + m1 * tmp) % lcm
    return r, lcm
```

3 つ以上ある場合は、2 つずつ順にまとめていけば済みます。ここで拡張ユークリッドの係数が使われている点に注目してください。**「`m1` の倍数を足して `r2` に合わせる」ために、`m1` の `mod m2` での逆元が要る**からです。

<Callout type="warn" title="mod が互いに素でない場合">
  中国剰余定理の教科書的な主張は「`mod` どうしが互いに素なら」という条件付きですが、上のコードはそうでない場合も扱えます。`(r2 - r1) % g != 0` で解の有無を判定しているのがその部分です。

  たとえば `x ≡ 1 (mod 4)` と `x ≡ 2 (mod 6)` は、`gcd(4,6) = 2` で `(2−1) % 2 = 1 ≠ 0` なので**解なし**です。実際、前者は奇数を、後者は偶数を要求しているので、両立しません。

  「解が必ずある」と思い込んで進むと、この矛盾するケースを取りこぼします。
</Callout>
