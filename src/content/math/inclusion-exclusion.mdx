## まず、困っている状況を体験してみます

> 1 から 30 までの整数のうち、**2 か 3 か 5 で割り切れるもの**はいくつありますか。

30 個なら数えられますが、これが「1 から 10<sup>9</sup> まで」だったらどうでしょうか。1 つずつ確かめることはできません。

素直に足してみます。

- 2 の倍数：`30 // 2 = 15` 個
- 3 の倍数：`30 // 3 = 10` 個
- 5 の倍数：`30 // 5 = 6` 個
- 合計：**31 個**

ところが実際に数えると **22 個**です。9 個も多く数えています。

理由は明らかで、**6（2 と 3 の両方の倍数）を 2 回数えている**からです。10 も、15 も、30 も同様です。重なっている分を補正しなければなりません。

## 発想を変える：足しすぎた分を引き、引きすぎた分を足す

2 つの集合なら簡単です。

`|A ∪ B| = |A| + |B| − |A ∩ B|`

両方に入っているものを 2 回数えたので、1 回ぶん引きます。

3 つになると、もう一段の補正が要ります。

`|A ∪ B ∪ C| = |A| + |B| + |C| − |A∩B| − |B∩C| − |A∩C| + |A∩B∩C|`

最後の項が重要です。**3 つすべてに入っているもの**を追いかけてみます。

- 最初の 3 項で、**3 回**足されている
- 次の 3 項で、**3 回**引かれている
- ここまでで合計 **0 回**。1 回も数えられていない状態になってしまった
- だから最後に **1 回**足し戻す

```python
from math import gcd

def count_divisible(n, a, b, c):
    def lcm(x, y):
        return x // gcd(x, y) * y

    return (n // a + n // b + n // c
            - n // lcm(a, b) - n // lcm(b, c) - n // lcm(a, c)
            + n // lcm(lcm(a, b), c))
```

<InclusionExclusion client:visible />

緑が「この項で足した数」、赤が「この項で引いた数」です。6 の倍数が 2 回緑になったあと赤で 1 回引かれ、30 が 3 回緑・3 回赤のあとで最後にもう一度足される様子を追ってみてください。

<Callout type="tip" title="なぜ符号が交互になるのか">
  `k` 個すべてに属する要素が、何回数えられるかを考えます。

  - 1 つ選ぶ項で <sub>k</sub>C<sub>1</sub> 回足される
  - 2 つ選ぶ項で <sub>k</sub>C<sub>2</sub> 回引かれる
  - 3 つ選ぶ項で <sub>k</sub>C<sub>3</sub> 回足される
  - ……

  合計は `C(k,1) − C(k,2) + C(k,3) − ...` です。二項定理から `(1−1)^k = 0`、つまり `C(k,0) − C(k,1) + C(k,2) − ... = 0` なので、移項すると **`C(k,1) − C(k,2) + ... = C(k,0) = 1`** になります。

  つまり、どの要素も**ちょうど 1 回だけ**数えられます。これが符号を交互にする理由です。組合せのノートの二項係数が、ここで効いてきます。
</Callout>

一般形はこうなります。

> `n` 個の集合の和集合の大きさ = Σ（`k` 個を選ぶすべての組み合わせについて）(−1)<sup>k+1</sup> × その `k` 個の共通部分の大きさ

項の数は 2<sup>n</sup> − 1 個です。したがって、**集合の数が 20 を超えると項が爆発します**。bit DP と同じ制約感覚になります。

## 二分探索の中に組み込む

包除原理が最も効くのは、**単独ではなく、判定関数の中に置かれたとき**です。

> `a`、`b`、`c` のいずれかで割り切れる数を小さい順に並べたとき、`n` 番目の数を求めてください。（Ugly Number III）

答えを直接求めるのは難しいのですが、**「`x` 以下にそういう数が何個あるか」なら、いま作った式で即座に求まります。** そして `x` を大きくすれば個数は単調に増えます。

これは二分探索のノートでやった「答えの決めうち」そのものです。

```python
def nth_ugly_number(n, a, b, c):
    # 条件 P(x): x 以下に、条件を満たす数が n 個以上ある
    ok, ng = 2 * 10**9, 0
    while abs(ok - ng) > 1:
        mid = (ok + ng) // 2
        if count_divisible(mid, a, b, c) >= n:
            ok = mid
        else:
            ng = mid
    return ok
```

判定 1 回が O(1)、二分探索が O(log(答えの範囲)) なので、全体で 30 回程度の計算で終わります。**「数え上げが O(1) でできるなら、答えを二分探索できる」**という組み合わせは、覚えておく価値があります。

<Callout type="warn" title="LCM があふれることがあります">
  `lcm(a, b)` は最大で `a × b` になります。`a` と `b` がどちらも 10<sup>9</sup> なら、`lcm` は 10<sup>18</sup>。3 つの LCM なら 10<sup>27</sup> です。

  Python では多倍長なので壊れませんが、**二分探索の上限をそのまま `lcm` に合わせると、無駄に広い範囲を探すことになります**。答えの上限は「`min(a,b,c) × n`」程度で抑えられるので、そちらを使ってください。

  C++ や Java では、そもそも `lcm` の計算があふれます。`lcm` が答えの上限を超えた時点で「その共通倍数は範囲内に存在しない」と判断して 0 を返す、という打ち切りが必要です。
</Callout>

## 補集合で数えるほうが速いこともある

包除原理と並んで覚えておきたいのが、**「満たすもの」ではなく「満たさないもの」を数える**という切り替えです。

> 各桁がすべて異なる `n` 桁以下の整数はいくつありますか。（Count Numbers with Unique Digits）

「すべて異なる」を直接数えるのは、条件が絡み合って面倒に見えます。ところが、**桁ごとに使える数字を数えていく**と素直です。

- 1 桁目：1〜9 の 9 通り（0 は先頭に置けない）
- 2 桁目：すでに使った 1 個を除く 9 通り（0 が使える）
- 3 桁目：8 通り
- ……

「重複しない」という条件が、**選択肢の数を 1 つずつ減らす**という形で自然に表現できました。順列の数え方そのものです。

一般に、次のような場合は補集合を疑ってください。

- 「少なくとも 1 つ」→ 全体 − 「1 つもない」
- 「どれかを満たす」→ 全体 − 「どれも満たさない」

**「少なくとも」という言葉が出てきたら、補集合のほうが簡単でないかを必ず一度確認する**、というのが実戦的な習慣です。

## この知識を使う場面

| 場面 | 使い方 |
| --- | --- |
| 「a か b か c で割り切れる個数」 | 包除原理で O(1) に |
| 二分探索の判定関数 | 「x 以下に何個あるか」を包除で数える |
| 「少なくとも1つ」 | 補集合（全体 − 1つもない）を疑う |
| 部分集合ごとの符号つき和 | bit で全部分集合を回り、popcount の偶奇で符号を決める |

最後の行を実装する形だけ示しておきます。

```python
total = 0
for mask in range(1, 1 << k):
    sign = -1 if bin(mask).count('1') % 2 == 0 else 1
    total += sign * count_for(mask)
```

`popcount` が奇数なら足す、偶数なら引く。ビット演算のノートで見た `popcount` が、ここで符号の決定に使われます。
