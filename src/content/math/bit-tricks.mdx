## まず、困っている状況を体験してみます

> 配列の中で、**1 つだけ 1 回しか現れない数**があります。ほかの数はすべてちょうど 2 回現れます。その 1 つを見つけてください。ただし、**追加のメモリを使わずに**やってください。

辞書で数えれば簡単ですが、それでは O(N) のメモリを使います。ソートして隣同士を比べる方法も O(N log N) かかります。

ここで、XOR の性質を1つ思い出します。

```
a ^ a = 0        （同じ数を2回重ねると消える）
a ^ 0 = a        （0 とは何も起きない）
```

そして XOR は**順番を入れ替えても結果が変わりません**（交換法則・結合法則が成り立ちます）。ということは、配列全部を XOR で畳むと、2 回現れる数はすべてペアで消え、**1 回だけの数だけが残ります。**

```python
ans = 0
for x in nums:
    ans ^= x
return ans
```

1 行です。メモリは変数 1 つ、時間は O(N)。これがビット演算の効きどころで、**「同じものが打ち消し合う」という性質を、数の世界に持ち込んでいる**わけです。

## 発想を変える：整数を「0/1 の並び」として見る

ビット演算を使いこなす鍵は、整数を数量ではなく、**0 と 1 が並んだ列**として見ることです。そう見ると、3 つの演算はすべて「集合の演算」に翻訳できます。

| 演算 | ビットごとの規則 | 集合として読むと |
| --- | --- | --- |
| `a & b` | 両方 1 なら 1 | 共通部分 |
| `a \| b` | どちらか 1 なら 1 | 和集合 |
| `a ^ b` | 違えば 1 | 対称差（片方だけに入っているもの） |
| `~a` | 反転 | 補集合 |
| `a << k` | 左へずらす | 2<sup>k</sup> 倍 |
| `a >> k` | 右へずらす | 2<sup>k</sup> で割った商 |

この読み替えができると、`mask | (1 << i)` が「集合に要素 i を加える」という意味だと素直に読めるようになります。

```python
x | (1 << i)      # i 番目のビットを立てる
x & ~(1 << i)     # i 番目のビットを落とす
x ^ (1 << i)      # i 番目のビットを反転する
x & (1 << i)      # i 番目が立っていれば 0 以外
x & -x            # 一番下の立っているビットだけを残す
x & (x - 1)       # 一番下の立っているビットだけを落とす
bin(x).count('1') # 立っているビットの数
```

## なぜ `x & -x` で最下位ビットが取れるのか

この式だけは、見ただけでは理由がわかりません。順を追って確かめます。

コンピュータは負の数を **2 の補数**で表します。`-x` は「`x` の全ビットを反転して 1 を足したもの」です。`x = 12`（2進法で `00001100`）でやってみます。

```
x        = 00001100
~x       = 11110011        全部反転
~x + 1   = 11110100        1 を足す = -x
```

ここで `x` と `-x` を上下に並べると、**最下位の 1 より上の桁はすべて食い違っていて、最下位の 1 とその下だけが一致している**のがわかります。

```
x   = 00001100
-x  = 11110100
AND = 00000100        ← 最下位の 1 だけが残る
```

なぜそうなるかというと、`+1` したときの繰り上がりが、ちょうど最下位の 1 の位置で止まるからです。それより下は全部 0（反転して 1 だったものが繰り上がりで 0 に戻る）、その位置で 1 が立ち、それより上は反転したままになります。

これが BIT（Fenwick Tree）で `i & -i` を使って担当区間を決めている、あの `lowbit` です。

<Callout type="tip" title="x & (x - 1) は「立っているビットを1つ落とす」">
  `x - 1` は、最下位の 1 を 0 にして、それより下をすべて 1 にします。

  ```
  x     = 00001100
  x - 1 = 00001011
  AND   = 00001000        ← 最下位の 1 だけが落ちた
  ```

  これを 0 になるまで繰り返した回数が、立っているビットの数（popcount）です。**立っているビットの数だけしかループしない**ので、32 回固定で数えるより速くなります。

  さらに、`Counting Bits`（0 から n までの各数について popcount を求める）は、この式から漸化式が出ます。

  ```python
  dp[i] = dp[i & (i - 1)] + 1
  ```

  `i & (i-1)` は `i` より必ず小さいので、DP として素直に埋まります。
</Callout>

## 部分集合を列挙する

bit DP でよく必要になるのが、「ある集合 `mask` の部分集合をすべて回る」という操作です。

素直に `for sub in range(mask + 1): if sub & mask == sub:` と書くと、`mask` の外のビットも全部試すことになり、2<sup>n</sup> 回まわります。実際に欲しいのは、`mask` の中に立っているビットが `k` 個なら 2<sup>k</sup> 個だけです。

そこで、次の1行を使います。

```python
def subsets(mask):
    res = []
    sub = mask
    while True:
        res.append(sub)
        if sub == 0:
            break
        sub = (sub - 1) & mask   # 1つ前の部分集合へ飛ぶ
    return res
```

<SubsetEnum client:visible />

`(sub - 1) & mask` が何をしているかを言葉にすると、こうです。`sub - 1` で最下位の 1 を落として下を全部 1 にし、`& mask` で `mask` の外にはみ出したビットを捨てる。結果として、**`mask` の部分集合を大きい順に、1 つも飛ばさず 1 つも重複せずに下っていけます。**

<Callout type="warn" title="空集合の扱いだけ、ループの形に注意">
  `while sub > 0:` と書いてしまうと、**空集合（sub = 0）が列挙されません。** 空集合を含めたいかどうかは問題によって違います。

  - 空集合が要る場合：上のコードのように `while True` にして、`sub == 0` を採用してから break する
  - 空集合が不要な場合：`sub = mask; while sub > 0:` で回し、末尾で `sub = (sub - 1) & mask`

  「集合を2つに分ける」という問題では、空集合を含めるかどうかで答えが変わります。書く前に、片方が空の分け方を許すのかを確認してください。

  なお、すべての `mask` について部分集合を列挙すると、全体の回数は 3<sup>n</sup> になります（各要素が「mask にも sub にもある」「mask だけ」「どちらにもない」の 3 通りだからです）。n = 16 で約 4,300 万回。ぎりぎり通る規模なので、n が 16 を超えるなら別の方法を考えてください。
</Callout>

## XOR をもう少し使う

XOR は「打ち消し合う」という性質が強力なので、専用の型がいくつかあります。

### 累積 XOR

累積和と同じことが XOR でもできます。

```python
P[0] = 0
P[i+1] = P[i] ^ nums[i]
# 区間 [l, r] の XOR は
P[r+1] ^ P[l]
```

なぜ引き算ではなく XOR で取り出せるかというと、`P[l]` に含まれる部分が **2 回重なって消える**からです。累積和で引き算していたところが、XOR では XOR そのものになります。

### lowbit でグループを分ける

> 2 つだけ 1 回しか現れない数があります。両方を見つけてください。

全部を XOR で畳むと、`a ^ b`（求めたい 2 数の XOR）が残ります。ここから個別に取り出すために、`a ^ b` の**立っているビットを 1 つ選びます**（`lowbit` で十分です）。

そのビットが立っているということは、`a` と `b` はその桁で**食い違っている**ということです。そこで、配列全体をそのビットが立っているかどうかで 2 グループに分けると、`a` と `b` は別々のグループに入ります。あとは各グループで XOR を畳めば、それぞれが求める数です。

<Callout type="warn" title="Python の整数には上限が無い、という落とし穴">
  Python の `~x` は「無限桁の 2 の補数」として扱われるため、`~5` は `-6` になります。C++ のように「32 ビットの中で反転」とはなりません。

  32 ビットの範囲で扱いたいときは、マスクを掛けて明示的に切ります。

  ```python
  x & 0xFFFFFFFF        # 下位32ビットだけ残す
  ```

  また、Python には符号なしの右シフト（`>>>`）がありません。負の数を右シフトすると符号ビットが伸びていきます。**LeetCode でビット演算の問題を Python で解くときは、負の数の扱いを必ず確認してください。**
</Callout>

| 2 つの数を分離する | `a ^ b` の立っているビットでグループ分け |
