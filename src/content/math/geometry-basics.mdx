## まず、困っている状況を体験してみます

> 3 つの点が与えられます。一直線上に並んでいるか判定してください。

最初に思いつくのは、傾きを比べる方法です。

```python
(y2 - y1) / (x2 - x1) == (y3 - y1) / (x3 - x1)
```

これは 2 つの意味で危険です。

1. **`x2 == x1` のときにゼロ除算になる**（垂直な直線）
2. **浮動小数点の誤差**で、一致するはずの傾きが一致しなくなる

2 番目が特にやっかいです。`1/3` は 2 進法で正確に表せないので、計算の順番が違うだけで結果がわずかにずれます。`==` で比べる限り、この判定は信用できません。

そこで、**割り算をしない形に書き直します。** 両辺に分母を掛けると、

```python
(y2 - y1) * (x3 - x1) == (y3 - y1) * (x2 - x1)
```

これなら整数のままです。ゼロ除算もありません。移項すれば、

`(x2 − x1)(y3 − y1) − (y2 − y1)(x3 − x1) == 0`

この左辺が、**外積**（クロス積）と呼ばれる値です。

## 外積：向きが符号で分かる

外積は「一直線かどうか」だけでなく、**どちら側にあるか**まで教えてくれます。

```python
def cross(o, a, b):
    # o から a へのベクトルと、o から b へのベクトルの外積
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

# cross > 0  : o → a → b は左に曲がる（反時計回り）
# cross < 0  : 右に曲がる（時計回り）
# cross == 0 : 3点は一直線
```

<CrossProduct client:visible />

符号の意味を覚えるコツは、**「O から A を見て、B はその左か右か」**と読むことです。左なら正、右なら負です。

外積の絶対値にも意味があります。`|cross|` は、3 点が作る**平行四辺形の面積**です。したがって三角形の面積はその半分になります。

`三角形 OAB の面積 = |cross(O, A, B)| / 2`

**割り算が 2 で割るだけなので、2 倍した面積のまま整数で扱えます。** 面積を比較するだけなら、2 で割る必要すらありません。

<Callout type="tip" title="距離も2乗のまま比べる">
  同じ発想が距離にも使えます。2 点の距離は `√((x2−x1)² + (y2−y1)²)` ですが、**大小を比べるだけなら平方根を取る必要がありません。**

  ```python
  d2 = (x2 - x1) ** 2 + (y2 - y1) ** 2      # 距離の2乗
  ```

  平方根を取ると浮動小数点になり、誤差が入ります。「どちらが近いか」「等しいか」を判定したいだけなら、2 乗のまま整数で比べてください。Valid Square のように「4 辺の長さが等しいか」を確かめる問題では、これが決定的な差になります。
</Callout>

## 2 種類の距離

問題によって、距離の測り方が変わります。

| 名前 | 式 | どんな移動か |
| --- | --- | --- |
| ユークリッド距離 | √((Δx)² + (Δy)²) | 直線で最短。ふつうの距離 |
| マンハッタン距離 | \|Δx\| + \|Δy\| | 縦横にしか動けない。碁盤の目 |
| チェビシェフ距離 | max(\|Δx\|, \|Δy\|) | 斜めにも1歩で動ける（キングの移動） |

Min Cost to Connect All Points では、マンハッタン距離が使われています。問題文に「`|xi - xj| + |yi - yj|`」と式で書かれているので、読み飛ばさないでください。**どの距離かで答えがまったく変わります。**

## 重なりの判定：1次元に落とす

> 2 つの矩形が重なっているか判定してください。

矩形どうしの位置関係は何通りもあるように見えますが、**x 方向と y 方向に分けて考えると、どちらも1次元の区間の重なり判定**になります。

区間 `[a1, a2]` と `[b1, b2]` が重なる条件は、

`a1 < b2 かつ b1 < a2`

です。「重なる条件」を直接書くより、**「重ならない条件」を否定する**ほうが考えやすいことが多いです。重ならないのは「片方が完全に左」か「片方が完全に右」のときだけなので、

```python
def overlap(a1, a2, b1, b2):
    return not (a2 <= b1 or b2 <= a1)
```

これを x と y の両方に適用して、両方成り立てば矩形が重なっています。

<Callout type="warn" title="境界で接するときを、含めるか含めないか">
  `a2 <= b1` の等号をどちらに入れるかで、**「辺で接しているだけ」を重なりと見なすか**が変わります。

  - Rectangle Overlap は「面積が正の重なり」を求めるので、接しているだけなら重なっていない扱いです（等号は「重ならない」側に入れます）
  - 「区間をマージする」問題では、接していればつなげるのが普通です

  区間の掃過のノートでも同じ注意を書きましたが、**接する入力を1つ作って確かめる**のが唯一確実な方法です。
</Callout>

## 凸包：外側だけを残す

もう少し進んだ型として、凸包（convex hull）があります。

> 平面上の点が与えられます。すべての点を囲む、最小の凸多角形の頂点を求めてください。（庭に柵を立てて、すべての木を囲む問題）

外積が使えると、これが素直に書けます。手順はこうです。

1. 点を **x の昇順**に並べる
2. 左から順に追加していき、**「左に曲がっていない」点が出てきたら1つ前を取り除く**
3. 同じことを逆順（右から左）にもやると、上側の境界ができる
4. 上下をつなげれば凸包

```python
def convex_hull(points):
    points = sorted(set(points))          # x の昇順、同じなら y の昇順
    if len(points) <= 2:
        return points

    def build(pts):
        hull = []
        for p in pts:
            while len(hull) >= 2 and cross(hull[-2], hull[-1], p) <= 0:
                hull.pop()                # 左に曲がっていないなら、へこむので戻す
            hull.append(p)
        return hull

    lower = build(points)                 # 下側の境界
    upper = build(points[::-1])           # 逆順に走ると上側の境界
    return lower[:-1] + upper[:-1]
```

<ConvexHull client:visible />

赤くなる点が「へこんでしまうので外した点」です。

このコードの形に見覚えがあるはずです。**`while` で末尾を取り除いてから追加する**という骨格は、単調スタックとまったく同じです。判定条件が「値の大小」から「外積の符号」に変わっただけで、**各点がスタックに入るのも出るのも 1 回ずつ**なので、ソートを除けば O(N) です。全体では、ソートが支配的な O(N log N) になります。

<Callout type="tip" title="なぜ x 順に並べると、左右2回で済むのか">
  x の昇順に走ると、常に右へ進み続けます。そのあいだ「左に曲がる」だけを許すと、自然に**下側の境界**をなぞることになります。

  逆順に走れば同じ理屈で上側がなぞれます。2 本をつなげば一周するので、**角度でソートする必要がありません**（角度ソートを使う Graham scan という別の方法もありますが、こちらのほうが実装が短く、誤差も出ません）。

  `lower[:-1] + upper[:-1]` で末尾を落としているのは、下側の終点と上側の始点が同じ点で重複するためです。
</Callout>

## この知識を使う場面

| 場面 | 使う道具 |
| --- | --- |
| 3 点が一直線か | 外積 == 0（割り算しない） |
| どちら側にあるか、曲がる向き | 外積の符号 |
| 三角形の面積 | \|外積\| / 2 |
| どちらが近いか | 距離の 2 乗のまま比較 |
| 区間・矩形の重なり | 各軸で1次元の重なり判定に分ける |
| すべての点を囲む | 凸包（外積 + 単調スタックの形） |
