## まず、困っている状況を体験してみます

コードを書く前に、必ずやることがあります。**制約を見て、その解法が間に合うかを確かめる**ことです。

```python
for i in range(n):
    for j in range(i, n):      # i から始まる
        ...
```

この二重ループは何回まわるでしょうか。「O(N²) だから N² 回」と答えると、少しずれています。内側は `i` から始まるので、`i` が進むほど短くなります。正確には、

`n + (n−1) + (n−2) + ... + 1`

です。この値が分かっていないと、「N = 50,000 のとき間に合うか」という判断ができません。

必要なのは、ループの回数を**式にする**ことと、その式を**数に直す**ことです。この記事では、そのための3つの数列と、いくつかの目安を押さえます。

## 等差数列：1 から N までの和

`1 + 2 + ... + N` は `N(N+1)/2` です。公式として覚えている人も多いと思いますが、**なぜそうなるか**を確認しておくと、似た形が出たときに自分で導けます。

両端から組にします。`1 + N`、`2 + (N−1)`、`3 + (N−2)`……。どの組も合計が `N+1` です。組は `N/2` 個できるので、全体は `N(N+1)/2` になります。

<SumFormula client:visible />

さきほどの二重ループは、ちょうどこの形です。

`n + (n−1) + ... + 1 = n(n+1)/2 ≈ n²/2`

つまり **N² のおよそ半分**です。N = 50,000 なら 12.5 億回。1 秒で 1 億回が目安なので、これは間に合いません。N = 10,000 なら 5,000 万回で、通ります。**「N² の半分」という感覚があると、この判断ができます。**

<Callout type="tip" title="「区間の個数」も同じ形です">
  長さ N の配列に、連続する部分配列（区間）はいくつあるでしょうか。左端の選び方が N 通り、右端はその右側なので、合計は `N + (N−1) + ... + 1 = N(N+1)/2` 個です。

  「すべての区間について何かを計算する」と書かれていたら、その時点で最低 O(N²) かかることが確定します。**それが許されない制約なら、区間を全部見ない解法（累積和、Sliding Window、単調スタック）を探すことになります。**

  Sum of Subarray Minimums のように「すべての区間の最小値の合計」を求める問題は、区間を列挙せずに「各要素が何個の区間で最小になるか」を数えることで O(N) に落とします。数え方を裏返すという発想です。
</Callout>

## 等比数列：半分ずつ、2倍ずつ

`1 + 2 + 4 + 8 + ... + 2^k` は `2^(k+1) − 1` です。つまり、**最後の項のおよそ 2 倍**にしかなりません。

この性質は、再帰や分割統治の計算量に直結します。

- **二分木を全部たどる**：深さ `k` の完全二分木のノード数は `2^(k+1) − 1`。葉の数のおよそ 2 倍
- **マージソート**：各段の仕事が O(N) で、段が log N 個あるので O(N log N)
- **動的配列の拡張**：容量が足りなくなるたびに 2 倍にしてコピーすると、コピーの総回数は `1 + 2 + 4 + ... + N ≈ 2N`。1 要素あたりならして O(1)

逆向きに `1 + 1/2 + 1/4 + ...` も同じ形で、**2 に収束します**。「毎回半分になるなら、全部足しても最初の 2 倍で済む」と覚えておくと便利です。

## 調和級数：N/1 + N/2 + N/3 + ...

3 つ目が、意外と出番の多い形です。

```python
for p in range(1, n + 1):
    for q in range(p, n + 1, p):   # p の倍数だけ
        ...
```

内側は `n // p` 回まわります。合計は、

`n/1 + n/2 + n/3 + ... + n/n = n × (1 + 1/2 + 1/3 + ... + 1/n)`

括弧の中は調和級数と呼ばれ、`ln n` におよそ等しくなります。したがって全体は **O(N log N)** です。

<HarmonicCount client:visible />

`n = 30` で試すと、素直な二重ループの 900 回に対して、実際は 111 回程度です。エラトステネスの篩や、「各数について倍数を更新する」型のループは、すべてこの形になります。

<Callout type="tip" title="篩が O(N log log N) なのは、素数だけを見るから">
  上の形は、`p` を 1 から N まで**すべて**動かすので O(N log N) です。エラトステネスの篩はさらに速く O(N log log N) になりますが、これは **`p` が素数のときだけ内側をまわす**からです。

  `1/2 + 1/3 + 1/5 + 1/7 + 1/11 + ...`（素数の逆数の和）が `log log n` 程度にしかならない、という数論の結果から出てきます。ここは導けなくて構いませんが、**「素数だけに絞ると、さらに一段軽くなる」**とだけ覚えておけば十分です。
</Callout>

## 制約から解法を逆算する

競技プログラミングでは、**制約が解法のヒントになっています。** 1 秒で約 10<sup>8</sup> 回という目安で逆算した表が、次のものです。

| N の上限 | 許される計算量 | 典型的な解法 |
| --- | --- | --- |
| 10<sup>18</sup> | O(log N) | 二分探索、繰り返し二乗法、数式 |
| 10<sup>7</sup>〜10<sup>8</sup> | O(N) | 一度なめるだけ。累積和、Sliding Window |
| 10<sup>6</sup> | O(N log N) | ソート、ヒープ、篩、BIT |
| 10<sup>5</sup> | O(N log N) / O(N √N) | 同上、平方分割 |
| 5,000 | O(N²) | 二重ループ、区間 DP の一部 |
| 500 | O(N³) | 区間 DP、Floyd-Warshall |
| 100 | O(N⁴) | 制約が小さいときは、雑な全探索も許される |
| 20 | O(2<sup>N</sup>) | bit 全探索、bit DP |
| 16 | O(3<sup>N</sup>) | 部分集合の部分集合を回る bit DP |
| 10 | O(N!) | 順列の全探索 |

この表の使い方は、**問題文を読んだらまず制約を見て、右の列から解法の候補を絞る**ことです。「N ≤ 20」と書いてあれば bit 全探索、「N ≤ 500」なら O(N³) が想定されている、という読み方をします。

<Callout type="warn" title="1秒で10^8回はあくまで目安です">
  この数字は言語や処理内容で大きく変わります。

  - Python は C++ の 10〜100 倍遅いと考えてください。**Python なら 10<sup>7</sup> 回程度が現実的な上限**です
  - 単純な整数演算は速く、辞書の参照やオブジェクトの生成は遅い
  - 定数倍を無視した O 記法だけで判断すると、「O(N log N) なのに間に合わない」ということが起きます

  LeetCode は言語ごとに時間制限を調整しているので極端なことは起きませんが、**「ぎりぎり O(N log N)」のときは、定数倍の軽い書き方（ヒープより ソート、辞書より配列）を選ぶ**価値があります。
</Callout>

## ならし計算量：合計で数える

最後に、この教材の中で何度も出てくる数え方を明示しておきます。

```python
for i in range(n):
    while stack and ...:
        stack.pop()
    stack.append(i)
```

内側に `while` があるので O(N²) に見えますが、実際は O(N) です。理由は、**個々のループではなく、全体での合計を数える**からです。

- `append` は `i` につき 1 回なので、全体で N 回
- `pop` できるのは、過去に `append` したものだけ。だから全体で高々 N 回

内側の `while` が 1 回で 5 回まわったとしても、それは過去に積んだ 5 個を消費したということで、その 5 個は二度と消えません。**合計は 2N 回で頭打ち**です。

この「1 要素あたりの出入りの回数で押さえる」という数え方を、ならし計算量（amortized）と呼びます。単調スタック、単調キュー、Union-Find、動的配列の拡張は、すべてこの数え方で計算量が決まっています。

## この知識を使う場面

| 見かけた形 | 回数 | 結論 |
| --- | --- | --- |
| `for i: for j in range(i, n)` | N(N+1)/2 | N² の半分 |
| `for p: for q in range(p, n, p)` | N ln N | N log N |
| 毎回半分に絞る | log N | 二分探索 |
| 毎回 2 倍に増える | 最後の項の 2 倍 | 等比なので実質 O(最後) |
| 内側 while + 各要素の出入りが 1 回ずつ | 2N | ならして O(N) |
