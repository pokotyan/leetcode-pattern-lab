## まず、困っている状況を体験してみます

> サイコロを 2 個振ったとき、出る目の合計の平均はいくつですか。

素直にやるなら、36 通りをすべて書き出して合計を 36 で割ります。答えは 7 です。

では 10 個ならどうでしょうか。場合の数は 6<sup>10</sup> = 約 6,000 万通り。書き出して数えるのは現実的ではありません。

ところが答えはすぐ出ます。**35** です。1 個あたりの平均が 3.5 で、それが 10 個だからです。

この「それぞれの平均を足すだけでよい」という性質が、期待値のいちばん強力な道具です。

## 期待値の線形性

期待値とは「確率で重みをつけた平均」です。値 `v` が確率 `p` で起きるとき、期待値はそれらの `p × v` の合計です。

サイコロ 1 個なら、`(1+2+3+4+5+6) / 6 = 3.5` です。

ここで重要なのが、**期待値の線形性**です。

> `E[X + Y] = E[X] + E[Y]`
> これは **X と Y が独立でなくても成り立ちます。**

後半が効きます。ふつう確率の計算では「独立かどうか」を気にしますが、**足し算の期待値に限っては、互いに影響し合っていても構いません。**

具体例で確かめます。

> 1 から n までのカードをシャッフルして 1 枚ずつめくります。「これまでで最大の値」が更新される回数の期待値はいくつですか。

一見すると、順序が絡み合っていて難しそうです。ところが、こう考えます。

**`i` 番目にめくったカードが「更新」になるのは、最初の `i` 枚の中でそれが最大のときだけ**です。最初の `i` 枚の順序はランダムなので、どれが最大になるかは等確率、つまり確率は `1/i` です。

あとは足すだけです。

`E = 1/1 + 1/2 + 1/3 + ... + 1/n ≈ ln n`

n = 100 万でも 14 回程度にしかなりません。**「更新される回数はとても少ない」**という結論が、場合の数を1つも数えずに出ました。

<Callout type="tip" title="困ったら「1つずつに分解して、確率を足す」">
  期待値の問題で手が止まったら、次の順に考えると進みます。

  1. 求めたい量を、**0 か 1 かの小さな量の合計**に書き直す（「i 番目が条件を満たすなら 1」）
  2. それぞれについて、**1 になる確率**を求める
  3. 全部足す

  0 か 1 の量の期待値は、そのまま「1 になる確率」です。この分解ができると、独立性を考えずに済みます。
</Callout>

## 確率の DP

もう1つの典型が、確率そのものを DP の値にする形です。

> 点数 0 から始め、1 から `maxPts` までの点をランダムに引いて足していきます。`k` 点以上になったら止めます。最終的な点数が `n` 以下である確率を求めてください。（New 21 Game）

`dp[i]` を「いま `i` 点のときに、最終的に条件を満たす確率」とします。`i` 点から次に引く目は `1 〜 maxPts` が等確率なので、

`dp[i] = (dp[i+1] + dp[i+2] + ... + dp[i+maxPts]) / maxPts`

という形になります。**確率は足して 1 になるので、遷移の重みがそのまま確率**です。数え上げ DP との違いは、割り算（平均を取る操作）が入るところだけです。

なお、この式の右辺は**連続する maxPts 個の和**なので、Sliding Window で O(1) に落とせます。確率 DP は遷移が重くなりがちなので、**累積和や窓の和で削れないか**を毎回確認してください。

<Callout type="warn" title="確率の問題で mod を取るとき">
  LeetCode では確率を浮動小数点で返す問題がほとんどですが、競技プログラミングでは「答えを 998244353 で割った余りで」と言われることがあります。

  確率は分数なので、そのままでは余りの世界に持ち込めません。**分母の逆元を掛ける**ことで整数に直します（剰余演算のノートの逆元がここで効きます）。「1/3 の確率」は、余りの世界では `3 の逆元` という1つの整数になります。
</Callout>

## 衝突確率：ハッシュを信じてよい理由

文字列照合のノートで、ローリングハッシュの偽陽性について「MOD を大きく取ればめったに起きない」と書きました。その「めったに」を数で押さえます。

2 つの異なる文字列のハッシュが偶然一致する確率は、だいたい `1/MOD` です。MOD が 10<sup>9</sup> なら 10 億分の 1。

ただし、**比較の回数だけ機会がある**ことに注意が必要です。N = 10<sup>5</sup> 個の部分文字列を互いに比べると、ペアの数は約 5 × 10<sup>9</sup> 個。すると、どこかで衝突が起きる確率は

`5 × 10^9 / 10^9 = 5`

となり、**1 を超えてしまいます**（つまり、ほぼ確実にどこかで衝突します）。これが誕生日のパラドックスと同じ構造です。

対策は 2 つあります。

- **MOD をもっと大きくする。** 10<sup>18</sup> 級の素数を使えば、ペアが 10<sup>10</sup> あっても衝突確率は 10<sup>-8</sup> です
- **ハッシュを 2 本使う。** 異なる MOD で 2 つのハッシュを計算し、両方一致したときだけ同じとみなします。両方偶然一致する確率は掛け算になるので、`1/10^9 × 1/10^9 = 1/10^18` です

「1 回あたりの確率」ではなく「**機会の数 × 1 回あたりの確率**」で見積もる、というのがここでの教訓です。

## 長さを知らずに等確率で選ぶ

最後に、確率の考え方がそのままアルゴリズムになっている例です。

> 連結リストから、ノードを 1 つ等確率でランダムに選んでください。**リストの長さは分かりません。**

長さが分かれば `random(n)` で済みますが、分からないので使えません。1 周して数えてからもう 1 周する、という方法はメモリも時間も余分にかかります。

そこで、次の手順を取ります。

- `i` 番目の要素が来たら、**確率 `1/i` で「いま持っているもの」をそれに置き換える**

```python
import random

def pick(stream):
    chosen = None
    for i, x in enumerate(stream, start=1):
        if random.randrange(i) == 0:     # 確率 1/i で今の要素に置き換える
            chosen = x
    return chosen
```

<ReservoirSampling client:visible />

なぜこれで等確率になるのか、`x1` が最後まで残る確率を追ってみます。

- 2 番目で置き換えられない確率：`1/2`
- 3 番目で置き換えられない確率：`2/3`
- 4 番目で置き換えられない確率：`3/4`
- ……
- n 番目で置き換えられない確率：`(n−1)/n`

これらを掛け合わせると、

`1/2 × 2/3 × 3/4 × ... × (n−1)/n = 1/n`

分子と分母が次々に打ち消し合って、`1/n` だけが残ります。ほかの要素についても、同じ計算で `1/n` になります。

**メモリは 1 つ、走査は 1 回だけ**で、しかも長さを知る必要がありません。

<Callout type="tip" title="k 個選びたいときも同じ形です">
  1 個ではなく `k` 個を等確率で選びたいときは、こうします。

  - 最初の `k` 個はそのまま採用する
  - `i` 番目（`i > k`）が来たら、確率 `k/i` で採用し、採用する場合は手持ちの `k` 個からランダムに 1 つ捨てる

  同じ計算で、どの要素も最終的に `k/n` の確率で残ります。「ログの中からランダムに 1000 件サンプリングする」といった実務の場面でも、そのまま使える手法です。
</Callout>

## この知識を使う場面

| 場面 | 使い方 |
| --- | --- |
| 「平均して何回か」 | 0/1 に分解して、確率を足す（線形性） |
| 「確率を求めよ」 | 確率そのものを DP の値にする |
| ハッシュの信頼性 | 機会の数 × 1 回あたりの衝突確率で見積もる |
| 長さ不明の列から等確率で選ぶ | リザーバーサンプリング |
| 重み付きのランダム選択 | 累積和を作って、二分探索で引く |

最後の行は Random Pick with Weight の型です。重み `[1, 3, 2]` なら累積和 `[1, 4, 6]` を作り、`1〜6` の乱数を引いて、その値が入る位置を二分探索で探します。**累積和と二分探索という既習の道具だけで、重み付き抽選ができます。**
