## 速さと容量は両立しない

メモリには種類があり、それぞれ性質が違います。

**SRAM** は、1 ビットを 6 個のトランジスタで保持します。電源がある限り値が保たれ、読み書きが極めて速い。ただし 1 ビットあたりの面積が大きく、高価です。

**DRAM** は、1 ビットをコンデンサ 1 個と トランジスタ 1 個で保持します。面積が小さく安い。ただしコンデンサの電荷は漏れるため、定期的に読み直して書き戻す必要があり（リフレッシュ）、アクセスも遅くなります。

この差は原理的なもので、技術の進歩で埋まるものではありません。したがって、**速くて大きいメモリは作れません**。

## それでも両方欲しい

そこで、**速くて小さいものと、遅くて大きいものを重ねて置く**という解決策が取られます。

```
        ┌──────────┐
        │ レジスタ   │  数百バイト      0 サイクル
        ├──────────┤
        │  L1       │  32〜64KB       4 サイクル
        ├──────────┤
        │  L2       │  256KB〜2MB     12 サイクル
        ├──────────┤
        │  L3       │  8〜64MB        40 サイクル
        ├──────────┤
        │  DRAM     │  8〜128GB       200〜300 サイクル
        ├──────────┤
        │  SSD      │  0.5〜4TB       数十万サイクル
        ├──────────┤
        │  HDD      │  数TB           数千万サイクル
        └──────────┘
```

上に行くほど速く小さく、下に行くほど遅く大きい。そして**上の層は、下の層のよく使う部分の写し**を持ちます。

## 桁を体感する

サイクル数だと実感が湧かないので、**1 サイクルを 1 秒に引き伸ばして**みます。

| 場所 | 実際 | 1 サイクル = 1 秒とすると |
| --- | --- | --- |
| L1 キャッシュ | 4 サイクル | 4 秒 |
| L2 キャッシュ | 12 サイクル | 12 秒 |
| L3 キャッシュ | 40 サイクル | 40 秒 |
| メインメモリ | 250 サイクル | **4 分** |
| SSD（NVMe） | 20 万サイクル | **2 日半** |
| HDD のシーク | 2000 万サイクル | **8 ヶ月** |
| 東京〜ロンドンの往復 | 7 億サイクル | **22 年** |

<Callout type="tip" title="この表は覚える価値がある">
  「メモリアクセスは遅い」と言葉で知っているのと、
  「L1 が 4 秒ならメモリは 4 分」と桁で把握しているのとでは、設計の判断が変わります。
  たとえば、メモリを 1 回読む間に、CPU は数百回の計算ができます。
  **計算を減らすためにテーブルを引く**という最適化は、
  そのテーブルがキャッシュに乗らなければ逆効果になります。
</Callout>

## なぜ階層が機能するのか

小さいキャッシュが役に立つのは、プログラムのメモリアクセスに偏りがあるからです。この偏りを **局所性** と呼び、2 種類あります。

**時間的局所性**：一度アクセスしたものは、近いうちにまたアクセスされる。

ループ変数、関数の局所変数、直前に読んだオブジェクト。これらは短い間に何度も使われます。

**空間的局所性**：あるアドレスにアクセスしたら、その近くにもアクセスされる。

配列の走査、構造体のメンバの連続アクセス、命令列の順次実行。

この 2 つが成り立つ限り、「最近使ったもの」と「その近く」をキャッシュに置いておけば、大半のアクセスが速い層で済みます。

<Callout type="note" title="局所性が成り立たないプログラム">
  ランダムなアクセスが続くと、キャッシュはまったく効きません。
  巨大なハッシュテーブルへのランダムアクセス、ポインタを辿る連結リストの走査、
  大きなグラフの探索。これらは**計算量が同じでも、実測では数倍から数十倍の差**が出ます。
  アルゴリズムの計算量だけでは説明できない性能差の多くは、ここから来ています。
</Callout>

## 階層はキャッシュだけではない

同じ「階層で誤魔化す」という発想は、あちこちで使われています。

| 層 | 速い側 | 遅い側 |
| --- | --- | --- |
| CPU 内 | キャッシュ | メインメモリ |
| OS | ページキャッシュ | ディスク |
| データベース | バッファプール | テーブルファイル |
| ウェブ | CDN、ブラウザキャッシュ | オリジンサーバ |
| アプリケーション | Redis | RDB |

構造はすべて同じです。**よく使うものを手前に置き、外れたら奥へ取りに行く**。そして「よく使うもの」をどう判断するかが、置き換えアルゴリズム（LRU など）の問題になります。

## 実測する

自分のマシンの階層を確かめられます。

```bash
# Linux
lscpu | grep -i cache
cat /sys/devices/system/cpu/cpu0/cache/index*/size

# macOS
sysctl -a | grep cachesize
```

レイテンシを測るには、配列のサイズを変えながらランダムアクセスの時間を測るのが定番です。

```c
// サイズを 1KB から 64MB まで倍々にして、それぞれでランダムアクセスを繰り返す
// 平均アクセス時間をプロットすると、階層の境界で段差ができる
```

L1、L2、L3、DRAM の各サイズを超えたところで、はっきりと段が現れます。**カタログの数字ではなく、自分の手元のマシンの数字**として見ておくと感覚が身につきます。

## まとめ

- SRAM は速くて高価、DRAM は安くて遅い。原理的な制約
- 階層を重ね、上の層に下の層の写しを置く
- L1 が 4 サイクルならメモリは 250 サイクル。この桁の差が設計を左右する
- 階層が機能するのは、プログラムに時間的・空間的局所性があるから
- 局所性がないアクセスは、計算量が同じでも数十倍遅くなる
