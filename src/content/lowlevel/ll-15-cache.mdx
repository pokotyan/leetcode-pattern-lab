## 1 バイト欲しくても 64 バイト持ってくる

キャッシュは、**キャッシュライン**という単位でメモリとやり取りします。現代の CPU ではほぼ 64 バイトです。

`arr[0]` を読むと、`arr[0]` から `arr[15]`（4 バイト整数なら 16 個）がまとめてキャッシュに載ります。

これは無駄に見えますが、空間的局所性があるので大抵は得です。次に `arr[1]` を読むとき、すでにキャッシュにあります。

```c
int arr[1000];
for (int i = 0; i < 1000; i++) sum += arr[i];
```

このループのメモリアクセスは 1000 回ですが、**キャッシュミスは 1000/16 ≈ 63 回**しか起きません。残りはヒットします。

<Callout type="tip" title="ライン境界をまたぐと 2 本必要になる">
  64 バイト境界をまたいで配置された 8 バイトの値を読むと、
  キャッシュラインが 2 本必要になります。
  第 1 章のアラインメントは、**この境界をまたがないようにする**意味でも効いています。
</Callout>

## どこに置くか

キャッシュは小さいので、メモリのどのアドレスをどのスロットに置くかを決める必要があります。

**ダイレクトマップ**（連想度 1）が最も単純です。アドレスの一部をそのままスロット番号にします。

```
アドレス:  [    タグ    ][ インデックス ][ オフセット ]
                           ↑              ↑
                    どのスロットか    ライン内の位置（6 bit = 64 バイト）
```

置き場所が 1 箇所に決まるので、検索が速く回路も単純です。

しかし問題があります。**インデックスが同じアドレスは、同じスロットを奪い合います**。

```c
// キャッシュが 32KB、ダイレクトマップの場合
float a[8192], b[8192];      // たまたま 32KB 離れて配置されたとする
for (int i = 0; i < 8192; i++) sum += a[i] * b[i];
```

`a[i]` と `b[i]` のインデックスが同じなら、交互に追い出し合います。キャッシュは空いているのに、毎回ミスします。これを **競合性ミス** と呼びます。

## 複数の置き場所を用意する

そこで、同じインデックスに対して複数のスロットを用意します。**n ウェイ・セットアソシアティブ** です。

| 方式 | 置き場所 | 特徴 |
| --- | --- | --- |
| ダイレクトマップ | 1 箇所 | 速いが競合しやすい |
| n ウェイ | n 箇所 | バランス。実際は 4〜16 ウェイ |
| フルアソシアティブ | どこでも | 競合しないが、全スロットを検索する必要があり高価 |

8 ウェイなら、同じインデックスのアドレスが 8 本まで同時に載れます。実用上はこれで大半の競合が消えます。

どれを追い出すかは、LRU（最後に使われてから最も時間が経ったもの）に近い方式が使われます。厳密な LRU は回路が大きくなるため、近似が使われるのが普通です。

## ミスの 3 分類

キャッシュミスは、原因によって 3 つに分けられます。対策が違うためです。

| 種類 | 原因 | 対策 |
| --- | --- | --- |
| **初回参照ミス** | 一度も読んでいないので当然ない | プリフェッチ。避けようがない場合も多い |
| **容量ミス** | 扱うデータがキャッシュより大きい | ブロッキング（後述）、データ構造を小さくする |
| **競合ミス** | 連想度が足りず追い出し合う | 配置をずらす、パディングを入れる |

**容量ミス**への典型的な対策が **ブロッキング**（タイリング）です。行列の積を素直に書くと、内側のループで行列全体を走査するためキャッシュに乗りません。

```c
// 素直な実装: 大きな行列ではキャッシュミスだらけになる
for (i) for (j) for (k) C[i][j] += A[i][k] * B[k][j];

// ブロッキング: 小さなブロックに区切り、各ブロックをキャッシュに載せきる
for (ii) for (jj) for (kk)
  for (i in ii) for (j in jj) for (k in kk) C[i][j] += A[i][k] * B[k][j];
```

計算量はまったく同じですが、**実測で数倍の差**が出ます。数値計算ライブラリが速いのは、この種の調整を徹底しているからです。

## 書き込みをどう扱うか

読み込みは単純ですが、書き込みには選択があります。

**ライトスルー**：キャッシュとメモリの両方に書く。常に一致しているので単純。ただし書き込みのたびにメモリアクセスが発生する。

**ライトバック**：キャッシュにだけ書き、**変更されたという印**（ダーティビット）を立てる。追い出されるときに初めてメモリに書き戻す。同じ場所を何度も書くとき、メモリアクセスが 1 回で済む。

現代の CPU はほぼ **ライトバック** です。

<Callout type="note" title="書き込み先がキャッシュにないとき">
  **ライトアロケート**：まずメモリからラインを読み込み、それから書く。
  そのあと同じラインを読むときに効きます。

  **ノーライトアロケート**：キャッシュを経由せず直接メモリに書く。
  一度書いたきり読まないデータ（大きなバッファの初期化など）に向きます。

  大量のメモリを一度だけ書くとき、キャッシュを汚さずに書く命令
  （x86 の `movnt` 系、非テンポラルストア）が用意されています。
</Callout>

## 複数のコアがあると一致させる必要がある

コアごとに L1 キャッシュがあるので、同じアドレスの写しが複数のコアに存在しえます。片方が書き換えたとき、もう片方が古い値を持ち続けては困ります。

そこで **キャッシュコヒーレンシプロトコル** が動きます。代表的なものが **MESI** です。各ラインが 4 つの状態のいずれかを持ちます。

| 状態 | 意味 |
| --- | --- |
| **M**odified | 自分だけが持ち、変更済み。メモリより新しい |
| **E**xclusive | 自分だけが持ち、未変更 |
| **S**hared | 複数のコアが持つ。未変更 |
| **I**nvalid | 無効 |

あるコアが書き込むとき、他のコアの同じラインを **Invalid** にします。これを **無効化** と呼び、コア間の通信が発生します。

**この通信がそのまま性能に効いてきます。** 複数のスレッドが同じキャッシュラインに書き込むと、無効化が飛び交い、極端に遅くなります。2 回後の記事で詳しく見ます。

## プリフェッチ

キャッシュミスを減らすもうひとつの手が、**先に読んでおく**ことです。

**ハードウェアプリフェッチャ**は、アクセスのパターンを検出して先読みします。配列を順番に走査していれば、数ライン先を自動的に読み込みます。等間隔の飛び飛びのアクセス（ストライド）も検出できます。

**ソフトウェアプリフェッチ**は、命令で明示的に指示します。

```c
__builtin_prefetch(&data[i + 16]);
```

ポインタを辿る構造のように、ハードウェアが予測できないパターンで有効なことがあります。ただし、早すぎると追い出され、遅すぎると間に合わないので、調整が必要です。

## まとめ

- キャッシュはライン（64 バイト）単位で動く
- 連想度が低いと、キャッシュが空いていても競合して追い出し合う
- ミスは初回参照・容量・競合の 3 種類。対策が違う
- 書き込みはライトバックが主流。ダーティなラインだけ書き戻す
- マルチコアではコヒーレンシプロトコルが動き、無効化の通信が発生する
