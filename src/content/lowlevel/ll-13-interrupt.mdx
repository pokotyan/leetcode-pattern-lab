## キー入力をどう知るか

キーボードが押されたことを、CPU はどうやって知るのでしょうか。

素朴な方法は、**定期的に見に行く**ことです。

```
loop:
    キーボードの状態を読む
    押されていたら処理する
    loop へ戻る
```

これを **ポーリング** と呼びます。単純ですが、2 つの問題があります。何も押されていないときも CPU を使い続けること。そして、見に行く間隔より短い事象を取りこぼすことです。

## 逆にする

**割り込み**は、この関係を逆転させます。

> **何かあったら、デバイスの側から CPU に知らせる。**

CPU には割り込み要求を受け取る信号線があります。デバイスがこの線を上げると、CPU は今実行している命令を完了させた直後に、次のことをします。

1. 現在の PC とフラグを退避する
2. **割り込みベクタテーブル**を引き、対応する処理のアドレスを得る
3. そのアドレスへジャンプする
4. 処理が終わったら、退避した PC に戻る

この処理を **割り込みハンドラ** と呼びます。

<Callout type="note" title="割り込みベクタテーブル">
  「割り込みの種類 → 処理の開始アドレス」の対応表です。メモリ上の決まった場所に置かれます。
  6502 では、メモリの末尾 6 バイトがこれに当たります。

  | アドレス | 用途 |
  | --- | --- |
  | `$FFFA-$FFFB` | NMI（マスク不可割り込み） |
  | `$FFFC-$FFFD` | RESET |
  | `$FFFE-$FFFF` | IRQ / BRK |

  **電源投入時、6502 は `$FFFC` から 2 バイト読み、そこへジャンプします。**
  「プログラムがどこから始まるか」は、このテーブルが決めています。
</Callout>

## 割り込みと例外

外から来るものだけでなく、CPU 自身が発生させるものもあります。両者は同じ仕組みで処理されます。

| 分類 | 発生源 | 例 |
| --- | --- | --- |
| **ハードウェア割り込み** | 外部デバイス | キーボード、タイマ、ネットワーク、ディスク完了 |
| **フォールト** | 命令の実行中の異常。**再実行できる** | ページフォールト |
| **トラップ** | 意図的な発生。**次の命令から再開** | システムコール、ブレークポイント |
| **アボート** | 回復不能 | ハードウェア障害 |

**フォールトとトラップの違い**が重要です。

- **フォールト**：戻り先は**その命令自身**。原因を取り除いてやり直す。ページフォールトはこれで、必要なページをメモリに読み込んでから、同じ命令を再実行します
- **トラップ**：戻り先は**次の命令**。意図的に呼んだものなので、やり直す必要はありません

## マスクできる割り込みとできない割り込み

割り込みハンドラの実行中に別の割り込みが来ると、処理が入れ子になって収拾がつかなくなることがあります。そこで、割り込みを一時的に禁止する仕組みがあります（**マスク**）。

ただし、どうしても止められないものもあります。

| 種類 | マスク | 用途 |
| --- | --- | --- |
| **IRQ** | できる | 通常のデバイス |
| **NMI** | **できない** | 電源断の予兆、重大なハードウェア障害、ファミコンの画面更新タイミング |

NMI（Non-Maskable Interrupt）は、無視することが許されない事象に使われます。ファミコンでは、画面の描画が終わったタイミングで NMI が発生します。ゲームはこの割り込みの中で画面の更新を行います。**描画中に更新すると画面が乱れるため、安全な時間帯を知らせる用途**です。

## コンテキストの保存

割り込みハンドラに入るとき、CPU が自動的に保存するのは PC とフラグくらいです。**汎用レジスタは保存されません。**

ハンドラが勝手にレジスタを使うと、中断されたプログラムの値が壊れます。したがって、ハンドラの先頭で使うレジスタを退避し、最後に復元する必要があります。

```asm
handler:
    push rax
    push rcx
    ...              ; 実際の処理
    pop  rcx
    pop  rax
    iret             ; 割り込みからの復帰専用命令
```

<Callout type="warn" title="割り込みハンドラで長い処理をしてはいけない">
  ハンドラの実行中は、他の割り込みが待たされます。長引くと取りこぼしが起きます。
  そこで Linux では、ハンドラを 2 段に分けます。

  - **上半分**：割り込み禁止の中で最小限のことだけする（デバイスから値を読み、「あとでやること」を登録する）
  - **下半分**：割り込み許可の状態で、残りをゆっくり処理する（softirq、tasklet、workqueue）

  「すぐやらなければならないこと」と「やるべきだが急がないこと」を分ける、という発想です。
</Callout>

## 特権レベル

もうひとつ、CPU がハードウェアとして持っている重要な仕組みがあります。

すべてのプログラムが何でもできてしまっては、OS が成り立ちません。あるプロセスが他のプロセスのメモリを読めてしまい、ページテーブルを書き換えられ、ディスクに直接アクセスできてしまいます。

そこで CPU は、**動作モード**を持ちます。x86 では **リング** と呼ばれ、0 から 3 まであります。

| リング | 用途 | できること |
| --- | --- | --- |
| **0** | カーネル | すべて |
| 1, 2 | ほぼ使われない | |
| **3** | ユーザプログラム | 制限あり |

リング 3 では、次の操作が**ハードウェアによって拒否されます**。

- ページテーブルを指すレジスタ（x86 の CR3）の書き換え
- 割り込みの禁止 / 許可
- 入出力ポートへの直接アクセス
- 他のプロセスのメモリへのアクセス

試みると例外が発生し、制御が OS に移ります。**OS がチェックしているのではなく、CPU が拒んでいる**という点が重要です。ソフトウェアによるチェックは回避できますが、これは回避できません。

<Callout type="tip" title="リングの外側にもある">
  仮想化のために **リング -1**（VMX root モード、ハイパーバイザ用）が追加されました。
  さらに、ファームウェアが動作する **SMM**（System Management Mode）は、
  OS からも見えない最上位の権限を持ちます。「リング -2」と呼ばれることがあります。
</Callout>

## ユーザからカーネルへ渡る唯一の道

リング 3 のプログラムがファイルを読みたいとき、自分ではディスクに触れません。OS に頼む必要があります。

その頼み方が **システムコール** で、実体は**意図的に発生させるトラップ**です。

```asm
mov  rax, 0          ; システムコール番号（0 = read）
mov  rdi, 3          ; fd
mov  rsi, buffer     ; バッファのアドレス
mov  rdx, 100        ; 長さ
syscall              ; ここでリング 0 に移る
```

`syscall` 命令を実行すると、CPU はリング 0 に切り替え、あらかじめ登録されたカーネルのアドレスにジャンプします。**ジャンプ先はカーネルが決めており、呼ぶ側は指定できません。** だから任意の場所に飛び込むことはできません。

割り込みの仕組みが、そのまま「安全な入口」として使われているわけです。第 7 章で詳しく扱います。

## まとめ

- ポーリングは見に行く方式、割り込みは知らせてもらう方式
- 割り込みベクタテーブルが「何が起きたら、どこへ飛ぶか」を決める
- フォールトはその命令をやり直す、トラップは次の命令から再開する
- NMI はマスクできない。無視が許されない事象に使う
- ハンドラはレジスタを自分で退避する。長い処理は下半分に回す
- 特権レベルは CPU の機能であり、ソフトウェアでは回避できない
- システムコールは、意図的に発生させるトラップ

ここまでで第 2 章は終わりです。CPU が命令を実行する仕組みが揃いました。
次の章では、その CPU を最も長く待たせているもの、**メモリ**に向かいます。
