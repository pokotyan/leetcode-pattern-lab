## 実行中のプログラムに付いてくるもの

**プログラム**はディスク上のファイルです。**プロセス**は、それを実行している最中の状態すべてを指します。

OS は、プロセスごとに次の情報を持っています。まとめて **PCB**（Process Control Block）と呼ばれ、Linux では `task_struct` という構造体です。

| 分類 | 内容 |
| --- | --- |
| 識別 | PID、親の PID、ユーザ ID、グループ ID |
| メモリ | ページテーブルへのポインタ、各領域の範囲 |
| CPU の状態 | レジスタの退避場所、プログラムカウンタ |
| ファイル | 開いているファイルディスクリプタの表 |
| シグナル | ハンドラの登録、保留中のシグナル |
| スケジューリング | 優先度、使用した CPU 時間、状態 |
| 統計 | 開始時刻、使用メモリ量、ページフォールト回数 |

同じプログラムから 2 つのプロセスを起動すれば、コードは同じでもこれらはすべて別々です。

```bash
ls /proc/self/          # 自分のプロセスの情報がファイルとして見える
cat /proc/self/status
```

## プロセスの状態

プロセスは常に CPU を使っているわけではありません。

| 状態 | 意味 | `ps` の表示 |
| --- | --- | --- |
| **実行中** | 今 CPU を使っている | R |
| **実行可能** | すぐ動けるが、CPU が空くのを待っている | R |
| **待機（割り込み可能）** | I/O やイベントを待っている | S |
| **待機（割り込み不可）** | 中断できない I/O 待ち | **D** |
| **停止** | シグナルで止められている | T |
| **ゾンビ** | 終了したが、親がまだ回収していない | Z |

**D 状態**が続いているプロセスは、`kill -9` でも殺せません。ディスクやネットワークの応答待ちで、カーネル内部で中断できない状態にあるためです。NFS のマウント先が落ちたときなどに発生します。

<Callout type="warn" title="ロードアベレージに D 状態が含まれる">
  Linux のロードアベレージは「実行可能なプロセス数」だけでなく、
  **D 状態のプロセスも数えます**。
  CPU がまったく使われていなくても、ディスクを待つプロセスが多ければ
  ロードアベレージは高くなります。「負荷が高い」の意味が直感と違う点です。
</Callout>

## fork

新しいプロセスは、既存のプロセスの複製として作られます。

```c
pid_t pid = fork();
```

`fork` は **1 回呼ばれて 2 回返ります**。親でも子でも、`fork` の次の行から実行が続きます。

区別は戻り値で行います。

| 戻り値 | どちら |
| --- | --- |
| 0 | **子プロセス** |
| 正の数 | **親プロセス**（値は子の PID） |
| -1 | 失敗 |

```c
pid_t pid = fork();
if (pid == 0) {
    printf("子です\n");
} else if (pid > 0) {
    printf("親です。子は %d\n", pid);
}
```

子が自分の PID を知りたければ `getpid()` を呼びます。0 が返るのは「自分は子である」という印であって、PID ではありません。

## 何が引き継がれるか

| 引き継がれる | 引き継がれない |
| --- | --- |
| メモリの内容（CoW で共有） | PID |
| 開いているファイルディスクリプタ | 親の PID |
| 環境変数 | **他のスレッド** |
| 現在のディレクトリ | 保留中のシグナル |
| シグナルハンドラの設定 | ファイルロック |

<Callout type="warn" title="fork はスレッドを引き継がない">
  マルチスレッドのプロセスで `fork` すると、**呼び出したスレッドだけ**が子に存在します。
  他のスレッドは消えます。

  問題は、消えたスレッドが**ロックを握ったまま**だった場合です。
  そのロックは永遠に解放されません。子プロセスが同じロックを取ろうとすると、
  デッドロックします。`malloc` の内部ロックでこれが起きると、
  子プロセスで `malloc` を呼んだ瞬間に固まります。

  **マルチスレッドのプロセスでは、`fork` の直後に `exec` する以外のことをすべきではありません。**
  POSIX が `fork` 後に呼んでよい関数を「async-signal-safe なものだけ」と制限しているのは、このためです。
</Callout>

## fork したら exec する

典型的なパターンです。

```c
pid_t pid = fork();
if (pid == 0) {
    execve("/bin/ls", argv, envp);    // 子は別のプログラムになる
    _exit(127);                        // exec が失敗したときだけここに来る
} else {
    int status;
    waitpid(pid, &status, 0);          // 親は子の終了を待つ
}
```

シェルがコマンドを実行するときに、まさにこれをやっています。

`posix_spawn` は、この 2 段階を 1 つにまとめた関数です。マルチスレッド環境で安全に使えます。

## 終了と回収

プロセスが終了しても、すぐには消えません。**終了ステータスなどの情報を残したまま**待機します。この状態が **ゾンビ** です。

親が `wait` / `waitpid` を呼ぶと、その情報を受け取り、ゾンビが消えます。これを **回収** と呼びます。

```c
int status;
pid_t pid = waitpid(-1, &status, 0);
if (WIFEXITED(status))   printf("正常終了。ステータス %d\n", WEXITSTATUS(status));
if (WIFSIGNALED(status)) printf("シグナル %d で終了\n", WTERMSIG(status));
```

**親が回収しないと、ゾンビが溜まり続けます。** プロセスは消えても PID を占有し続けるため、最終的に PID が枯渇します。

<Callout type="tip" title="孤児プロセス">
  親が先に死んだ場合、子は **孤児** になり、init（PID 1）が新しい親になります。
  init は定期的に `wait` を呼ぶので、孤児のゾンビは自動的に回収されます。

  **ゾンビが問題になるのは、親が生きているのに回収していない場合だけ**です。

  なお、コンテナでは PID 1 がアプリケーション自身になることがあります。
  そのプロセスが `wait` を呼ばないと、ゾンビが溜まります。
  `--init` オプションや `tini` のような小さな init が使われるのは、この対策です。
</Callout>

## プロセス間で情報をやり取りする

プロセスは分離されているので、直接メモリを読み書きできません。やり取りには専用の仕組みが要ります。

| 方法 | 特徴 |
| --- | --- |
| **パイプ** | 一方向のバイト列。親子間で使うのが基本 |
| **名前付きパイプ（FIFO）** | ファイルシステム上に名前を持つパイプ。無関係なプロセス間でも使える |
| **Unix ドメインソケット** | 双方向。ファイルディスクリプタの受け渡しもできる |
| **共有メモリ** | 同じ物理ページを両方のアドレス空間にマップする。最速だが同期は自前 |
| **メッセージキュー** | 構造化されたメッセージの受け渡し |
| **シグナル** | 番号だけを送る。通知用 |
| **ファイル** | 単純だが遅い |

**共有メモリが最速**なのは、カーネルを経由しないからです。一度マップすれば、あとは普通のメモリアクセスです。ただし、同時に書き換えたときの整合性は自分で守る必要があります。

## プロセスを分けることの意味

なぜスレッドではなくプロセスに分けるのか。理由は **分離** です。

- 片方がクラッシュしても、もう片方は生き残る
- メモリを誤って壊し合うことがない
- 権限を個別に落とせる

Chrome がタブごとにプロセスを分けるのは、1 つのタブのクラッシュや脆弱性が他に波及しないようにするためです。PostgreSQL が接続ごとにプロセスを使うのも同じ考え方です。

代償は、切り替えのコストと、情報のやり取りの手間です。

## まとめ

- プロセスは、実行中のプログラムに付随する状態すべて
- D 状態は中断できない I/O 待ち。`kill -9` でも死なず、ロードアベレージに含まれる
- `fork` は 1 回呼ばれて 2 回返る。戻り値 0 が子
- マルチスレッドで `fork` すると他のスレッドが消える。ロックが取り残される
- 終了したプロセスは、親が `wait` するまでゾンビとして残る
- プロセス間の情報のやり取りには専用の仕組みが要る
- 分離が必要な場面ではプロセス、共有したい場面ではスレッド
