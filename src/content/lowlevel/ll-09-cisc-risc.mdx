## 発端は、メモリが高価だったこと

1970 年代、メモリは極めて高価でした。プログラムのサイズを小さくすることに、直接的な金銭的価値がありました。

そこで、**1 命令にできるだけ多くの仕事をさせる**設計が採られました。「メモリから値を読み、足し、結果をメモリに書き戻す」を 1 命令で行う。文字列をまとめてコピーする命令を用意する。こうすればプログラムは短くなります。

この方向を後から **CISC**（Complex Instruction Set Computer）と呼ぶようになりました。

もうひとつの事情があります。当時は**アセンブリで直接書くことが多かった**ため、人間にとって便利な命令が求められました。高級言語の構文に近い命令があれば、書く量が減ります。

## 反論：ほとんど使われていない

1980 年前後、複数の研究が同じことを指摘しました。

> **豊富に用意した命令のうち、コンパイラが実際に出力するのはごく一部である。**

複雑な命令は、コンパイラにとって使いどころの判断が難しく、単純な命令の組み合わせで書いたほうが最適化しやすい。結果として、回路の大部分が使われないまま面積と消費電力を占めている。

さらに、複雑な命令は実行に複数クロックかかるため、パイプライン化の妨げになっていました。

そこで逆方向の提案が出ます。

- 命令を単純なものに絞る
- **命令長を固定**にして、デコードを単純にする
- メモリに触るのは**ロードとストアだけ**。計算命令はレジスタしか見ない
- 空いた面積で**レジスタを増やす**

これが **RISC**（Reduced Instruction Set Computer）です。「Reduced」は命令の数ではなく、**1 命令あたりの複雑さ**が減ったことを指します。

## 対比

| | CISC | RISC |
| --- | --- | --- |
| 命令長 | 可変（x86 は 1〜15 バイト） | 固定（多くは 4 バイト） |
| 1 命令の仕事 | 多い | 少ない |
| メモリアクセス | ほとんどの命令で可能 | ロード / ストアのみ |
| レジスタ数 | 少ない（x86-64 で 16） | 多い（ARM64 で 31） |
| デコード | 複雑 | 単純 |
| コード量 | 小さい | 大きい |
| 代表例 | x86, VAX, 68000 | ARM, RISC-V, MIPS, SPARC |

<Callout type="note" title="固定長であることの効き方">
  可変長だと、**次の命令がどこから始まるかは、今の命令を解析し終わるまで分かりません**。
  つまり複数の命令を並行してデコードするのが難しい。
  固定長なら、4 バイトごとに区切るだけで 8 個でも 16 個でも同時にデコードできます。
  これが現代の幅広い CPU 設計で効いてきます。
</Callout>

## 結末：x86 は内側で RISC になった

1995 年の Pentium Pro 以降、x86 の実装は根本的に変わりました。

**外から見える x86 の命令を、内部で単純な命令列に翻訳してから実行する**、という構造になったのです。この内部命令を **マイクロオペレーション**（μop、マイクロオプ）と呼びます。

```
x86 命令                  内部のマイクロオペレーション
add [rbx], rax     →      load  tmp, [rbx]
                          add   tmp, tmp, rax
                          store [rbx], tmp
```

つまり、**実行エンジンは RISC 的に作り、デコーダで x86 との互換性を保つ**という折衷案です。これにより、過去のバイナリを動かしながら現代的な実装を使えるようになりました。

一方の ARM も、単純な命令だけでは足りず、必要に応じて複雑な命令を追加しています。SIMD、暗号化、行列演算の専用命令などです。

**結果として、両者は中央で出会いました。** CISC か RISC かという分類は、今日では ISA の表面的な性格を指す言葉になっています。

<Callout type="warn" title="ただし、デコードの差は残っている">
  x86 の可変長デコードは、今も相応の回路と電力を消費します。
  1 サイクルあたりのデコード幅を増やすのが難しく、
  Apple の M シリーズが 8 命令同時デコードのような設計を取れるのは、
  ARM64 が固定長だからです。
  「もう差はない」と言い切れるほど、差が消えたわけではありません。
</Callout>

## x86 の現況

**x86-64**（AMD64、Intel 64）は、AMD が 2003 年に策定しました。Intel 自身は別方式（Itanium）で 64 ビット化を図りましたが普及せず、AMD の拡張が事実上の標準になった、という経緯があります。

主な特徴です。

- 汎用レジスタ 16 本（`rax`〜`r15`）
- 命令長 1〜15 バイトの可変長
- 計算命令が直接メモリを参照できる
- SIMD 拡張が何世代も積み重なっている（SSE, AVX, AVX-512）
- サーバとデスクトップで圧倒的なシェア

## ARM の現況

**ARM** は、当初から低消費電力を重視して設計されました。

- 32 ビット時代は **AArch32**、64 ビットは **AArch64**（ARM64）。両者は別の命令セット
- 固定長 4 バイト（Thumb モードでは 2 バイト混在）
- ロード・ストア・アーキテクチャ
- 汎用レジスタ 31 本
- スマートフォンではほぼ独占。Apple Silicon 以降、デスクトップとサーバにも広がっている

**ARM 社は CPU を製造しません。** 設計をライセンスし、各社がそれを使ってチップを作ります。Apple、Qualcomm、Amazon がそれぞれ独自に実装しているのはこのためです。

<Callout type="tip" title="RISC-V">
  RISC-V は、**ライセンス料の要らないオープンな ISA** です。
  基本命令は 40 程度に絞られ、必要な機能は拡張として足す設計になっています。
  教材として読みやすく、学習目的で ISA を読むなら最初の候補になります。
</Callout>

## 別アーキテクチャのバイナリを動かす

ISA が違えば、バイナリはそのままでは動きません。方法は 3 つあります。

| 方法 | 仕組み | 例 |
| --- | --- | --- |
| **再コンパイル** | ソースから作り直す | 最も速い。ソースが必要 |
| **動的バイナリ変換** | 実行時に命令を翻訳し、結果をキャッシュする | Apple の Rosetta 2 |
| **インタプリタ方式のエミュレーション** | 1 命令ずつ解釈して実行する | QEMU の一部、この連載の NES エミュレータ |

Rosetta 2 が実用的な速度を出せるのは、**初回に翻訳した結果を保存して使い回す**からです。1 命令ずつ解釈する方式は書きやすい代わりに、10 倍以上遅くなるのが普通です。

NES のように元の機械が遅ければ、素朴な方式でも十分間に合います。Track 3 ではその方式を取ります。

## まとめ

- CISC は「1 命令に多くの仕事を」、RISC は「命令を単純にして数で押す」
- RISC の Reduced は、命令数ではなく 1 命令あたりの複雑さ
- x86 は内部でマイクロオペレーションに翻訳し、実行エンジンは RISC 的
- ARM も複雑な命令を追加しており、両者は歩み寄った
- 固定長デコードの優位は今も残っている
- 別 ISA のバイナリは、再コンパイル / 動的変換 / エミュレーションで動かす
