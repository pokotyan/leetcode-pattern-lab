## コンデンサに電荷を貯める

DRAM の 1 ビットは、**コンデンサ 1 個とトランジスタ 1 個**でできています。コンデンサに電荷があれば 1、なければ 0 です。

この構成の利点は、1 ビットあたりの面積が極めて小さいことです。SRAM の 6 トランジスタに対して、実質 1 個ぶん。だから大容量を安く作れます。

欠点は 2 つあります。

**1. 電荷は漏れる。** 放っておくと数十ミリ秒で失われます。そこで、定期的に全ビットを読み出して書き戻す **リフレッシュ** が必要です。この間、そのメモリ領域にはアクセスできません。容量が増えるほどリフレッシュの負担も増えます。

**2. 読むと壊れる。** コンデンサの電荷を読み出すと、その電荷が失われます。したがって読み出しの後には必ず書き戻しが必要です（破壊読み出し）。

<Callout type="note" title="DRAM の D は Dynamic">
  常にリフレッシュし続けなければ内容が消えるので **Dynamic**。
  電源がある限り保持される SRAM は **Static** です。
  どちらも電源を切れば消える **揮発性** メモリです。
</Callout>

## 行を開くという操作

DRAM のセルは、格子状に並んでいます。アクセスは 2 段階です。

1. **行を活性化する**（ACTIVATE）：指定した行の全セルを読み出し、**行バッファ**（センスアンプ）に載せる
2. **列を選ぶ**（READ / WRITE）：行バッファの中から必要な列を取り出す

行バッファは 1〜8KB 程度あります。ここが決定的に重要です。

**同じ行への次のアクセスは、行バッファから取るだけなので速い**（行ヒット）。
**別の行にアクセスするには、今の行を閉じて（PRECHARGE）、新しい行を開く必要がある**（行ミス）。

| 状況 | おおよその遅延 |
| --- | --- |
| 行バッファにある（行ヒット） | 約 15ns |
| 行を開く必要がある | 約 30ns |
| 別の行を閉じてから開く | 約 45ns |

**3 倍の差**です。つまり、DRAM のレベルでも「近くにアクセスすると速い」という局所性が効いています。キャッシュだけの話ではありません。

<Callout type="tip" title="メモリのスペック表の数字">
  「CL16-18-18-36」のような表記は、この手順の各段階の所要クロック数です。

  | 記号 | 意味 |
  | --- | --- |
  | CL | 行を開いた後、データが出るまで |
  | tRCD | 行の活性化から列の選択まで |
  | tRP | 行を閉じるのにかかる時間 |
  | tRAS | 行を開いてから閉じられるようになるまで |

  クロック周波数が上がっても CL の数値が同じ割合で増えれば、
  **実時間のレイテンシは変わりません**。周波数だけを見ても意味がない理由です。
</Callout>

## 帯域を増やす

レイテンシは簡単には縮みませんが、**同時に運ぶ量**は増やせます。

**DDR**（Double Data Rate）は、クロックの立ち上がりと立ち下がりの両方でデータを転送します。これで 1 クロックあたり 2 回。

**チャネル**は、独立したメモリの経路です。デュアルチャネルなら 2 本の経路で同時に転送できます。マザーボードのスロットに色分けがあり、「2 枚挿すときは同じ色に」と指示されるのはこのためです。1 枚だけ挿すとシングルチャネルになり、帯域が半減します。

**バンク**は、DRAM 内部の独立した区画です。あるバンクが行を開いている間、別のバンクは別の行を開けます。並行して動くことで、待ち時間を重ねられます。

これらはすべて **帯域**（1 秒あたりに運べる量）を増やす工夫で、**レイテンシ**（1 回の要求が返るまでの時間）は改善しません。

<Callout type="warn" title="帯域とレイテンシを混同しない">
  「DDR5 は DDR4 の 2 倍速い」という表現は、帯域の話です。
  1 回のランダムアクセスが返るまでの時間は、ほとんど変わっていません。
  過去 20 年で帯域は数十倍になりましたが、レイテンシは 2 分の 1 程度にしかなっていません。
  **CPU との速度差は開き続けています。**
</Callout>

## コアによってメモリが遠い

CPU が複数のソケットを持つサーバや、多数のコアを持つプロセッサでは、メモリコントローラがコアのグループごとに分かれています。

自分のグループに直結したメモリは速い。他のグループのメモリは、相手のコントローラを経由するので遅い。この構成を **NUMA**（Non-Uniform Memory Access、非対称メモリアクセス）と呼びます。

| アクセス先 | 相対的な遅さ |
| --- | --- |
| ローカルノード | 1 |
| リモートノード | 1.5〜2.5 倍 |

つまり、**同じプログラムでも、どのコアで動き、どこにメモリを確保したかで性能が変わります**。

OS は通常、「確保を要求したスレッドが動いているノードに割り当てる」という方針（first-touch）を取ります。したがって、

- メモリを確保したスレッドと、それを使うスレッドが別ノードにいると遅い
- 初期化を 1 スレッドでまとめてやると、全部が 1 ノードに集まる

という落とし穴があります。並列処理では、**各スレッドが自分で使う領域を自分で初期化する**のが定石です。

```bash
numactl --hardware              # ノード構成を見る
numactl --cpunodebind=0 --membind=0 ./a.out    # ノード 0 に固定して実行
```

## エラー訂正

DRAM のセルは、宇宙線や電気的ノイズでビットが反転することがあります。頻度は低いものの、大容量・長時間の稼働では無視できません。

**ECC メモリ**は、余分なビットを持たせて 1 ビットの誤りを訂正し、2 ビットの誤りを検出します。サーバでは標準的に使われます。

<Callout type="note" title="Rowhammer">
  DRAM の集積度が上がった結果、**ある行に繰り返し高速にアクセスすると、
  隣の行のビットが反転する**という現象が見つかりました。Rowhammer と呼ばれます。

  これは物理現象を利用した攻撃に使われます。狙った場所のビットを反転させることで、
  権限昇格が可能になった実例が報告されています。
  **ソフトウェアのバグがなくても、ハードウェアの性質だけで安全性が破れる**例です。
  対策としてリフレッシュ頻度の調整や、行の監視機構が導入されています。
</Callout>

## まとめ

- DRAM はコンデンサに電荷を貯める。漏れるのでリフレッシュが必要
- アクセスは「行を開く → 列を選ぶ」の 2 段階。同じ行なら速い
- DDR、チャネル、バンクは帯域を増やす工夫。レイテンシは改善しない
- CPU とメモリの速度差は開き続けている
- NUMA 環境では、どのコアからどのメモリを触るかで性能が変わる
- Rowhammer は、物理現象がそのまま脆弱性になった例
