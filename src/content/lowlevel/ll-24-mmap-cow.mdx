## 割り当てを先延ばしにする

`malloc(1GB)` が即座に返ってくるのを不思議に思ったことがあるかもしれません。1GB ぶんのメモリを用意するには時間がかかるはずです。

実際には、**何も用意していません**。仮想アドレス空間に「ここは 1GB ぶん使う予定」と記録しただけです。物理メモリは 1 バイトも割り当てられていません。

最初にそのアドレスに触った瞬間、ページフォールトが発生し、そこで初めて物理ページが 1 枚割り当てられます。これが **デマンドページング** です。

```c
char *p = malloc(1024L * 1024 * 1024);    // 一瞬で返る。物理メモリは 0
p[0] = 'a';                                // ここで 4KB だけ割り当てられる
```

<Callout type="note" title="オーバーコミット">
  この仕組みのため、Linux は**物理メモリ + スワップより多くの仮想メモリを約束できます**。
  実際に使われなければ問題ないからです。

```bash
cat /proc/sys/vm/overcommit_memory     # 0 = ヒューリスティック（既定）
```
  約束を守れなくなったときの対処が、後述の OOM Killer です。
</Callout>

`ps` や `top` で見えるメモリ量が 2 種類あるのは、この区別によります。

| 表示 | 意味 |
| --- | --- |
| **VSZ / VIRT** | 仮想アドレス空間の広さ。約束した量 |
| **RSS / RES** | 実際に物理メモリを消費している量 |

**気にすべきは RSS です。** VSZ が数 TB でも、実際の消費がわずかということは普通にあります。

## ファイルをメモリとして扱う

**mmap** は、ファイルを仮想アドレス空間に対応づけるシステムコールです。

```c
int fd = open("data.bin", O_RDONLY);
char *p = mmap(NULL, len, PROT_READ, MAP_PRIVATE, fd, 0);

// これ以降、p[i] でファイルの i バイト目にアクセスできる
printf("%c\n", p[100]);
```

`read` を呼ばずに、**ポインタでファイルを読めます**。

仕組みはデマンドページングと同じです。`p[100]` に触った瞬間にページフォールトが起き、OS がファイルの該当部分を読み込みます。

| | read / write | mmap |
| --- | --- | --- |
| データの流れ | ディスク → カーネルのバッファ → ユーザのバッファ | ディスク → ページキャッシュ（そのまま見える） |
| コピー回数 | 2 回 | **1 回** |
| システムコール | 読むたびに必要 | 最初の 1 回だけ |
| ランダムアクセス | `lseek` が必要 | ポインタ演算だけ |
| 小さなファイル | 有利 | セットアップの分だけ不利 |

大きなファイルへのランダムアクセスでは、mmap が有利です。データベースやインデックスの実装でよく使われます。

<Callout type="warn" title="mmap の落とし穴">
  - **アクセスするとページフォールトで待たされる**。どこで I/O が発生するか、コードからは見えません
  - ファイルが**他のプロセスに切り詰められる**と、その領域へのアクセスが SIGBUS になります
  - 書き込みがディスクに反映されるタイミングは OS 任せ。確実にするには `msync` が必要です
  - 32 ビット環境では、アドレス空間が足りず大きなファイルをマップできません
</Callout>

## 書くまでコピーしない

**コピーオンライト**（Copy-on-Write、CoW）は、「同じ内容なら共有し、書き換えようとした瞬間に初めて複製する」という仕組みです。

`fork()` がこれを使っています。

素朴に考えれば、`fork` は親のメモリを全部複製する必要があります。数 GB のプロセスなら、それだけで時間がかかります。しかも、`fork` の直後に `exec` で別のプログラムに置き換わるなら、複製は完全な無駄です。

そこで、

1. **ページテーブルだけを複製する**。物理ページは共有したまま
2. 共有したページを、両方とも **書き込み不可** に設定する
3. どちらかが書き込もうとすると、**ページフォールトが発生する**
4. OS がそこで初めてそのページを複製し、書き込み可能にして再開させる

**読むだけなら複製は一切発生しません。** 書き換えたページだけが、1 枚ずつ複製されます。

```
fork 直後
  親: ページ A (読み取り専用) ─┐
                              ├─→ 物理ページ X
  子: ページ A (読み取り専用) ─┘

子が書き込むと
  親: ページ A ──→ 物理ページ X
  子: ページ A'──→ 物理ページ Y（X の複製）
```

<Callout type="tip" title="CoW が使われている他の場所">
  - **Redis の永続化**：`fork` してスナップショットを取る。子プロセスは書き込まないので複製がほぼ発生しない
  - **コンテナのイメージ**：レイヤ間でファイルを共有し、変更時だけコピーする
  - **ファイルシステム**：Btrfs、ZFS のスナップショット
  - **プログラミング言語**：文字列の実装（Python のように不変なら共有し放題）
</Callout>

## メモリが足りなくなったら

物理メモリが尽きると、OS は使われていないページをディスクに退避します。これが **スワップ** です。

退避するページの選び方には、ページテーブルの **Accessed ビット**が使われます。CPU が自動で立てるこのビットを OS が定期的にクリアし、次に見たとき立っていなければ「最近使われていない」と判断します。

スワップアウトされたページにアクセスすると、メジャーフォールトが発生し、ディスクから読み戻されます。**メモリの数万倍遅い**ので、これが頻発すると性能が壊滅します。この状態を **スラッシング** と呼びます。

```bash
vmstat 1
# si/so 列（swap in / swap out）が継続的に動いていたら危険信号
```

<Callout type="note" title="ページキャッシュとスワップは別物">
  - **ページキャッシュ**：ファイルの内容をメモリに載せたもの。捨てても元がディスクにあるので、いつでも解放できる
  - **スワップ**：匿名メモリ（ヒープやスタック）をディスクに退避したもの。捨てられない

  `free` コマンドで「メモリがほとんど使われている」ように見えても、
  大半がページキャッシュなら問題ありません。`available` 列を見るべきです。

```bash
free -h
#               total   used   free   shared  buff/cache   available
```
</Callout>

## OOM Killer

スワップも尽きると、Linux は **OOM Killer** を起動し、プロセスを 1 つ選んで強制終了します。

選ばれるのは、メモリ使用量と設定値（`oom_score_adj`）から計算されるスコアが最も高いプロセスです。たいてい、最もメモリを使っているプロセスが選ばれます。

```bash
cat /proc/<pid>/oom_score
echo -1000 > /proc/<pid>/oom_score_adj     # 対象外に近づける
dmesg | grep -i "killed process"           # 発生の記録
```

<Callout type="warn" title="OOM Killer は予告なく殺す">
  `malloc` が NULL を返す前に、プロセスが突然消えます。
  オーバーコミットの結果、**約束を守れなくなった時点で誰かが犠牲になる**という設計です。
  コンテナ環境では、cgroup のメモリ上限を超えた時点で、そのコンテナ内のプロセスが対象になります。
  「原因不明でコンテナが再起動している」場合、まず `dmesg` を見るべきです。
</Callout>

## 関連するシステムコール

| 呼び出し | 用途 |
| --- | --- |
| `mmap` / `munmap` | 領域の対応づけと解除 |
| `mprotect` | 権限の変更（読み / 書き / 実行） |
| `madvise` | アクセスパターンのヒント（`MADV_SEQUENTIAL`、`MADV_DONTNEED`） |
| `mlock` | ページをメモリに固定し、スワップさせない |
| `msync` | mmap した内容をディスクに書き出す |

`mlock` は、秘密鍵のようにディスクに書き出されては困るデータに使われます。

## まとめ

- `malloc` はアドレス空間を予約するだけ。触った瞬間に物理ページが割り当てられる
- VSZ ではなく RSS を見る
- mmap はファイルをアドレス空間に対応づけ、コピー回数を減らす
- コピーオンライトは「書くまで複製しない」。`fork` を実用的にしている
- スワップはページを退避する。頻発するとスラッシングで性能が壊滅する
- ページキャッシュは解放できるが、スワップ対象の匿名メモリは解放できない
- メモリが尽きると OOM Killer がプロセスを選んで殺す
