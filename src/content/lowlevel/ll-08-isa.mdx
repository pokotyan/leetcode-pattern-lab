## 契約としての ISA

CPU が理解できる命令の一覧、各命令のビット配置、レジスタの本数と名前、メモリの扱い方。これらをまとめて **ISA**（Instruction Set Architecture、命令セットアーキテクチャ）と呼びます。

ISA は、**ソフトウェアとハードウェアの間の契約**です。

- ソフトウェア側は「この命令列を渡せば、この通りに動く」と期待できる
- ハードウェア側は「契約を守る限り、中身をどう作ってもよい」

この分離が決定的に重要です。1995 年の Pentium 向けにコンパイルされたバイナリが、今日の CPU でも動きます。中身はまったくの別物なのに、契約が同じだからです。

<Callout type="note" title="ISA とマイクロアーキテクチャは別物">
  **ISA** = 外から見える仕様（命令の一覧とその意味）。
  **マイクロアーキテクチャ** = それを実際にどう作るか（パイプラインの段数、キャッシュの構成、実行ユニットの数）。

  「x86-64」は ISA、「Zen 4」や「Golden Cove」はマイクロアーキテクチャです。
  同じ ISA を、Intel と AMD がまったく違うマイクロアーキテクチャで実装しています。
</Callout>

## 機械語とアセンブリ

**機械語**は、CPU が直接読むビット列です。人間には読めません。

**アセンブリ**は、それに 1 対 1 で対応する人間向けの表記です。

```asm
mov  eax, 1        ; 機械語では b8 01 00 00 00
add  eax, ebx      ; 機械語では 01 d8
```

アセンブリと機械語の関係は、**ほぼ機械的な置き換え**です。だから変換器（アセンブラ）は、コンパイラに比べればはるかに単純です。

<Callout type="tip" title="ほぼ 1 対 1、であって完全な 1 対 1 ではない">
  アセンブラは、記号の解決（ラベル → アドレス）と、擬似命令の展開を行います。
  また x86 では、同じ意味の命令に複数の符号化が存在することがあり、
  アセンブラが短いほうを選びます。逆アセンブルして元と同じ文字列に戻る保証はありません。
</Callout>

## アセンブリの記法が 2 つある

x86 には 2 つの記法があり、**オペランドの順序が逆**です。

```asm
; Intel 記法（Windows、NASM、Intel の文書）
mov  eax, ebx        ; ebx を eax に入れる（左が宛先）

; AT&T 記法（GCC、Linux の伝統）
movl %ebx, %eax      ; ebx を eax に入れる（右が宛先）
```

慣れないうちは方向を読み違えます。`objdump` は `-M intel` で Intel 記法に切り替えられます。

## アドレッシングモード

「どこの値を使うか」の指定方法を **アドレッシングモード** と呼びます。種類の多さが ISA の性格を決めます。

| モード | 書き方（Intel 記法） | 意味 |
| --- | --- | --- |
| 即値 | `mov eax, 5` | 命令の中に値が埋まっている |
| レジスタ | `mov eax, ebx` | レジスタの中身 |
| 直接 | `mov eax, [0x1000]` | 指定アドレスのメモリ |
| レジスタ間接 | `mov eax, [ebx]` | レジスタが指すアドレスのメモリ |
| ベース + オフセット | `mov eax, [ebx+8]` | 構造体のメンバへのアクセス |
| ベース + 添字 × スケール | `mov eax, [ebx+ecx*4]` | 配列の要素へのアクセス |

最後のものは、`arr[i]` を 1 命令で表現するためのものです。`ecx` が添字、`4` が要素のサイズです。**高級言語の構文が、そのまま命令の機能として用意されている**わけです。

この「便利な命令をどこまで用意するか」という判断が、次の記事のテーマになります。

## 互換性が縛るもの

ISA は一度公開すると、事実上変更できません。世に出回っているバイナリが動かなくなるからです。

結果として、x86 には 40 年以上の地層が積もっています。

- 16 ビット時代（8086, 1978）の命令が今も残っている
- 32 ビット拡張（80386, 1985）で命令が増えた
- 64 ビット拡張（AMD64, 2003）でさらに増えた
- SIMD 拡張が MMX → SSE → AVX → AVX-512 と重なった

命令の総数は数千に達し、命令の長さは 1 バイトから 15 バイトまで可変です。**デコードだけで相当な回路を使います**。

<Callout type="warn" title="使われていない命令も消せない">
  x86 には、10 進数演算の補正命令（`AAA`、`DAA` など）のように、
  現代のコンパイラがまず出力しない命令が残っています。
  64 ビットモードでようやく削除されたものもありますが、
  32 ビット互換モードでは今も動かす必要があります。
  互換性とは、**過去の全ての決定を永久に引きずること**です。
</Callout>

## エミュレータから見た ISA

ISA が「外から見える契約」であることの実用的な帰結として、**契約さえ守れば、それをソフトウェアで実装してもよい**ということがあります。

これがエミュレータです。ファミコンの 6502 の ISA をソフトウェアで再現すれば、実機のプログラムがそのまま動きます。中身が回路かソフトウェアかは、プログラムからは区別がつきません。

この連載の Track 3 でやるのはまさにそれです。「6502 の契約書を読み、その通りに振る舞うプログラムを書く」ことになります。

## 実際に見る

コンパイル結果のアセンブリは、いつでも見られます。

```bash
# C からアセンブリを出す
gcc -S -O2 -masm=intel foo.c -o -

# 実行可能ファイルを逆アセンブルする
objdump -d -M intel ./a.out | less
```

短い関数から始めるのがおすすめです。`int add(int a, int b) { return a + b; }` をコンパイルすると、引数がどのレジスタで渡され、戻り値がどこに置かれるかが見えます。この約束事（呼び出し規約）は第 5 章で扱います。

## まとめ

- ISA はソフトウェアとハードウェアの契約。互換性の単位
- ISA（仕様）とマイクロアーキテクチャ（実装）は別物
- アセンブリは機械語のほぼ 1 対 1 の人間向け表記
- アドレッシングモードの豊富さが ISA の性格を決める
- 互換性の代償として、x86 には数十年分の命令が積み重なっている
- 契約さえ守ればソフトウェアで実装できる。それがエミュレータ
