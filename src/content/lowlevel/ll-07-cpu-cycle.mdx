## CPU の中にあるもの

CPU の中身は、大きく 3 つに分けられます。

| 部分 | 役割 |
| --- | --- |
| **レジスタ** | ごく少数の、ごく速い記憶場所 |
| **ALU** | 足す、引く、論理演算をする計算器 |
| **制御部** | 命令を読み取り、他の部分に指示を出す |

**レジスタ**は、CPU の中にある変数のようなものです。x86-64 なら汎用レジスタが 16 本、ARM64 なら 31 本。**それだけしかありません**。

数が少ないのは、速さと引き換えだからです。レジスタは計算器のすぐ隣にあり、1 クロックでアクセスできます。数を増やすと配線が伸び、選択回路が大きくなり、遅くなります。

その中に、特別な役割を持つものがあります。

| レジスタ | 役割 |
| --- | --- |
| **PC**（プログラムカウンタ） | 次に実行する命令のアドレス |
| **SP**（スタックポインタ） | スタックの先端のアドレス |
| **フラグ** | 直前の計算の結果の性質（ゼロだった、桁あふれした、など） |

<Callout type="note" title="レジスタが少ないことの帰結">
  変数が 100 個あるプログラムでも、レジスタは 16 本しかありません。
  したがって、**使っていない変数はメモリに追い出す**必要があります。
  どの変数をレジスタに残すかを決めるのは、コンパイラの仕事のうち最も難しい部分のひとつで、
  **レジスタ割り当て**と呼ばれます。
</Callout>

## 実行のサイクル

CPU がやっているのは、次の 4 手の繰り返しだけです。

```
1. フェッチ (Fetch)     PC が指すアドレスから命令を読む
2. デコード (Decode)    その命令が何を意味するか読み取る
3. 実行 (Execute)       ALU で計算する / メモリを読み書きする
4. ライトバック          結果をレジスタに書く。PC を次に進める
```

そして 1 に戻ります。電源が入っている間、これを止まることなく繰り返しています。

具体例で追います。`R1 = R2 + R3` に相当する命令が、アドレス 100 にあるとします。

```
1. フェッチ    PC = 100。100 番地から命令のビット列を読む
2. デコード    「加算」「入力は R2 と R3」「出力は R1」と読み取る
3. 実行        R2 と R3 の値を ALU に流し、和を得る
4. ライトバック 和を R1 に書く。PC を 104 にする（命令長が 4 バイトなら）
```

<Callout type="tip" title="「次の命令」は足し算でしかない">
  PC を進めるのは単なる加算です。逆に言えば、**PC に別の値を書き込めば、そこに飛びます**。
  これが分岐であり、関数呼び出しであり、例外処理です。
  goto も if も for も、機械語のレベルでは「PC に何を書くか」という 1 種類の操作に還元されます。
</Callout>

## 命令の中身

命令はビット列です。その中に「何をするか」と「どこに対してか」が詰め込まれています。

ARM64 の加算命令を例に取ります（32 ビット固定長）。

```
┌───────────────┬──────┬──────┬──────┐
│   オペコード    │  Rm  │  Rn  │  Rd  │
└───────────────┴──────┴──────┴──────┘
   何をするか      入力2  入力1  出力先
```

**オペコード**が操作の種類、残りが対象です。デコードとは、このビット列を切り分けて、各部分を対応する回路の制御線に配ることです。

「デコード」というと難しそうに聞こえますが、実体は**ビット列を条件として、どの回路を有効にするかを選ぶ**だけです。第 1 章で見た「選ぶ回路」が、ここで大量に使われます。

## クロック

CPU の中では、無数の信号が同時に動いています。放っておくと、ある回路の計算が終わる前に次の回路が結果を読んでしまいます。

そこで **クロック**という周期的な信号を全体に配り、**その立ち上がりの瞬間だけ値を確定させる**ことにします。1 周期の間に信号が回路を通り抜けられれば、確実に正しい値が次に渡ります。

「3.5GHz」とは、この周期が 1 秒間に 35 億回あることを意味します。1 周期は約 0.29 ナノ秒です。光が 9cm 進む時間で、CPU の端から端までの配線遅延が無視できない領域です。

<Callout type="warn" title="クロックが速い = 速い、ではない">
  1 命令に何クロックかかるかは命令によって違います。また、後で見るパイプラインにより、
  **1 クロックあたり複数の命令が完了する**こともあります。
  指標としては IPC（Instructions Per Cycle）とクロック周波数の積で見る必要があり、
  クロック数だけを比べても意味がありません。
  2000 年代前半に周波数競争が終わったのは、周波数を上げると消費電力と発熱が
  それ以上の勢いで増えることが分かったためです。
</Callout>

## 命令の種類

どの CPU でも、命令は大きく次のグループに分かれます。

| 種類 | 例 | 何をするか |
| --- | --- | --- |
| **データ転送** | `MOV`, `LD`, `ST` | レジスタ間、レジスタとメモリ間で値を移す |
| **算術・論理** | `ADD`, `SUB`, `AND`, `SHL` | ALU で計算する |
| **分岐** | `JMP`, `BEQ`, `CALL`, `RET` | PC を書き換える |
| **比較** | `CMP`, `TEST` | 引き算だけして、結果は捨て、フラグだけ残す |
| **特権命令** | `HLT`, 割り込み制御 | OS だけが使える |

`if (a == b)` は、機械語ではこう分解されます。

```
CMP  a, b        ; a - b を計算し、結果は捨ててフラグだけ更新
JNE  else_label  ; ゼロフラグが立っていなければジャンプ
```

比較と分岐が別命令なのは、**フラグという副作用を経由して繋がっている**からです。この 2 命令の間に別の命令を挟むとフラグが壊れる可能性があり、コンパイラはそこを気にしてコードを並べています。

## メモリに触る命令は特別扱い

レジスタ同士の演算は 1 クロックで終わります。一方、メモリへのアクセスは**桁違いに遅い**です。

| 場所 | おおよその時間 |
| --- | --- |
| レジスタ | 0 クロック（実行と同時） |
| L1 キャッシュ | 4 クロック |
| メインメモリ | 200〜300 クロック |

200 クロックとは、その間に他の命令を 200 個実行できたということです。だから CPU の設計の大部分が、**メモリを待つ時間をどう隠すか**に費やされています。第 3 章のテーマです。

この差があるため、多くの CPU は「メモリに触る命令」と「計算する命令」を分けています。計算命令はレジスタしか触らず、メモリとのやり取りは専用のロード / ストア命令だけが行う、という設計です。これを **ロード・ストア・アーキテクチャ**と呼び、ARM や RISC-V がこの方式です。x86 は違い、計算命令が直接メモリを参照できます。この違いが、次の記事で扱う CISC と RISC の分かれ目のひとつです。

## まとめ

- CPU はレジスタ、ALU、制御部からなる
- 実行は「フェッチ → デコード → 実行 → ライトバック」の繰り返しだけ
- 分岐とは、PC に別の値を書くこと
- クロックは、値を確定させる瞬間を全体に知らせる信号
- メモリアクセスはレジスタの数百倍遅く、設計の多くがその隠蔽に費やされている
